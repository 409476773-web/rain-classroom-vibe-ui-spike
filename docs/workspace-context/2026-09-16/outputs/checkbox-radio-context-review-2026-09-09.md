## 2. 方案的演进与最终含义

这次调研已经从“补齐两个基础控件”推进到“建立可以保持雨课堂风格、允许合理组合的选择组件家族”。研究覆盖了基础选择、带说明选项、选择卡片、对象选择、预览、关联字段和本页全选；不是把所有研究示例都加入第一批实现。

中间有一次需要明确保留的纠正：早期回复把“控制器必须最抢眼”“所有内容必须与标题列对齐”等说得过于绝对，并把未核验风险说成了现稿缺陷。后续《版式错误类型地图》已经主动撤回这种判断。最终应遵守的是四种关系清楚：

1. 选择标记对应哪个对象。
2. 标题、说明、元信息、组级帮助、字段错误分别属于谁。
3. 哪些内容是比较和决策的依据。
4. 哪些区域改变选择，哪些只预览或编辑，以及当前状态是什么。

文本型选择项默认采用“控制器列 + 主内容区域”，但图片可以是决策主体，详情网格、全宽区域、不同控制器位置也不能仅凭形式判错。`ContentRail` 是组织规则，不需要因此新增公共 Layout 组件。

用户的“没问题”确认的是 **V0.3 布局与信息层级修订**。后续交接规格没有把它扩展为 API 定稿、交互通过、完整状态视觉通过、组件发布或业务迁移通过。

## 3. 应保留的建设分层

| 层次 | 职责与边界 |
| --- | --- |
| Checkbox、CheckboxGroup、RadioGroup / Item | 选择状态、单值/集合关系、原生表单、键盘、禁用、重置、可访问名称。Checkbox 与 Radio 保留不同语义。 |
| CheckboxCard、RadioCard | 在选择语义上增加雨课堂卡片表面和内容结构，复用行为规则，不复制四份选择逻辑。 |
| 四类 Recipe | 图文预览、对象、比较、带独立预览操作；复用完整默认组合，确有业务差异时再调整局部。 |
| 业务 Pattern | 本页全选、关联字段、方案预览、保存/取消；上层管理业务草稿、校验范围和提交。 |

这些名称是工程候选，不能据此机械创建同名组件。对照当前仓库时还有一项身份衔接：复用矩阵已保留独立的 Checkbox、CheckboxGroup、Radio、RadioGroup，不能因规格采用 `RadioGroup / Item` 写法而静默丢失既有公共身份。

`03-selection-manifests.json` 是候选能力契约，当前标记不可安装，真实源码路径、提交和底座映射尚未填写。它不是已经可用的 shadcn Registry，也不是已建立的正式 Code Connect。

## 4. 交互实现真正需要守住的合同

### 三类交互区域

- **只选择：**真实控件与标签只有一次激活路径，整行点击不能再叠加一套重复切换。
- **选择 + 独立操作：**预览/详情留在同一视觉对象中，但处于选择宿主之外；按钮使用非提交行为；预览不改选择、不保存；关闭后焦点返回触发入口。
- **选择 + 条件输入：**输入字段有自己的标签、帮助和错误关系。输入框方向键不切换 Radio；条件展开不抢焦点；停用时保留草稿，但排除该分支的校验与业务提交。

### 状态和集合

- 组值是唯一事实源；外部受控更新不反向触发用户回调，一次用户变化只通知一次。
- Radio 允许初始为空；不会自动选第一项，也不会再次点击已选项就清空。
- Checkbox 的 mixed 是聚合展示，不能成为第三个提交值；“总量未知”也不能用 mixed 冒充。
- 本页全选只作用于当前明确、可修改的集合 E。混合态激活得到 `S ∪ E`，全选态取消得到 `S \ E`；必须保留范围外和锁定项的已选值。E 为空时总控禁用且未选；总控不新增一个“全选”表单值。
- 原生 FormData 与业务模型分别说明。禁用但已选的值可能保留在业务模型中，不能假设原生提交会包含它。
- “至少选一项”是组级校验，不能给每个 Checkbox 都设置 required。
- 原生 Checkbox/Radio 没有 readOnly 行为；首批使用明确的结果展示，不伪造浏览器已经支持只读。
- value 应稳定、唯一。候选字符串值与旧组件数字值的迁移要显式处理，不能用统一字符串转换制造 `1` 与 `"1"` 冲突。

验收应优先覆盖这些容易在“看起来能点”时被漏掉的关系，再做四种卡片的重复展示。38 项验收中还包括长标题、320px 窄容器、图片比例、布局稳定、Focus/禁用/错误、辅助技术、强制颜色和来源追踪；目前没有运行结果。

核对出的实施事实：

- 控制器占位为 24×24；可见 Checkbox 为 16×16，可见 Radio 为 18×18。占位、可见图形与完整点击区域应分别处理。
- 常见外边距 16、控制器与内容间距 8，因此外层主内容起点为 48。
- 图文卡片底部内边距实测 18，不应为了统一而改成 16。
- 图文卡片约 296×231.43，对象卡片 612×108，比较卡片 296×208，带预览卡片 612×148。这是画稿参考尺寸；296/612 不自动成为 Size 枚举，320 是测试容器而非全局断点。
- 预览图保留 7:3 比例。
- 带预览卡片中的 `TrailingVisual` 实际位于内部内容区左侧。外层内容起点 48，内部图形后文字起点进一步偏移，因此标题可在卡片 x=100，而 Actions 仍在 x=48；不能把“统一内容轨道”误读为所有文字绝对坐标都是 48。
- 标题主要是 Noto Sans SC Medium 500、15/24；说明主要 13/22。部分元信息值实际为 12/22，辅助键/标签有 11/22，不能把所有次级信息一律当成同一字号。

少量设计文案仍需在正式接入时澄清：一些旧容器名仍写“上图下文”“左图右文”，但实际布局已修订；两张画板页脚仍有“待设计评审”，与后续明确确认不一致；组合说明写 5 类但画板有 6 节。这些是文档/命名残留，不能反过来推翻已确认的当前几何。
