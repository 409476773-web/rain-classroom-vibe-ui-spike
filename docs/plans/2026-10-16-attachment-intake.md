# 附件预览：三种入口形态

用户于 2026-10-16 确认资料列表、媒体网格与消息输入三种设计，并授权落到当前附件预览。Prototype Mode，页面私有 local-experiment，不晋升公共 API。

- 资料列表和弹窗：已有文件时标题栏轻量添加，首次添加时显示短拖放区。
- 媒体：添加位作为网格最后一项，首次添加时显示媒体空态。
- 输入：保留回形针入口，整个编辑区接收文件，正文文本拖放继续正常工作。
- 拖入时临时突出所属范围；离开、落下、Escape、窗口失焦或关闭弹窗清除反馈。每个区域仅一个接收者。
- 使用既有 Button、Textarea、Dialog、AttachmentList、上传 controller 与单图标入口；文件限制、传输和其他附件状态沿用当前行为。
- 页面演示工具增加“查看首次添加”以直接体验空态；此操作仅清空本页对应示例，不影响其他场景。

局部入口衍生自现有 AttachmentPicker 的 input/receive 防重复机制，源码来源与修改前校验和保存于本轮 evidence baseline。新增局部 Button 配方仅作用于媒体添加位，消费现有 Rain Token。

验证：先补入口状态测试，再运行受影响页面和附件单元测试、类型检查及构建；浏览器覆盖 1440px / 360px，三种形态的空态、已有与拖入退出、真实选择、混合拒绝、同文件再选、键盘、弹窗关闭、媒体播放、原列表折叠。最后查看实际 Rain 预览，记录截图。

设计稿作为布局方向；图标和精确样式以 Rain 当前组件与 Token 为准。上传仍为本页模拟。物理设备触控、Safari、屏幕阅读器及正式对比度验收保留未验证；实现完成后交用户查看。
