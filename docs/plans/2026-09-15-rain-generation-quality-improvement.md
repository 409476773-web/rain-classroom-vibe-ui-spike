## 2. 路线与首批范围

推荐顺序：现有资产使用入口 → BM-D 整页设计对照 → 图表适配 → 新任务迁移。

另两条路线的取舍：

- 先补大量公共组件：扩大能力，但无法直接修复现有组件未被选中和页面组织问题；暂不作为首批。
- 全面放宽规则、切换成熟组件生态：扩大选择空间，但同时引入品牌和重复能力问题；首批只对明确缺口做局部适配。

首批结果只回答三个问题：局部设计是否改善、改善是否能迁移、仍有哪些具体能力或规则缺口。首次运行不证明稳定性或普遍效率优势。

### 变化分层

| 层面 | 可直接使用或探索 | 何时回到共享建设 |
| --- | --- | --- |
| 品牌与基础行为 | 使用已登记 Rain Token、图标、Focus、主题与状态约束 | 需改变已确认基础值、共享行为或引入新全局角色时 |
| 页面组织 | 主从比例、信息顺序、分组、局部留白、阅读宽度与响应式 | 相同关系在多个任务稳定复现并值得复用时 |
| 组件选择 | 现有完整组件、Variant、Size、Density；有依据的 Local Recipe/Fork | 现有 API/配方在多个场景重复造成问题时 |
| 缺失能力 | 先评估现有能力与成熟实现，必要时做页面局部适配 | 行为、接口、主题和消费边界稳定后再讨论公共化 |

保持现有 Variant → Local Recipe → Local Fork 顺序。页面较窄不是自动选择最小尺寸的依据；组件密度仍通过现有机制协调，不靠零散 CSS 缩放控件。

治理改进只解决现有原型自由与实际检查之间的具体冲突，不再建立第三种模式。需要更改检查时保留保护共享组件、依赖边界和历史结果的能力，不删除验证器或把范围扩大到整个工作区。

## 3. 生成过程的具体改法

### 3.1 输入与设计

每个页面先用简短说明明确：主要使用者、要完成的判断或操作、信息优先级、必要状态、使用容器。不强制用户逐项填写；AI 从任务中推导，只对无法推导且会改变方案的内容提问。

复杂页面比较两种有实际结构差异的组织方式。比较可以是简短结构稿，不要求每次实现两套高保真页面。比较、检索和自查都计入实际工作成本。

随后形成一版主方案，并记录少量关键选择：

- 哪些控件改变整页范围，哪些只影响局部。
- 哪个区域承担主要阅读或操作。
- 主要操作、辅助设置和导航分别如何表现。
- 哪些已有组件能覆盖，哪些缺口需要适配。

这些记录用于选择与审阅，不进入业务页面，不要求为每个节点写解释。

### 3.2 从用途找候选

| 用途 | 现有候选 | 关键区别 |
| --- | --- | --- |
| 同级内容分区 | Tabs | 同时处理内容面板与组内键盘关系 |
| 少量互斥条件或模式 | RadioGroup、CheckableTagGroup | 按业务决定是否允许清空；不以按钮外形代替组语义 |
| 较多或较长的候选值 | Select | 考虑选项数量、标签长度与搜索需求 |
| 执行操作 | Button；合适时 IconButton | 依据频率、重要性和识别成本决定表现 |
| 低频操作或显示设置 | DropdownMenu；需要独立字段时 Popover | 菜单项与表单内容分别选择 |
| 即时过滤与明确提交搜索 | Input、SearchInput | 保留既定交互；SearchInput 不是所有搜索字段的默认替换 |
| 展开、收起等图形 | 现有图标规则与静态入口 | 宿主处理状态、名称与颜色，不用字符临时替代 |

不设组件种类、图标数量或 Tabs 使用率配额。默认索引保持实际成熟度门槛；现有工作区可用的本地 Button 等通过明确的本地入口使用，不为了检索而提升资产身份。

### 3.3 排版、密度和设计审阅

复用现有 Typography/Density/Spacing 规则，补其场景应用与反例，不再写一份数值规范。

- 先选页面主次，再选字号、粗细和留白；Data 字体不绑定所有指标必须 36px。
- default 作为表单、报告和工作台的起点；局部 compact 需要结合区域任务和邻近控件整体判断。
- 区域边界由位置、留白、底色和操作关系共同表达，避免仅靠增加 Card、描边或标题加粗。
- 业务页面呈现业务任务；主题切换、失败触发等演示能力放入预览工具区，假数据保留必要说明。
- 审阅必须查看实际整页及交互状态；截图留档、无溢出、颜色合法不单独代表设计合格。

### 依据结果选择后续动作

- 检索命中但仍选错：改善用途理解和示例，检查 AI 的设计判断；不继续堆关键词。
- 选型正确但整页仍弱：继续推敲信息组织、内容与视觉关系；不宣称换图表即可解决。
- 多个场景依赖同一种局部覆盖：核查组件 API/默认配方，形成独立共享改进建议。
- BM-D 好看但迁移任务照搬：降低示例对固定结构的暗示，补选择理由；保留失败结果。
- 图表能力满足但适配负担持续很高：重新评估引擎或适配边界。
- 迁移达到可接受质量：将已验证的选型与组合经验接回同一 AI 入口；后续再处理 BM-C 的设计返工与其他能力扩面。

BM-C 的重复折叠操作、目录图标、模式选择、局部密度与阅读层级仍是已知待改项，不因先校准 BM-D 而消失。该页继续保留宿主草稿、卷别边界、保存失败保护等已验证行为。
