## 2. 同一视觉家族，两种交互职责

| 部分 | 核心职责 | 状态来源 |
| --- | --- | --- |
| 题号按钮 QuestionNumber | 定位当前查看的题目 | 当前位置与作答／批改反馈分别由页面提供 |
| 选项及选项组（名称待实施合同确定） | 选择答案 | 单选或多选的值；结果反馈另外提供 |
| 文字行、图文卡片 | 扩展一个选项的内容与可点击区域 | 复用同一个选项的值、禁用和反馈规则 |

“正在看第 3 题”和“选择了 C”不合并成一个通用 selected 状态。题号仍是导航按钮；选项按 Radio / Checkbox 的选择语义建设。

整行中的 A/B/C/D 标识属于该选项内部视觉，不再套一个独立可点击按钮，避免双重焦点和一次点击触发两次变化。共用样式从已经出现的重复中提取，暂不建设万能按钮、公开标识基类或通用状态引擎。

## 3. 分批交付

| 批次 | 内容 | 本批达到的结果 |
| --- | --- | --- |
| 已完成的视觉基线 | 首版 32 px 题号，方形／圆形、底部反馈、当前位置 | 保留已接受的外观；自动检查、对比度与视觉验收分别记录 |
| 选项基础（已验收） | 32 px 编号；独立 A/B/C/D、单选、多选、整行文字选择；默认、悬停、按下、选中、键盘焦点、禁用；未选中的填底／描边方案 | 能组成完整的单选题与多选题，独立形态和文字行行为一致 |
| 第二批：结果与内容组合 | 选中正确／选中错误、结果未公开、只读回顾；判断题选项；图片／图表选项卡片及长内容 | 学生回顾和教师查看均能使用；结果含义不覆盖选项身份；图文仍复用第一批选择能力 |
| 第三批：完整尺寸（已验收） | 保留底部反馈方案，完成六档尺寸、字重、圆角、标识尺寸、间距和点击区域；右上角反馈暂缓 | 六档公共实现与视觉验收已完成 |

共用规则现在就梳理；先以同一基准尺寸把两种交互做完整，再增加尺寸，便于比较并减少反复。文档、运行验证、图标与 Token 登记随每批交付，不留到最后补做。

结果状态是已规划的必做能力，不因拆批而被遗漏。第二批可先整理状态表，与第一批开发准备并行；选项结构需要容纳反馈，但不提前公开未确定的业务状态。

## 4. 已确认规则继续有效

- 单选再次点击已选项保持选择；多选允许取消。点击整行可以完成选择。
- 单选的圆形与多选的圆角方形属于选项含义；题号中的圆形表示小题，不能仅靠形状推导交互类型。
- 已选中的题号／选项编号字重增加，编号本体没有持续描边；独立的键盘焦点仍保留。
- 选中整行或卡片的外层浅蓝底与弱蓝边，和内部编号本体无描边分别管理。
- 未选中的题号与结果使用对应色系弱描边；绿色、橙色反馈文字保留同色系文字色。
- 后续用户明确覆盖选项回顾：选项编号使用对应色系实底与反白字母／判断图标，没有下方结果小字或附加结果图标；题号原规则不变。
- 题号高强调只用于当前查看的题目，已作答不等于当前查看；当前位置不吞掉结果标记。
- 未作答不自动显示正确答案，未选中的正确选项不默认铺浅绿色；答案公开策略由页面明确决定。
- 全部视觉映射到现有公共 Rain Token；正确、错误、未作答及批改图标使用图标库。
- 尺寸公共 Token 的存在不代表某个图标或反馈组合适用于该尺寸；标记随尺寸的适配另行核对。不能套用 IconButton 的完整尺寸表作为本组件已确认尺寸。

## 5. 下一批前需要收口的少量内容

| 内容 | 推荐处理 |
| --- | --- |
| 选项 32 px 基准和未选样式 | 从已讨论的填底／描边两种外观建立状态表；逐项映射现有 Token，不照搬原型 CSS |
| 只读与禁用 | 只读保留答案与结果的可读性并阻止修改；禁用表达暂不可操作，二者分开验收 |
| 答案评价与表单校验 | “选错答案”和“还没有选择必答项”分别表达，避免共用一个 error 状态 |
| 判断题内容 | 表示“对／错”的选项图标与“回答正确／错误”的反馈要可区分，提供明确文字或可访问名称 |
| 结果覆盖范围 | 选中正确／错误纳入计划；部分正确、漏选、未选正确项提示先保留为业务策略，不自动增加公共状态 |
| 富内容里的额外操作 | 图片展示纳入组合；播放、放大等独立动作在有实际场景时设计清楚操作区域，不能嵌套交互控件 |

这些项目已分别落实到两批选项合同，不要求把全部设计从头讨论。选项当前复用原生 Radio／Checkbox 的选择行为，不以先造完整表单组件库为前置条件。

## 6. 业务扩展贯穿每批

进度可以在题号内部，也可以采用其他组合；异常和申诉同样由业务决定呈现。组件库不再放固定位置的教师进度示例，也不逐项增加批改率、申诉数等业务属性。

优先直接使用完整组件；现有变体不能满足样式需求时使用命名 Local Recipe；需要插入进度等新结构时采用局部 Fork 或实际场景验证后的组合。现有 Local Recipe 只能修改已声明 Parts 的样式，不等于任意结构插槽。

改造仍保留题号／选项身份、当前定位或选择、反馈三者的明确含义，沿用 Token、图标和键盘规则。业务自定义不意味着改变这些基础语义。

## 7. 验证与来源

每批只验证本批变化：选择行为和组间隔离、整行与编号一致性、键盘与可访问名称、禁用／只读，以及浅深色下的真实尺寸和状态。尺寸扩展时重点检查三位题号、圆形小题、反馈碰撞和点击区域。自动化通过与每批视觉验收分别记录；本次 32 px 题号验收不接受其已登记的对比度例外。
