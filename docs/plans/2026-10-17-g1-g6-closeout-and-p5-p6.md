## Task 1：当前差额与正式检查

1. 逐项核对冻结 64 项、实际导出、Registry/Manifest、示例入口与阶段登记；区分共享 UI、组合配方及有意的限定实现。
2. 运行 `pnpm verify:governance`、`pnpm verify:icons`、`pnpm typecheck`、`pnpm build` 与 `node scripts/asset-index.mjs --check`；分别保留命令、退出码和完整日志。
3. 并行运行 `pnpm exec vitest run --maxWorkers=2`；先分类真实失败，不因历史通过就声称本轮通过。
4. 根据实际失败确定最小修复文件。行为缺陷先复现再修复；不降低阈值、删除断言、重签原证据或扩大用户视觉接受。

## Task 2：最小修复与本地收尾

1. 修复本轮确认的问题，复跑受影响检查；行为或验证器修复保留有价值的失败回归。
2. 当前文档入口确有过期时，更新事实源或相应入口；生成索引只由已有生成器更新。
3. 在独立证据目录执行适用浏览器抽查，优先构建产物；检查桌面/窄屏、Light/Dark、关键交互和控制台异常。先检查所有输出路径，避免覆盖历史证据。
4. 独立只读审阅差异，核对实际源与基线，记录通过、失败、未运行和仍需人审项目。

## Task 3：按原计划接续 P5/P6

1. 读取既有工作台、报告与新任务迁移记录，标明哪些能复用、哪些不等价于本次 P5。
2. 在收尾后的固定资产基线上，使用未参与调优的新任务验证检索、真实 API、局部调整与未改兄弟隔离；记录首稿、自查、反馈入口。新任务内容遵循现有设计依据，不变更公共资产。
3. 准备 P6 当前版本整体评审：准确覆盖表、质量和返工记录、剩余问题及可打开的审阅结果。人工评分/视觉接受保留待用户实际评审，不自行关闭。
4. 实际进度及本地授权按当前阶段记录的既有形式追加；不得回填旧阶段，远程、Figma、发布、真实业务接口和生产迁移仍按各自边界。
