# Rain 原型设计：从任务到首稿

本页随本地 Starter 导出，供没有历史聊天的 AI 使用。它组织已有组件与设计经验，不新增公共组件或全库视觉默认。候选、示例和局部接受不能互相替代；新页面需独立审阅。

## 与设计 Skill 的分工

设计判断使用 [Rain Designer](../../.agents/skills/rain-designer/SKILL.md)及其[设计指南](../../.agents/skills/rain-designer/references/designer.md)。本页导航当前品牌、组件 API、Token、真实源码与原型边界，不重复维护方法正文。入口已读时直接继续，不在两个文件之间循环启动。

先理解任务、信息与操作关系，再核对和复用合适能力；历史整页不作为默认答案，不强制布局、卡片、列数、配色、光学偏移或方案数量。[原设计经验库](information-design.md)保留项目案例、来源与历史方法编号，按需核实具体用法或用户明确要求的参考；不作为默认生成起点。通用方法只在 Designer 中维护，项目已确认规则不能被一般原则取消。

品牌主蓝保持 `#1561F8`，消费现有 Rain Token；正式 UI 与中文单位使用 PingFang SC，关键数据的字体资格以现有 Foundations 合同为准。保持 Focus、可访问名称与来源，不分发未经许可的字体。公共 packages 与锁文件默认只读；局部设计自由不授权改共享资产、发布或写入 Figma。

原工作区的当前学习报告 V2 已获视觉确认，记录为 `evidence/runtime/learning-report-a/v2-feedback/verification.md`；这是局部参考，原 `#bm-d`、公共图表和新页面不继承其验收。方法库中的原始案例路径不保证随 Starter 附带，缺失时不能声称已经查阅。

2026-09-19 原有多稿约定保留为历史来源；2026-10-13 当前用户指令改为按任务和风险决定是否比较不同方向，不固定稿数，不因已选方向重新启动选择。普通业务标题优先16/24、正文14/22，长阅读沿用 Reading；重点数据18/20按需要到22/24、数值与单位分开。常规控件优先，同组输入/选择/按钮可显式采用已有36px配方（Button 为 medium，Input/Select 为36），不因区域拥挤自动改 compact。旧共享默认不改。辅助内容先用字重、位置与留白退后，必要信息仍须可读。

## 开始前的四个判断

1. 使用者主要要完成什么：查找并处理多个对象、编辑一个对象、连续处理任务，还是比较数据？写一句主任务。
2. 哪些信息帮助判断，哪些可以稍后查看？确定主要操作，区分整页条件、局部显示和执行命令。
3. 根据前两项判断查找合适的组件、Layout 或组合，核对真实用途、API 和状态。只有选用具体组合、核实行为或明确要求参考/还原时，才查看相关截图与源码；不为套用历史页改变任务。
4. 开工前只记几行：所读依据、选择原因、保留与改变的关系。设计说明留在工作记录，不放入业务界面。

优先复用已有 Variant → 页面 Local Recipe → 页面 Local Fork。共享 packages 默认只读；业务数据、过滤、草稿、校验、保存留在页面。不要为一页增加全局 Token 或公共 Props。

## 按行为选择组件

| 用户行为 | 首选与判断 | 避免的误用 |
| --- | --- | --- |
| 切换完整的同级内容区域 | [Tabs](../../manifests/ui/tabs.yaml)，同时提供导航与面板 | 仅为分段外观创建空面板 |
| 少量选项中选一个条件或模式 | [RadioGroup](../../manifests/ui/radio-group.yaml)；标签型筛选比较 [CheckableTagGroup](../../manifests/ui/checkable-tag-group.yaml) | 一排普通 Button 各自管理选中状态 |
| 从较多候选值选择 | [Select](../../manifests/ui/select.yaml)，搜索、多选按任务选择 | 为少量模式切换默认增加下拉步骤 |
| 立即过滤 / 明确提交搜索 | [Input](../../manifests/ui/input.yaml) / [SearchInput](../../manifests/ui/search-input.yaml) | 因组件名含搜索就改变生效时机 |
| 执行动作 / 打开低频操作 | [Button](../../manifests/ui/button.yaml) / [DropdownMenu](../../manifests/ui/dropdown-menu.yaml) | 没有真实任务的更多菜单或重复操作 |
| 展开、关闭或纯图标操作 | [IconButton](../../manifests/ui/icon-button.yaml)，提供可访问名称和真实状态 | 近似字符或自绘图形替代已有图标 |
| 编辑字段 / 重要确认 | [FormItem](../../manifests/ui/form-item.yaml) 配合字段；[Dialog](../../manifests/ui/dialog.yaml) / [AlertDialog](../../manifests/ui/alert-dialog.yaml) | 页面另写焦点、Escape 或嵌套浮层控制器 |

合同中的 useWhen、doNotUseWhen、Props 和 Parts 是选型与 API 来源。只读命中的几项；从 [UI 出口](../../packages/ui/src/index.ts)核对真实导出，不猜 Props。Button 等本地资产不因随 Starter 附带就获得公共发布身份。

## 把组件组织成页面

需要同排控件、分区表单或连续批改时，查看[三个组合指引](composition-recipes.md)，核对尺寸、业务状态归属和允许改造的位置；附完整源码，新的业务组合仍需单独验证。

就近的纯文字说明使用共享候选 `@rain-next/ui` Tooltip，合同见 `packages/ui/src/tooltip/README.md`，继承 Classic 固定深底视觉。Resizable 已在本轮迁为共享候选，从 `@rain-next/ui` 导入，独立 Playground 入口 `#resizable`；此前固定 Starter 快照不自动包含本轮新资产，源码合同见 `manifests/ui/resizable.yaml`。用于阅读与判断区域的空间分配。Tooltip 当前视觉与默认下方交互已确认，Resizable 原样板视觉接受保留为来源，本轮共享候选与文档待审；不以 Tabs 截断提示冒充通用入口，不复制拖动引擎，业务状态留宿主。

| 条件 | 保持的设计关系 | 反例与检查 |
| --- | --- | --- |
| 多个控件作用于同一份结果 | 查询放在同一组，共用结果范围；显示设置和批量操作分组 | 不把全页筛选混进图表指标切换；检查改变条件影响哪些区域 |
| 多个区域服务同一连续任务 | 先判断共同表面与分隔，再选择容器 | 不因每区有标题就各套 Card；看整页主任务是否清楚 |
| 需要强调层级 | 结合字重、留白、对齐和表面，使用已有排版方案 | 不把每个标题、数字都放大；14/16px 等搭配只属于原场景 |
| 多个重点数据需要主题辨识度 | 按指标含义选语义图标或同风格小插图；用近主题色的配色家族、浅染色与局部材质区分主题和分组 | 不默认退化成白卡加文字；不随机给每卡换风格，也不把装饰色与风险状态混用 |
| 相同内容重复出现 | 保留最有用位置上的一次表达 | 总数、对象名称、操作和解释不在相邻区域重复；必要错误/状态反馈除外 |
| 窄屏或内容变长 | 先换行、堆叠、调整比例和滚动范围 | 不自动缩小所有文字和点击区；测试长标题、错误、菜单、底部操作 |
| 选择的是完整对象 | 选择控件与整对象反馈对应；查看入口独立 | 标题点击不同时改变选择，Checkbox 不贴在日期旁暗示只选日期 |

上表是有条件的组合判断，不是固定模板。表单/报告/工作台以 default 密度为起点；列表局部 compact 要连同邻近字段、按钮一起判断。Card 表达对象或明确表面，Layout 表达空间。

视觉值继续来自 [Typography](../../packages/foundations/src/typography-contract.ts)、[Token](../../packages/foundations/src/token-contract.ts)及[布局源码](../../packages/layouts/src/layout.tsx)。普通文字用 UI 字体；长正文按 Reading 角色；关键数据才考虑 Data 字体，中文单位分开。不复制 Tailwind 默认配色、任意阴影或新字体。

排版、通用内容条目与任务进度的具体调用见 [G4 使用说明](g4-components.md)：Typography 直接选择现有预设，普通内容用 Item／Parts，确定或未知比例用 Progress。任务状态与业务操作留宿主；新增候选和用法有各自待审范围。

图标从 foundations 的 icons/catalog 公共入口核对身份及 availability，再通过 @rain-next/ui/icons/<slug> 静态导入。按真实行为选图标；某页的图标选择不自动成为全局语义。

2026-09-19 用户补充的报告设计方向：重点数据的语义图标、邻近主题的多色、局部柔光、渐变图标底及半透明层次，既能帮助识别，也有独立的审美价值。学习变化型指标卡的左对齐扫读与分组总览的居中插图两种构图；图表应让系列色贯穿标记、图例和读数浮层，表格可用微型条和浅色标签区分数值与关系。这是报告重点数据区的局部表达探索，不自动替换全局默认或普通控件规则；普通统计使用这些手法不代表 AI 生成，不添加虚假的 AI 身份。来源为用户提供的 Figma 文件 `MbWg1ft5zk1JRQiQ6dS30e`，节点 `2827:93616`、`2827:96656`。学习覆盖两份完整设计稿的全部模块；四张局部截图只是重点。除重点数据外，也学习目录与工具栏、原文高亮、图文对照、网络图与图例、热力和气泡矩阵、章节解读、纯文字总结、局部筛选与分页。先理解每个模块的信息问题和视觉表达，再判断适用场景，不用当前页面的数据或组件缺口限制学习范围。相关组合仍是设计参考，尚非成熟视觉模板。

## 连续处理工作台的已确认案例

当前导航E1–E6已在2026-10-05获得运行视觉、本地AI消费与实例隔离审阅确认，见[消费合同](navigation-v042-w6.md)及[决定范围](../../evidence/runtime/navigation-v042/g3-acceptance-review02/acceptance.json)。这是可参考的本地组合案例，候选仍未发布，完整质量门单列。

- 分类、当前对象、对象内内容分别选NavigationList/ObjectNavigator/NavigationTabs，少量模式条件使用SegmentedControl。Tabs需要承载真实面板，避免只有页签外观；按人/按题只改变遍历顺序，草稿保持学生ID＋题目ID归属。
- 摘要先合并同对象信息、删除重复解释，再压缩组内间距；标题与元信息可同行，窄容器允许自然换行。普通标题16/22和队列密度是当前局部配方，不修改共享默认。
- 类别和评审状态适合小Tag，所有条目共有的满分是普通属性；成员由头像、姓名、学号、职责成组。必要信息不能因“小字”身份而一律淡化。
- 收起入口附近保留稳定恢复按钮，独立滚动面板的标题在本面板吸顶。临时/固定/专注的布局事件不触发业务保存；评分用现有InputNumber，长反馈用Textarea，按页面选择已有filled样式。

方法依据已合并到V04、D02、D03、I01。新业务只复用关系与判断过程，仍按实际内容、容器和状态验证；不照抄E2/E3窗口尺寸或自动继承视觉验收。

## 提交前：整页 → 区域 → 组件 → 状态

- 实际打开桌面和窄窗口：主任务与主操作是否可辨，信息和控件归属是否一致，是否有无用容器或重复内容？
- 检查真实长内容、必要的 loading/error/empty/disabled，以及键盘、焦点与关闭恢复；不用额外假操作凑齐展示。
- 修改外观时保留完整尺寸和状态关系。低对比度历史样例不能推广；引用样例颜色不等于该组合已通过对比度。
- 保留第一次可运行源码/截图与后续修正，分别记录自查、技术复核和用户反馈。未实测的耗时、token、返工成本写 not-measured。
- 第一次用户反馈前，用 design-notes.md 记录选择依据、所读文件、实际检查及未验证项。AI 自查不能替代用户视觉接受。

## 反馈进入下一次生成

每次修订提取：**触发条件 → 原问题 → 设计判断 → 使用方式 → 适用范围 → 证据与确认状态**。先更新已有指南或组件合同，避免复制同义规则。

设计完成、确认后，检查是否有可复用的新经验；中间反馈先记在任务记录中，未经验证的探索注明状态。项目案例可按[原经验库](information-design.md)的来源与范围格式维护；通用方法仍由 Designer 单点维护，修改方法正文需相应授权，不另建并行方法库。没有新发现不追加。独立 Starter 的补充先留在衍生副本，回到原工作区时核对来源再合并，不覆盖原快照锁。

- 通用组件缺陷或已授权默认调整：回到共享组件与合同。
- 多个组件的关系：更新组合指南和参考图，保留场景身份。
- 单页文案、像素微调或局部图标偏好：留在页面 Recipe，不上升为全局标准。

知识文件不会自动训练模型。效果依赖实际加载和使用，须用未参与调优的新需求再检查；一次成功消费不能证明稳定质量提升。
