# 给小文｜新版进度表怎么用

## 只记住一句话

**基础只补当前需要的；组件先成组可用；细节留到后面。**

## 六个工作表

| 表 | 什么时候看 |
|---|---|
| 每天看这里 | 每天开始：看基础放行提醒、今天主线、各组可用数、等待你看的项。 |
| 基础准备 | 先看F01—F05；F06/F07按需，F08到报告组再做。 |
| 64项组件 | 查看每组顺序，更新蓝色输入格。 |
| 页面验收 | 工作台P1/P2、报告P3/P4、新任务P5、首版P6与组件同时推进。 |
| 稍后精修 | 记录不影响当前使用的小问题，不在主线上无限改。 |
| 说明与来源 | 忘记统计口径、旧进度怎么带过来时再看。 |

## 每天只做三个动作

1. 开始：确认今天主线；基础有阻塞只影响相关任务，不等所有Token完善。
2. 验收：看本组结果，只记一个最主要的问题；微调达到2轮就判断“必修”还是“后补”。
3. 结束：更新状态与证据，把细节记后补，明确明天主线。

“开发反馈/基本检查”依据执行者实际结果填写；你的判断依据你看到的结果。不需要看代码，但不要把没有证据的“他说完成”当通过。
证据栏可写预览地址＋短记录路径/版本号；无入口时可写检查报告/截图记录，不能只写“通过”。

## 组件表自动结论

- 可演示、基本检查通过、你判断通过、覆盖本轮约定范围并有记录，才显示“本轮可用”。
- 范围只有部分时显示“限定子集”，不混进64项本轮可用数。
- 基本检查通过但你还没看，显示“待你看”。
- 没有检查/版本记录时会提醒补记录。
- 阻塞或需修复的继续保留；不依赖它的任务可以继续。

## 基础表的“已核验”不等于全部Token完成

F01—F05为首批前置，证据齐全并完成对应检查/确认才算放行。F05需要你的限定默认方向确认。
F06/F07没新增需要时可填“本批无需新增”，但要写核对/复用理由；后面有新消费者仍可重开该任务。
F08在报告批次做，不拖住其他组件。颜色更多、所有色系更细，不是基础放行标准。

## 新旧进度怎么衔接

本次上传旧表全为初始待核对/待开始；新版保留了这些实际收到的字段，没有收到你另填的副本。
你电脑里已有填写时：按“64项组件”的原工作包条目键，将开发反馈、基本检查、我的判断、轮数、记录、主要问题迁入对应项；不要按行号盲复制。新增“覆盖范围”需核对，不能自动认定完整。
页面按P1—P6迁移，精修清单逐条保留。不要让新版空白覆盖旧成果，不重开两周计时。
本表是个人跟进记录，不能将其“本轮可用”直接写成仓库system-approved、正式发布或完整可访问性合格。
