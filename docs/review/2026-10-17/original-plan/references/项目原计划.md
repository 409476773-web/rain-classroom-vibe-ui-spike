## 项目背景

### 项目现有问题
雨课堂现在已经有了一套基础的组件库。 已有figma的组件库设计稿，包含多种可在画图时直接使用的组件、token、颜色。

这套组件库，直接给ai使用时，vibe coding能力较差。ai只能生硬地套用组件库内容，无法像使用 google ai studio 时，搭配shadcn-ui 组件库一样，既能遵循一定的品牌规范（颜色，文字，字号，间距，token，设计基础决策原则....)，同时，又能：
- 灵活选择布局、设计各种导航、顶栏、侧边栏、内容模块等等模块样式
- 灵活地 改造组件：在现有组件合理的位置，新增其他组件 或  改变样式 或 新增样式 ......
- 组装组件为更复杂或更贴合业务的功能要求的复合组件
- 搭配大模型，灵活且知道怎么使用各个现有的组件

### 项目目标
#### 增强组件库：
1.补充现有组件库的组件种类与能力：相比起 **shadcn-ui**，ant design ，material ui 等优秀组件库，雨课堂现有组件库组件样式、能力不足。无法更好地支持复杂业务
2.**重新梳理组件库架构**。
3.改造为更适合 vibe coding 和 vibe design 的技术架构。（只优先服务 vibe design 和 vibe coding 原型生成，先不考虑实际代码生产环境）

#### 改造为更适合 vibe coding 和 vibe design 的组件库
1.改造组件库为 适合 **vibe coding** 的 ai-ready组件库。 方便产品经理，根据业务需求，快速制作出 符合业务需求与雨课堂品牌风格的可交互原型。
2.改造组件库为 适合 **vibe design** 的  ai-ready组件库。方便uiux设计师、产品设计师，根据业务需求，快速制作出 符合业务需求与雨课堂品牌风格的可交互原型。并且在此之上，ai能与设计师一起改造与设计组件（因为不同业务会有不同的组件应用方式、甚至改造出新组件）
3.ai能清楚地知道，有哪些组件？这些组件可以怎么用（不要完全限定死，允许一定程度的自由发挥）？改造组件时可以怎么摆？页面有哪些布局？....
4.所有组件，除了沉淀在figma设计稿里，也需要一份可以体验和使用的 html网页版 playground（且有清晰的分类，不要混放在一起）。非开发人员（无代码知识），可以使用playground，体验组件，同时，也提供一些变颜色、参数的端口。


#### 打通组件库设计与代码的协作流程
1.设计师可在figma内，自行改造、组装、设计新组件，同时交给codex，进行组件库代码沉淀。
2.同时，使用ai进行 vibe coding出的新的组件时，也能导入到figma，交给设计进行设计图的二次绘制。（注意，这个功能不需要组件库本身能满足，只需要有别的工具能把用这个组件库做出来的代码，导回figma内即可）。
