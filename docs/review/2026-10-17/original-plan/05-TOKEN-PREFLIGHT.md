# Token 必要准备｜F01—F08
## 0. 决策：加强基础，但不扩大为另一轮系统重建

这是原G0/G1内的限时工作。先让新增源码正确消费Rain、默认设计更协调，再批量扩面。
原Token审阅为只读历史依据，本包把其中建议转成实施任务；不自动修改共享值、授权或状态。源码是当前数值来源，不手改生成文件，不将所有旧别名一次迁移。

**不是把全部T01—T19建完才做组件。**它们是审阅分类；F01—F08才是本次操作顺序。
F05要通过G1真实样板验证，故G1制作与基础准备同步。只有与该组件有关的新基础缺口才阻塞其放行。

## 2. 任务详情

### F01｜核对现有基础与本机版本

**时机：**G0｜第1天；性质：前置。关联审阅：T03, T05, T18。依赖：无。

**实施：**读取当前Token事实源、生成器、说明与已有差异；确认teacher-grading源码；只修正现行说明漂移，不改历史记录。

**通过标准：**给出本机版本、已有/缺口清单与证据；审阅快照的17/15等计数在本地重新核对，不能盲填。

**停止边界：**已有定义能用就复用，不重新做整库审计或整套色板。


### F02｜shadcn → Rain 样式对应

**时机：**G1｜第1—2天；性质：前置。关联审阅：T18, T03, T12, T15, T19。依赖：F01。

**实施：**以固定取得的首批源码列出实际用到的颜色、排版、间距、尺寸、圆角、阴影、主题、断点/容器与动画；集中翻译为现有Rain入口或受控别名。

**通过标准：**真实组件样式生效，主题/Portal正确；局部改一例不影响兄弟例；源码与构建产物均有检查记录。

**停止边界：**只覆盖首批实际需求；后续批次增量补映射，不先穷尽整个Tailwind。


### F03｜新原型默认字号与同组尺寸

**时机：**G1｜第1—2天；性质：前置。关联审阅：T04, T05, T08, T09。依赖：F01。

**实施：**普通页面标题优先16；常规正文以已有14方案起步；重点数据18/20按需到22/24；常规控件优先，同排协调；核对本机字体回退。

**通过标准：**同一工具栏无无理由紧凑控件或大标题；新消费配方可查；旧样式/特殊大屏用法未被全局改变。

**停止边界：**不删大字号，不全库改默认，不把所有控件强制等高；代码字体按真实需要再补。


### F04｜常用配色与键盘焦点

**时机：**G1｜第1—2天；性质：前置。关联审阅：T01, T02, T03, T10, T13, T14, T19。依赖：F01。

**实施：**复用现有任务面、辅助区、选中、提示、危险、标签配方；检查前景/底色/边界/状态与实际主题；焦点接现有机制。

**通过标准：**重点清楚、辅助信息不抢眼、必要内容可读；状态与焦点可辨；低对比度未决项不当通过。

**停止边界：**不扩无限色板，不将所有辅助信息加深；不让未触及的历史问题阻塞全线。


### F05｜两个真实组合样板放行

**时机：**G1｜第2天内目标；性质：前置。关联审阅：T18, T05, T08, T03, T19。依赖：F02, F03, F04。

**实施：**①工具栏：输入/选择/按钮或切换/辅助信息；②内容卡与浮层：标签/关键数字/局部网格/菜单或弹窗；同页保留默认、局改与兄弟实例。

**通过标准：**F02—F04检查通过；两个样板可看可操作，设计师限定确认默认方向；证据范围明确。

**停止边界：**只确认这次默认方向，不当全库通过；阻塞只影响相关任务，其他独立任务继续。


### F06｜大间距与轻阴影少量补缺

**时机：**G1起｜遇缺口再做；性质：按需。关联审阅：T07, T10, T11。依赖：F01。

**实施：**只有真实组合需要时补48/64间距、1—2档轻阴影；同步源定义、Layouts类型/映射、生成输出、检索和相关检查。

**通过标准：**新增有真实消费者且浅深主题/局部改造正常；不需要新增则记录复用理由。

**停止边界：**未触发需求不建设；不改变Card既有默认，不将宽高全部塞进间距表。


### F07｜响应式与叠放顺序

**时机：**G1/G3｜相关组件前；性质：按需。关联审阅：T14, T15, T16, T19。依赖：F02。

**实施：**为实际源码所用断点/容器条件建立映射；整理最小浮层层级角色，保留已有叠放上下文；测弹窗内菜单/提示与分栏变化。

**通过标准：**窄窗口可用、必要操作不被遮挡；容器阈值和视口断点不混用；无新增需求则有核对理由。

**停止边界：**不把所有局部阈值统一成全局断点，不只靠无限提高层级数字。


### F08｜图表角色与数据正负号

**时机：**G4｜第5—6天；性质：报告同步。关联审阅：T06, T17。依赖：F02, F03, F04。

**实施：**复用现有色值建立分类系列、顺序色阶、正负变化和轴/网格/提示角色；核对+12%、-12.5%及字体支持；单位分开。

**通过标准：**趋势/比较/构成示例数据与图例一致；零值/缺测有区别；正负号正确；不只依赖颜色。

**停止边界：**不是先扩全部色系，不重写图表引擎，不把第一系列永远等同品牌或成功。


## 3. F02 的最小映射交付，不是另建Token平台

复用当前源定义与生成入口，由执行者在已有体系中确定单一登记位置。`templates/TOKEN-MAPPING.template.json`只是记录示范，不是要求新建一套运行Schema或复制品牌数值。

每项至少记录：
来源资产及固定版本/文件哈希；来源类或变量；实际用途；现有Rain对应；策略（原样结构/转译类/语义别名/必要新增）；作用域和主题；消费者；实际验证。
没有核对的映射保持待验证，不能用空引用标完成；上游多份素材的哈希分别保存。

| 需核对的层面 | 具体风险与处理 |
|---|---|
| 颜色 | surface/foreground/primary/accent/muted/selected不能全部映到同一蓝；互相关联的前景/背景成对检查。 |
| 几何 | `p-4`与`p-rain-4`不可按数字同名替换；控件高度、图标、点击范围与布局间距分别处理。 |
| 排版 | 上游font-medium等与Rain已有字重需核对，不为名称一致全局增加新档。新普通页面不默认24/36大字。 |
| 圆角/阴影/边界 | 使用已有映射或当前真实缺口；none/无边界是有效能力，不为了凑数字制造新Token。 |
| 主题/Portal | 明确Rain主题标记与上游类/变量的传递；嵌套浅深区域、浮层打开后主题变化按实际支持验证。 |
| 响应式 | 确认主题重置后所用断点类可生成；容器条件与视口断点不能混淆，局部尺寸不全局化。 |
| Focus/动效 | 保留键盘行为，接已有Focus与减少动画规则；避免叠两套ring或保留无来源动画库依赖。 |
| 构建/扫描 | 所用完整类名能进入输出；动态拼接类不假定会生成。同时查看实际样式与浏览器结果。 |
| 局部修改 | 改一例时默认兄弟例不变；层叠/作用域真实起效，不能仅检查DOM上已有class。 |

**两种实现手段都是最小适配：**把来源类转译为Rain已有类；或为来源提供引用Rain变量的受控别名。W1根据真实成本选定一套主要策略，避免每个组件随机选法。不得把全部Tailwind默认视觉重新开放当作快捷修复。
结构类（flex/grid等）本身不等于视觉Token；布局创造不应被误限制为只能套固定组件。视觉值受约束，页面内部结构仍可自主组合。

## 4. 两个组合样板的检查清单

### 样板A：工作台工具栏
同一行或合理换行的输入、选择、动作按钮、互斥切换和辅助信息；文本长度包含真实长名称。
先看信息归属、主操作与组间留白，再看不同组件尺寸协调。单选语义保留；不以一排互不关联Button冒充。
展示新原型标题/正文/辅助文字，必要数据用克制尺寸；旧组件默认不全局改变。

### 样板B：内容卡与浮层
一个卡片内混用横排、纵排和局部网格，带分类标签、重要数字/单位、普通说明与操作菜单；弹窗或浮层按真实用途组合。
同页保留未改实例、局改实例、兄弟实例，验证内层/外层不串样式；含键盘进入退出、长内容、窄容器、主题与实际叠放。

### 最低证据与放行
- 固定输入来源、实际改动/哈希、消费者、日期、命令及环境。
- 两个样板均有可打开的入口、实际画面检查和适用状态；源码模式与构建产物的样式对应检查。
- 新默认/新配方的关键可读性和焦点问题需处理；未相关旧问题独立保留。
- 用户集中确认限定默认方向后，F05记完成并扩批。已有同范围有效确认可引用；没有确认不能代填。
- 超时不扩大研究、不用继续加色解决未定位问题；报告卡点，推进独立项目。

## 6. 新增共享Token的规则

只有同时满足以下条件才加入本轮：实际源码/业务组合需要；现有值/角色不能合理覆盖；名称/来源/用途清楚；消费者存在；类型、导出、生成、映射和检查一起交付。
48/64和1—2档轻阴影仍是候选，不因出现在计划里就写入共享体系。方案/新默认需在样板集中判断；不逐像素反复征求确认。
代码/快捷键用等宽字体确有需求时再加Code角色，不随便下载字体；不要把关键数据专用字体用到普通代码或中文单位。
标注“可探索”的新配方，与默认推荐的已核验配方分开。不得把装饰类别用于绕开必要文字/操作可读性。

## 7. 迁移与不做项

保留既有语义ID与已确认样式；新原型的推荐优先级可以调整，但旧消费者要有明确变更范围和回归。
不机械扩所有色系到10/12档，不增加超小控件来塞信息，不清除全部大字号，不统一全部局部断点，不重新搭Token服务器/Figma同步平台。
新任务仍引用已有Manifest/Registry和生成器。个人表记录“本次是否看过”，不是第二份Token事实源。
