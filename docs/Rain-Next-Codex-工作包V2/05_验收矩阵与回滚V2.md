# Card 与接入批次验收矩阵 V2

## 0. 使用原则

下表全部是计划测试，不是本轮项目测试结果。执行状态统一在 [08 机器台账](08_计划与验收台账V2.json) 中保留 `not-run`；实施时按实际结果登记，不通过本包初值改变仓库的正式生命周期。

技术检查、视觉接受、对比度、真实设备与发布各自独立。仓库旧记录不能被新截图覆盖，也不能因为一个局部样本通过就关闭整个 Benchmark。

## 1. 基准组合

使用 CR-01 信息卡、CR-02 课程媒体卡、CR-03 指标片段、CR-04 操作卡；同屏至少有目标和非目标 Card，另有受保护的 Button、Input、Tag 或 Surface。测试均用虚构数据。

视口与尺寸分开：Card 的宽度受容器控制，不把网页视口直接当作卡片宽度。建议检查宽容器、侧栏窄容器、长中文／英文不间断文本；采用项目实际支持的主题、Density 与设备声明范围。

不要求把所有排列做成巨大笛卡尔积。默认完整组合、每项关键边界和高风险嵌套必须覆盖；其余采用代表矩阵，报告具体覆盖。

每个实际执行项保存：测试 ID、实际命令或操作步骤、实际 HEAD／工作区摘要、浏览器和字体环境、结果、日志／截图位置、未覆盖范围。字段嵌入当前仓库证据格式即可，不必新建第二套验收平台。

## 3. 两轮 vibe design 任务

### 任务 VD-1：结构重排

对同一个课程媒体卡提出：保持内容与操作不变，将上图下文改为左图右文；窄容器恢复上下，不能复制基础 Button／Tag 实现。

核对：变更文件范围、是否只变目标 Recipe、布局是否可解释、未注册视觉值、字段和事件是否保留、窄容器可读性。

### 任务 VD-2：从上轮继续调整

在 VD-1 的真实结果上，将目标卡片改为更紧凑的主标题和说明组合，Footer 操作调整为次要位置；同屏另一个 Card 不变。

核对：是否理解已有状态、是否能用现有 size／Recipe、是否反复修改公共 Master、非目标 computed style 和交互是否改变。

不要给执行代理预置“必须成功”的结论。允许记录真正需要系统改造的缺口；这就是测试要发现的结果。

## 4. 价值评测如何计量

只记录实际可观察量：任务是否完成、真实用户纠正次数、代理自行修复次数、修改文件范围、是否意外改变非目标、视觉评审结果。

真实用户纠正次数与代理修复次数分开；未发生真实用户评价时填 `not-measured`，不是 0。技术自动判定“颜色来自 Token”不能代替“视觉层级正确”。

本轮独立 CSS 实验不能用来声称库级生成效率提升；旧 B2 的未完成对照也不能当作新效果证据。

## 5. 准入门槛

| 状态 | 允许表达 | 不允许表达 |
| --- | --- | --- |
| 合同／来源已整理 | 可准备实施 | 组件已迁移 |
| 技术矩阵通过、视觉待看 | 技术候选可预览 | 新视觉已被接受 |
| 限定视觉与必要交互接受 | 对应范围原型可用 | 全主题、全可访问性、生产可用 |
| 来源／Manifest／本地记录闭合 | 当前工作区可追踪 | 标准 Registry 已发布 |

关键语义、事件、依赖和样式缺失不应作为“已知限制”直接放行；低频未实现形态可以延期并明确范围。

颜色判断按部件用途和项目既有规则：必要文字和焦点不因视觉喜欢而自动豁免；装饰边界也不要被误当成每个都必须满足交互边界要求。原有已接受例外仅限原记录，不扩展给 Card。

## 6. 回滚与不破坏原则

实施前记录：实际 HEAD、未提交修改、已知消费者、受保护文件清单、Card 相关旧样式区段。可以用本地对比副本或已有版本控制，不自行创建远程仓库或推送。

出现以下情况，停止切换默认使用而保留候选用于诊断：

- 有效标题／ref／事件丢失，现有消费者无法编译；
- Card 改造影响了非目标组件；
- 样式仍依赖 Playground 或上游未提供的工具类；
- 需要超出授权范围的依赖大升级或核心全局重构。

回滚只撤销本批可追踪差异，不使用全仓 reset、clean、覆盖 checkout；共享文件有其他人后续修改时逐块处理。不删除失败证据，不恢复错误的生命周期标记，不回写旧截图。

允许一个临时、明确标记的局部比较版本；验收后公共默认入口应唯一。并行版本不是永久绕过迁移的策略。

## 7. 本轮独立实验实际结果

这不是上表的项目验收。

- [CSS 级联](证据/css-cascade-reproduction.json)：同源普通旧规则与分层工具类冲突时，左右留白为 20px；调换 class 属性顺序仍为 20px；不再匹配旧类后为 0px。
- [选择器归属](证据/selector-scope-reproduction.json)：后代 Footer 条件同时匹配内外两个卡片；限定直接子节点的对照只影响内层。
- 使用容器 `/usr/bin/chromium`，版本 144.0.7559.96；页面是手工构造的最小 HTML，没有安装或导入 Rain／shadcn 工程。
- 首次尝试 Playwright 默认浏览器路径时因二进制不存在而未运行；改用已安装 Chromium 后完成上述两项。没有下载或安装项目浏览器。
- 项目构建产物、Card 真正的嵌套行为、声明范围的多浏览器与字体环境仍须 Codex 执行。
