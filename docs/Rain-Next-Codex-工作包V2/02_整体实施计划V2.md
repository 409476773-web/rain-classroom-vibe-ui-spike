# Rain Next｜受控补齐与 Card 优先替换实施计划 V2

## 0. 目标与范围

目标是让现有 Rain Next 在 1–2 周的实施窗口内形成**原型可用基线**：能生成真实页面、连续改变结构、维持品牌和行为，再按业务深化。64 品类是完整处置与逐步覆盖范围，不是两周内所有变体、Figma 和生产质量都完成的保证。[P01][E01]

以用户最新说明为准：旧 Vue 库停止继续建设，仅提供视觉、功能与业务参考；旧文件中的“独立演进”措辞不构成继续改造 Classic 的任务。

本计划保持当前 React／TypeScript／Vite／Tailwind／Base UI 方向。Card 改为优先采用 shadcn 基线适配，其他已有组件不跟随它批量替换。[R04][R13]

审阅参考：`321e1a0c1b5f9284e0fcb5167fa059d6174b1752`。实施时首先比较本地 HEAD 与未提交修改，不得通过 reset、clean 或 checkout 覆盖来回到参考版本。

## 1. 三类完成必须分开

| 层次 | 最小含义 |
| --- | --- |
| 目录处置完成 | 每个品类知道对应 Rain 资产、缺口、采用方式、优先级 |
| 限定原型可用 | 实际代码、样式、状态和交互在声明场景通过验证 |
| 系统或生产成熟 | 另有设计 Gate、广泛验证、发布及生产硬化；本轮不自动取得 |

来源标签、资产身份、成熟度、发布和业务采用沿用仓库现有定义，不能相互推导。本文不创造新的仓库生命周期枚举；M0-C 等只是计划里程碑。[R01]

## 2. 第一周的双样本

### M0-C：Card 的静态接入与 vibe design

采用已固定审阅的上游作者源码与 Card 样式段，完成 Rain 适配；保留公共入口、有效语义与追踪标记；移除会继续覆盖新样式的旧 Card 声明。交付基础、课程媒体、指标内容、操作型四个 Recipe 示例，以及真实局部改造测试。

不引入新的 Headless 底座；不建设完整卡片编辑器；不扩展出几十种公共卡片类型；不等待全部公共 Layout 完成。示例可先用受控结构类组合。

### M0-O：Dialog 的复杂交互接入

新 Dialog＋公共 Separator，复用已有 Button／Input／Select／FormItem。检查主题、密度、嵌套浮层、焦点、长内容、保存失败和草稿。

M0-C 不能代替 M0-O：Card 成功只证明静态样式与组合路径成立，不证明复杂浮层安全。

两条线共享接入规则、来源记录和原型入口。人员不足时先 Card，立即转向 Dialog；人员充足时在接口与共享文件负责人明确后并行。

## 5. 首批接入准则

### 5.1 保留规则

保留有效接口、品牌、可访问性、图标身份和使用经验；不强制保留薄弱的具体实现。Card 改换来源，不等于 Surface、Badge 或所有基础组件也换源。

### 5.2 样式转译

沿用 Rain Token 的单一事实来源。覆盖颜色、排版、间距、圆角、Focus、状态选择器、动画依赖、类合并和扫描范围；不把 `primary` 等同名角色不加判断地硬映射。

当前 Tailwind 清空默认主题，所以源码出现一个类名不等于该 CSS 已生成。局部 className 顺序也不能解决旧 CSS 优先级；按实际层级和 computed style 验证。[R05][R06][E04][E05]

新 Card 仅清理 Card 自己的旧样式；不得为了 override 生效，改变整个 UI 样式表层级或普遍使用 important。

### 5.3 上游来源

Card 审阅双文件已固定于 `3ba91b1…`；两种合法接入方式：获得该来源可核实的完整安装产物，或明确以作者源码＋所选样式的 Card 段完成本地转译。后者不要求构建完整上游仓库。

不得只复制带 `cn-card` 的模板就宣称视觉接入完成；不得因模板引用 `cn` 而安装新的工具包。记录来源文件 Git blob 与实际取得内容的摘要，不能拿 CLI 版本替代组件版本。[U01][U02][U03]

其他组件分别锁定，不受 Card 的 source commit 自动担保。

### 5.4 元数据

Card 补独立 Manifest 与本地 Registry，沿用现有项目格式。结构化规则写“用途、部件、状态、修改边界、依赖与来源”，不复制完整上游文档成为永久提示词。

标准 shadcn Registry 的兼容输出后续按需生成；裸 `button` 不是 Rain Button，依赖必须明确定向。[R12][E07]

## 6. 页面驱动的补齐顺序

### A．Layout 与 BM-A

先做 Stack／Inline／Grid；Split 先处理区域、最小尺寸、收起与滚动，拖动调宽和持久化可延后。它们不拥有查询或评分。

补 Table／Pagination／Empty；数据处理配方复用已有 SearchInput、Select、Checkbox、Dropdown 和 Tag。Card 视图使用新 Card 和同一宿主数据，不复制一套查询。

建议场景规则（需在场景中显式登记，不自动升级为组件全局默认）：

- 记录使用稳定 ID；当前查询中跨页选择按 ID 保留。
- 表头全选明确为当前页可操作项；全集选择暂不实现。
- 查询条件变化时清空选择并重置页码；切换表格／卡片保留查询与选择。
- 图表如加入，统计范围必须明确，不能默认为当前已加载页。
- 宿主拦截过期请求；不是 Table 自行请求生产 API。

### B．字段与 BM-B

Textarea 接入现有 FormItem 上下文；只把原生 textarea 塞进去不算完成标签、错误、禁用的桥接。Select 不提供原生约束校验和 FormData 桥接；宿主负责草稿、错误和提交。[R08][R09]

使用 Dialog 或 Sheet，覆盖长文本、单／双列、固定操作、保存中、失败重试、取消。上传可先模拟，但要明确成功／失败；未实现时只能关闭相应切片，不能把原登记的完整 BM-B 标为通过。[R10]

### C．BM-C 工作台

围绕任务条、左上下文、中主任务、右检查器、独立滚动与收起。收起和布局切换不应意外丢失业务状态。不可将整个工作台改造成一个公共 Card 的配置参数。

### D．BM-D 报告

形成清晰的标题、四个关键指标、趋势、摘要与 AI 洞察。Statistic 为数值／单位／标签的轻量组合；不改变 LINE Seed 的限定范围，不分发字体。Chart 使用必要的成熟引擎与 Rain 映射，不先建设全图表库。

## 7. 设计自由度

| 范围 | 可以做什么 | 保持什么 |
| --- | --- | --- |
| 页面使用 | 选已有变体、内容、尺寸，调整允许的布局 | 品牌与基础行为 |
| 局部 Recipe | 改指定部件的已登记样式、结构组合 | 功能作用域、来源、非目标不变 |
| 局部 Fork | 确有结构不足时在页面内探索 | 来源版本、未验证状态，不自动污染公共实现 |
| 公共组件任务 | 在 System Mode 中修改 Card 内部和接口 | 有授权、有迁移、有测试与设计 Gate |

保留共享组件不是冻结所有设计。Card 的公共替换是一次系统任务；之后生成一页课程时，默认使用局部改造，不每页重新改公共 Card。

## 8. 治理与权限

本包是提案，不自动解除当前阶段限制。执行时，已明确授权的本地批次按新范围记录；保留冻结历史、既有 Gate 和颜色欠项。普通范围内不反复索取同一确认，新增依赖大升级／全局品牌变化／无法兼容的破坏性 API 再报告具体差异。

可扩展的是登记和执行入口，不是关闭有效检查。历史快照检查与当前资产通用检查应逐步分开，先做首批所需最小增量，不趁机重写全仓治理。[R01][R03]

不自动授权：远端 push／PR／merge、生产迁移、公开仓库、包或 Registry 发布、Figma 写入、字体分发、将技术 PASS 当作人工确认。

## 9. 真实消费与文档

先建立 `apps/prototype` 或实际现有等价入口，只引用必要的源码与样式。不复制 Playground 的整套页面 CSS、图库预览和历史证据作为应用依赖。

再进行一次干净目录 Starter 消费：验证源码/包入口、workspace 替代方式、依赖、Tailwind 扫描、主题、密度与字体回退。UI 包的 `tsc --noEmit` 不证明可发布的编译产物已生成。[R13][E06]

第一阶段文档只需可检索、明确用法、来源、修改规则、当前状态；无需低代码编辑平台或单独 MCP 服务。

前提：现有工程能运行，有 React 集成及复核能力，使用 Mock 数据，设计判断可以集中完成。不是工时保证。Card 一旦达到首批合同，就进入页面；不追加无限视觉方案。

超出窗口时依次延期：低频变体、非必要动效、低优先级品类、在线分发平台、全量 Figma。不可延期掉核心语义、状态连接、必要的焦点保护、来源和不破坏已有资产的验证。

## 11. 并行与回流

视觉来源核对、上游调查、局部组件、测试场景可并行；锁文件、Token 事实源、生成器、公共出口和全局样式由一个集成负责人统一处理。

局部试验反复证明有价值后，按现有机制升级为公共 Pattern／Block；不因生成过一次就进入系统目录，不为了全部“自己建设”而重写已经适用的上游实现。
