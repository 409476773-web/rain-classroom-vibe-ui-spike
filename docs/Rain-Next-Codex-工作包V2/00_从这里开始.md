# Rain Next｜Codex 工作包 V2

**版本：2026-09-12／计划提案。主题：Card 优先替换＋受控组件补齐。**

当前交付只完成了只读审阅、计划编写和独立 CSS 机制实验。没有修改项目源码、安装项目依赖、执行项目测试、推送 Git 或写入 Figma。本文件不是现有组件已迁移的证明。

执行跟踪（2026-09-14）：上文及台账原状态字段保留 2026-09-12 提案快照。RN-07 已有后续实施，见台账 `executionUpdate` 与 [当前阶段](../../status/current-phase.yaml) 的 `componentRefinements.textareaRn07`；[实施记录](../plans/2026-09-13-textarea-rn07.md)及[验证记录](../../evidence/runtime/textarea/verification.md)区分功能完成、独立审阅和限定视觉验收。执行状态不从本规划快照反推。

## 1. 这版最重要的决定

保留新 React 底座与成熟资产，但不按“文件已经存在”一律保留实现。Card 调整为 `adapt-shadcn` 的优先替换候选：以已核对的上游结构与样式规则为参考，适配 Rain 品牌、接口与可修改边界，替换现有公共实现，而不是长期新建第二套 Card。

Card 与 Dialog 分别承担两个接入验证：

- **M0-C：静态组件与设计改造。** 解决 Card 的间距、部件、样式优先级、媒体布局、旧用法和局部隔离。
- **M0-O：复杂交互与状态协作。** 新 Dialog 组合现有 Button／Input／Select，验证 Portal、主题、密度、焦点和任务草稿。

二者之后进入公共 Layout 和 BM-A／BM-B；不要为了“所有卡片都设计完”推迟整页验证。

## 2. 给设计师的阅读入口

先读 [增量审阅](01_增量审阅与资产处置V2.md) 与 [整体实施计划](02_整体实施计划V2.md)。评审 Card 时只需聚焦默认疏密、标题与操作关系、Footer 处理、图片与长内容，以及改造是否局部生效。

本包中的 20／16px 等试作候选不是已经确认的视觉标准。实施代理可在获得实施授权后制作候选，再集中进行视觉验收，不应把每个常规实现细节都抛回给设计师。

## 3. 给 Codex 的最短入口

使用 [首批任务书](04_Codex首批任务书V2.md)，再按需读取 [Card 合同](03_Card替换决策与目标合同V2.md) 与 [验收矩阵](05_验收矩阵与回滚V2.md)。不要每轮读取全部历史证据和 64 项资料。

建议交给 Codex 的启动语：

> 以这份 V2 工作包为新的计划提案，先执行任务书 A 的只读预检。确认实际 HEAD、工作区修改、现有 Card 消费者与治理约束，列出拟改文件、源码来源、接入差异及需要运行的验证。不要重做完整架构审计，不要覆盖工作区，不要自行执行 Git 远程操作、Figma 写入、发布或人工验收。若本地已存在比参考 Commit 更新的 Card 实现，先比较差异，不能回退到旧版本。

用户随后明确“按 V2 实施 Card 批次”时，执行任务书 B 的限定本地实施范围；该指令不自动授权其他 64 项组件、依赖大升级、远程 Git、发布或 Figma 操作。

## 5. V1 到 V2 的变更

| V1 的安排 | V2 的安排 |
| --- | --- |
| 已有组件默认保留，Card 暂按现有资产使用 | 保留有价值成果，但 Card 优先采用成熟基线替换 |
| 首批只有 Dialog＋Separator | 加入 Card 设计改造样本；Dialog 的交互验证仍必做 |
| 泛化的样式映射 | 明确旧 CSS 层级、slot 名称、上游模板与样式、嵌套隔离和变量作用域 |
| Card 没有专属迁移任务 | 新增 RN-C1～RN-C4，原 RN-00～RN-16 编号保留并更新依赖 |
| 64 品类 Card 行为“保留” | 改为“已有薄弱实现→adapt-shadcn 替换候选”，不宣称已经替换 |

V2 取代上一份“受控补齐实施计划 V1”和“Codex 首批任务说明 V1”中同范围的计划建议。**不覆盖仓库现行规则，不修改历史验收，不将新决定回填成旧阶段已完成。** 旧审阅的固定 Commit 事实仍可参考；执行状态以实际仓库与当次授权为准。
