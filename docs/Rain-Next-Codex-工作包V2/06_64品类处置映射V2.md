# shadcn 64 品类处置映射 V2

**核对日期：2026-09-12。** 官方目录快照为 64 项；本表不是不可变化的永久清单。[E01]

现有对应关系沿用固定 Rain Commit 的公共导出审阅，本轮重点重新核对 Card；不声称重新逐个跑了 64 项功能测试。`Typography` 的内容排版／Typeset 路径仍作为同一个目录对应，不重复增加计数。

V2 的关键变化：**Card 从“已有→保留”改为“已有薄弱实现→优先 adapt-shadcn 替换候选”。** 其余资产只有在发现具体不足后调整，不能因 Card 替换而全部换源。

所有处置状态为 proposed，实际入库、测试、视觉 Gate、发布和业务采用分别登记。公共出口未见不等于仓库完全不存在实验代码，也不等于底层依赖不提供相近能力。

## 目录之外仍需建设

公共 Layout（Stack／Inline／Grid／Split）、层级与路径、多视图集合、按业务需要的虚拟化／拖放、Patterns／Blocks／Templates、Starter、检索与来源闭合，不能通过“64个组件文件都有”推导为已完成。

首阶段优先 Layout 与 BM-A/B。Tree、TreeSelect、TreeTable、Cascader 等沿用能力分解原则按真实需求建设，不把 Tree 画面变成全部层级组件的祖先。

## 分发特别提醒

现有本地 Registry 不是标准 shadcn Registry。采用上游依赖时，核对资产命名与依赖目标；不要让 `button` 重新安装出第二套默认 Button。出处、CLI、组件内容和软件包依赖分别锁定。[R12][E07]
