## 1. 依据优先级

当前用户明确需求（继续审阅与重写文档、Card采用上游的方向）→原项目计划与当前仓库实际合同→固定版本实现与证据→官方上游资料→本包明确标注的提案。

本包采用原计划“原型优先、品牌约束、灵活布局与组件改造、可体验Playground、设计和代码协作”的目标。源笔记本身不证明新库任何资产已经完成。[P01]

## 2. 版本与访问

Rain main 本轮仍为 `321e1a0c1b5f9284e0fcb5167fa059d6174b1752`。上游 main 读取为 `3ba91b1cc83e1bbe4ab35a422ff2a694849c5048`，仅作为本次Card来源审阅基线，不追随main自动升级。

GitHub代码搜索返回 `total_count=0, incomplete_results=true`；不用于证明没有更多消费者。Core UI本轮读取确认两处用法，完整计数留给本地检索。

尝试读取上游 `apps/v4/styles/base-nova/ui/card.tsx` 返回404；本包不把该路径当作已取得产物。官方base-nova安装JSON本轮没有取得可用完整内容。当前计划明确使用已经读到的作者Card和Nova样式段进行来源审阅，不把较旧new-york-v4安装产物冒充同一基线。

作者模板中 `cn-card` 等不是Rain可直接运行的最终样式。该源与样式要一起转译；最终安装内容或本地转换内容的摘要由实施批次记录。

## 4. 摘要的含义

源码返回的 Git blob SHA 是Git对象标识，不是文件原始内容的SHA-256。上游Card与Nova样式的blob分别为 `2062884f29a8044fa48edf86605182eca29f8716`、`514a3e8e00deac2ef59fee04c57cb10fd277ef39`。

不从代码片段重新计算一个摘要并冒称完整源文件指纹。计划台账中 `installArtifactLocked=false` 是事实：本包不是一个已经安装、锁定并测试完成的组件发行版。

工作包另带文档自身SHA-256校验清单，仅验证交付文件完整性，不证明仓库运行通过。

## 5. 本轮实测与未测

实测：两个容器Chromium 144.0.7559.96的独立HTML/CSS机制实验，见证据目录。没有加载任何项目包，也没有运行真实Tailwind编译。

未测：Rain工程构建、项目单元和浏览器测试、完整CSS产物、独立消费、真实字体/触屏/读屏、多框架或性能对比、Figma当前节点。

仓库中的既有通过数量和视觉接受只属于各自原记录，本包不复制为新的通过报告。

## 6. 证据用途

独立级联实验解释为什么不能只在旧Card上追加工具类；独立选择器实验解释为什么要检查嵌套部件归属。两者都不能直接推出“现有所有Card已经坏了”或“采用shadcn一定成功”。实际修复效果需实施批次复核。
