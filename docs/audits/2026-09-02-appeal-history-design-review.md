# 申诉历史单屏设计评审

- 结论：信息结构方向成立，但当前存在会损害用户信任的结果矛盾，修正前不建议进入最终交付
- 边界：这是静态截图评审，未验证滚动、展开、关闭、键盘操作、真实颜色值或响应式表现

## 视觉证据

2026-09-12 送审整理：原始参考图含姓名/昵称、头像、成绩与申诉内容，来源未说明是否为虚构示例，因此仅本地留存，不纳入审核仓库。本次不改变下方原始评审结论；旧基线中的原图路径与哈希继续保留为历史记录。

## 任务步骤与健康度

1. **进入申诉历史并确认记录数量 — 基本健康。** 标题、总数和关闭入口清楚，但真实可点击范围无法从截图确认。
2. **快速浏览每轮申诉的状态和分数 — 需要优先修正。** 轮次、状态和分数变化入口清楚，但第二次申诉的标题、详情分数和处理文案互相矛盾；第三次申诉仍在处理中，却已经展示类似最终结果的分数箭头。
3. **阅读单轮的参与者、理由和处理意见 — 基本健康但过长。** 人物、动作、时间和内容分组容易理解；重复的原始批改内容、过重的外框和没有明确展开入口的省略文字增加阅读负担。
4. **浏览多轮旧记录并退出 — 待验证。** 设计稿已有 5 次记录，但截图只展示 3 次且整体很长；需要验证旧记录收起、内容区滚动、标题和关闭入口固定、键盘退出及窄屏表现。

## 做得好的地方

- 最新一轮在前，符合用户查看当前进度的目的。
- 每轮都有“轮次、状态、分数变化”的摘要，用户不必先读长文。
- 助教、学生、老师的头像、名称、动作和时间形成了可追溯的处理链。
- 冷色批改区与暖色申诉理由区能快速区分信息来源，而且不只依赖颜色，还有文字标签。
- 分数区域和长评语区域分开，正文行距与内容宽度整体可读。

## 最高优先级问题

### 1. 同一轮结果互相矛盾

第二次申诉同时出现：

- 标题摘要 `5.5 → 6.0`；
- 详情分数 `申诉后 6.5`；
- 老师动作 `改判分数`；
- 处理意见却写着 `维持原有分数不变`。

这是信任问题，不只是文案问题。每轮申诉应只有一份最终结果数据，标题摘要、状态标签、详情分数和处理意见都从同一结果生成，不能分别填写。

### 2. “处理中”与最终分数表达冲突

第三次申诉标记为 `申诉中`，但右侧已经展示 `5.5 → 6.0`，很像最终改分。建议二选一：

- 尚无结果：显示 `原分 5.5 · 处理中` 或 `5.5 → 待处理`；
- 已有临时结果：明确写 `当前暂定 6.0 · 复核中`，不要伪装成最终结果。

### 3. 五轮历史会变成过长的弹窗

三轮已经形成很长的页面，五轮全部展开会让用户难以回看。建议最新或进行中的一轮默认展开，历史轮次默认收起，只保留：轮次、结果、分数变化、完成时间。用户需要时再展开完整过程。

## 次优先级问题

- 同一份原始批改在每轮中重复出现。可以在第一轮保留全文，后续轮次用“查看本轮基准批改”展开，减少重复。
- 申诉理由被省略号截断，却没有可见的“展开全文”。历史记录需要可追溯，省略必须配明确操作。
- 蓝色标题和粗外框在每一轮都很强，导致当前轮次与历史轮次视觉重量相同。建议当前轮次保留强调，历史轮次改成更轻的中性色摘要卡。
- 时间、浅蓝标签和部分辅助文字偏淡，存在对比度风险；需要用真实颜色值检查，不能只凭截图判断合格。
- 时间线同时使用圆点、头像和竖线，提示有些重复。可保留头像作为节点，让竖线负责串联，减少一个装饰层。
- 右上角关闭图标需要足够大的点击范围和清楚的键盘选中反馈；截图无法验证。

## 建议的标题摘要规则

- 进行中：`第三次申诉 · 申诉中｜原分 5.5｜等待处理`
- 已改分：`第二次申诉 · 已完成｜5.5 → 6.0｜分数变化`
- 未改分：`第一次申诉 · 已完成｜5.5｜维持原判`
- 只改评语：`已完成｜分数不变｜评语已更新`

状态标签必须由真实结果生成，避免“分数变化”“改写评语”“维持原判”同时出现互相冲突的组合。

## 下一版建议优先顺序

1. 先统一每轮申诉的状态、分数和处理结论。
2. 再把“进行中”和“已完成”的摘要规则分开。
3. 然后收起历史轮次，并为长文本增加“展开全文”。
4. 最后再减轻蓝色外框、精简时间线标记并校验辅助文字对比度。
