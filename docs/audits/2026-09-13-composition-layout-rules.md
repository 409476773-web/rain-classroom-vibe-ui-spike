# 从 Dialog 精修提炼的组合排版规则

日期：2026-09-13。用户明确要求先精修当前 Dialog，并以它为起点梳理后续组件可沿用的组合排版规则。本稿服务这一轮 System Mode 实施；课程编辑示例仍为 `local-experiment`，公共 Dialog / Separator 仍为候选。

本文区分三层结论：**跨组件的职责原则**、**本轮 Dialog 的数值候选**、**后续场景需要验证的推广建议**。数值表已完成本轮浏览器测量，人工视觉确认仍另记；它不是全库已验收的布局规范，也不新增公共 Token、组件或配置框架。

同日后续讨论中，用户已确认第 2.1 节的全库间距层级关系，并授权继续实施。当前布局包已有最小关系校验，RN-06局部样例已协调数值；本稿第5、8节保留前一轮Dialog的数值和验证范围，不扩写为全库符合新关系。决定来源与实施范围见[三级间距设计记录](../plans/2026-09-13-spacing-hierarchy-design.md)。

## 1. 来源与本轮判断

现有基础见 [Space 合同](../../packages/foundations/src/composition-contract.ts)、[Size / Density 职责](../adr/0003-size-and-density-responsibilities.md)、[Typography 合同](../../packages/foundations/src/typography-contract.ts)、[RN-05 实施与边界](../plans/2026-09-13-dialog-v2-implementation.md)。VE-014 提供固定头尾、表单分组和任务表面的 Rain 来源；其 916×1224 外框和复杂业务内容不直接成为本轮目标，见[视觉来源审计](2026-09-01-visual-asset-audit.md#ve-014--新建教材弹窗)。

本轮沿用上轮调研方向，2026-09-13 再次核对 shadcn 官方文档：

| 来源事实 | 吸收的组合经验 | Rain 的采用边界 |
| --- | --- | --- |
| [Dialog](https://ui.shadcn.com/docs/components/base/dialog) 明确标题、说明、操作区结构，另有固定操作区和长内容滚动示例 | 按任务区域分配职责，先规定哪个区域滚动 | 沿用已有 Rain Parts 与 Base UI 行为，不复制官网主题 |
| [Field](https://ui.shadcn.com/docs/components/base/field) 区分单字段、相关字段组和带标题的语义分组 | 字段内部与组间排列各有归属；校验信息跟随字段 | 当前单字段复用 Rain FormItem；Group / Section 是组合职责，不据此新增公共 API |
| [Card / Spacing](https://ui.shadcn.com/docs/components/base/card#spacing) 用同一间距变量协调区块间距和部件缩进 | 容器整体安排边缘留白，避免各部件独立累加 | 借鉴协调方式；Rain Card 已接受的 default 20 / sm 12 不由本轮重设 |
| [Separator](https://ui.shadcn.com/docs/components/base/separator) 分别展示横线、竖线、菜单与列表用途；Field 文档建议克制使用分隔 | 分隔线须对应内容关系，并与所属区域共同设计 | 保留 Rain 线条和颜色来源，按用途选择语义或装饰线 |

判断：成熟感来自稳定的关系——同一内容边线、可解释的疏密、清楚的分区和完整的操作区。采用同一组间距数字本身不能保证这些关系成立。上轮讨论中的官网示例像素值属于当时样本观察，本文不将其登记为 shadcn 全部风格的统一标准。

## 2. 跨组件原则：每段距离由一个层级管理

| 层级 | 管理什么 | 不承担什么 |
| --- | --- | --- |
| 单个控件 | 文字、图标、清除或加载部位的内部几何及交互区域 | 与下一个字段或区域的距离 |
| Field：当前为 FormItem | 标签、控件、帮助和校验信息的关系及语义关联 | 整个表单的字段间距 |
| Group：相关字段的父布局 | 字段之间的 gap、列宽、同排对齐和换行 | 再次给每个字段增加一层内部 padding |
| Section：一个内容主题 | 分区标题、说明、字段组及分区之间的关系 | 用一张 Card 代替所有语义分组 |
| 容器：Dialog / Card / 面板 | 外形、内容边线、头部 / 正文 / 操作区的衔接 | 改写内部 Input、Select、Button 的完整尺寸方案 |

两个相邻区域的总距离应有一个明确拥有者。布局可用父级 `gap`，也可由指定部件提供 padding；避免父 gap、上一区域底 padding、下一区域顶 padding 同时补同一段留白。检查实际边界距离，不只检查某个 CSS 值。

公共组件自身默认留白仍有效。当前 Dialog 精修在已授权的 Dialog Parts 内协调头部、正文、底栏；其他容器沿用各自合同，不通过页面样式穿透其内部。局部变化优先使用已有 Parts / Local Recipe；没有重复场景证据时保持局部。

### 2.1 已确认：自由选值的三级间距关系

用户确认：全库共享层级关系，页面、卡片、面板分别拥有适合自己的数值配方；具体数值自由选择，不固定差值或比例，允许任意两级或三级全部相等。

**边缘留白 ≥ 分区间距 ≥ 分区内信息间距。**

- 边缘留白：所属视觉容器内边缘到内容的距离。
- 分区间距：该容器内直接内容分区之间的距离。
- 分区内信息间距：同一分区内信息单元之间的距离。
- 比较限定在同一视觉容器的相关层级及同一方向。横向、纵向可分别配置；不拿页面左右留白直接约束另一个区域的纵向间距。
- 层级由内容关系决定；增加响应式包装或嵌套一个 Stack 不自动增加语义层级。不存在的层级不人为增加留白。
- 数值沿用现有 Rain Space。配方提供可调整的默认值，不把一组数字写成全库唯一值；`24/20/12`、`20/20/12`、`16/16/16` 都符合关系，`16/24/8` 不符合。
- 调整数值、切换响应式布局后，同方向的关系仍须成立。全部相等是合法选择，不强制加入差值来制造层级。
- 检查最终的空间关系，包括父 gap、子模块留白和分隔线两侧留白的累计影响；线条自身厚度单独记录，不与空白混为一项。仍遵守每段距离由一个层级管理。

Stack / Inline / Grid / Split 共享该关系规则，由宿主根据容器、分区、信息组的实际角色选值。续步已增加 `defineLayoutSpacing({ inset, section, item })`，仅校验调用方声明的已有Space值及顺序，非法值抛出错误；不自动设置padding、识别DOM层级、静默纠正或改变四原语默认值。横向/纵向可分别调用，控件内部完整方案继续由控件拥有。

当前页面纵向32/24/16、Card内容20/16/12、Pane16/12/8是[局部可调整配方](2026-09-13-layouts-usage.md#三级间距使用)，不构成固定数值规范。容器与父布局仍须显式消费各自值，并检查最终累计距离；函数返回合法三元组，不等于任意调用页面已经满足几何关系。本轮已清除资料列表中重复留白，按新组合做了[实际测量](../../evidence/runtime/spacing-hierarchy/verification.md)。

## 3. 对齐、层级与中文内容

- **先建立内容边线。** 同一区域的标题、说明、字段根节点和分区标题共享起点；字段控件填充所属列。末端操作组与这条内容区域的右边线对齐。线条端点按内容边界或容器边界选择，不能无理由多出第三条缩进线。
- **按关系分出疏密。** 标签与其控件形成紧密单元；相关字段之间留出阅读停顿；内容主题改变时才使用更明显的分区。相邻关系相同，间距保持一致；不能为了总高度整齐而把帮助文字挤进控件或隐藏。
- **先用层级和留白，再决定是否画线。** 两个简单字段不需要单独的分区标题和分隔线。长内容中的“基本信息”“教学安排”等确有主题变化时，使用分区标题；只有留白不足以表达边界时补线。
- **中文左对齐、自然换行。** 继续使用 Rain UI 字体链和明确的标题 / 正文字体角色；不使用手工空格、强制断行或两端对齐来凑标签宽度。说明、帮助、错误支持多行；窄屏和长中英文混排另测。
- **不把文字框等同于字形边界。** 当前 Dialog 标题沿用 18/28/600，说明沿用 14/24；FormItem 保留自身完整排版。比较间距时记录布局盒，比较视觉时同时看中文字形和基线，不为追求盒子等高修改字号或行高。
- **关闭按钮是独立操作。** 它与标题区组成一排，保留既有点击区域和 Focus；标题可换行，按钮不可被长标题挤窄。视觉居中不通过裁切命中区域实现。

## 4. Separator：分隔用途决定形态与留白

| 用途 | 线的位置 | 间距归属 |
| --- | --- | --- |
| 正文内不同内容主题 | 线端点与正文内容边线一致 | Section 组合拥有线两侧留白；Separator 自身不附带通用外边距 |
| 固定操作区与滚动正文 | 操作区上缘，可沿容器内侧通宽 | Body 管理内容末尾距离，Footer 管理按钮到边界的距离；边界已有线时不再叠加 Separator |
| 同一横排中的不同动作组 | 竖线与横排的视觉中心对齐 | 父级排列管理两侧 gap 和可用高度，线不凭空撑高整排 |

语义分隔使用既有 Separator 的可访问性语义；仅作表面装饰的分界使用 `decorative` 或容器边框。线条没有点击行为、没有 Tab 停点。不要在每个字段之间加线，不用更多边框掩盖分组关系不清。

## 5. 当前 Dialog 的数值候选

以下只针对当前编辑课程 Dialog 及其长内容对照。除宽度属于现有显式几何能力外，所有间距均使用已有 Rain Space 值；本轮不新增基础刻度。实际生效数值以第 8 节的浏览器记录为准。

| 关系 | 本轮目标 | 归属与测量口径 |
| --- | --- | --- |
| 短编辑 / 长内容外框 | 480 / 560px | 当前示例显式选择宽度；保持视口约束，不据此扩充公共尺寸枚举 |
| 标题、正文、操作的左右缩进 | 24px | Dialog 各 Part 协调；从外框内边缘到内容盒测量，实体边框另计 |
| 标题到说明 | 8px | Header 内部；说明缺省时不保留空占位 |
| 标题说明组到首个字段 | 24px | Header 到 Body 衔接的一处留白；以组末端到字段根节点起点测量 |
| 相关字段之间 | 20px | 示例字段组 gap；从完整 FormItem 末端到下一项起点测量，包含项内帮助 / 错误后的实际高度 |
| 字段组到说明分区线 | 24px | Body 的区块 gap；从完整字段组末端到线起点测量 |
| 分区线到小标题 | 16px | 说明 Section 内部 gap；从线末端到标题盒测量 |
| 小标题到说明正文 | 4px | 同一说明单元内部 gap；段落 margin 归零 |
| Field 内部 | 保留现有方案 | 当前 FormItem 使用 4px gap；本轮不迁移为 shadcn 示例的内部间距 |
| Body 最后一项到操作区分界 | 24px | Body 底部 padding；测量最后可见内容盒末端到分界，避免正文自带末端 margin 叠加 |
| 操作区内距 | 上下 16px、左右 24px | Footer；有多行状态或按钮换行时允许自然增高 |
| 同排按钮间距 | 8px | Footer 动作组；取消在前、主操作在后，均显式使用现有 small / 32px 方案 |
| 关闭按钮 | 28 / 16px | 沿用既有 IconButton 方案，完整命中区 28px；与当前 28px 标题行中心对齐 |
| 操作区表面 | 轻中性背景 + 轻顶线 | 只消费既有 Rain Category 与 Line；实际主题色、合成和对比度单独实测 |

短表单不为增加“模块感”嵌套 Card，也不强留长内容的滚动高度。正文短时按内容自然收缩；内容变长时保持 Header / Footer 可见，仅 Body 滚动。选择长内容宽度是本示例的设计选择，不是“字数超过阈值就自动扩宽”的通用逻辑。

## 6. 操作、滚动与密度

操作区用主次按钮表达任务优先级；状态说明位于同一操作区域并支持换行；取消与保存由宿主组成一个动作组，窄屏空间不足时整组下移，避免拆成上下两行。不把错误塞进按钮标签。保存中、失败、重试、取消仍由宿主事务管理；视觉精修不能改变草稿保留、防重复提交和焦点返回。

Dialog 内容限制在视口内，Body 是本轮唯一正文滚动所有者。不要再给整张表单设第二个独立滚动层；输入框和 Select 的键盘焦点应可见，子浮层仍位于所属 Dialog 之上。窄屏保持单列并允许操作区增长；中文说明和错误增加高度时不能覆盖按钮。

按 ADR 0003：Density 选择区域默认，显式 Size 优先；Size 选择完整控件方案。本轮先保持 24 / 20 / 16 / 8 的组合距离在 default / compact 中一致，分别验证现有控件的密度变化。不能把全部 gap、字号和命中区一起按比例缩小，也不能因为两种控件都叫 `small` 就假设等高。

后续在查询条、工具栏等横向组合中，可由宿主明确选取已有尺寸再决定居中、基线对齐或换行。需要观察完整控件框和文字基线；不要只修改高度使它们看似一致。这是后续组合建议，未声称本轮已经验证所有控件组合。

## 7. 后续怎么沿用

后续组件先沿用第 2～4 节的职责和检查方式，再从各自已有合同选择数值。Dialog 的 24px 缩进、20px 字段间距、轻底色操作区不直接成为 Card、列表、工具栏或页面的全局默认。

| 后续样本 | 优先验证的关系 | 本轮资格 |
| --- | --- | --- |
| 设置卡片 | Card 既有缩进与字段组衔接，说明 / 错误增高后的节奏 | RN-06 已实现局部样例，保留 Card 已有 20 / 12 决定；不等于该组合已完成人工视觉接受 |
| 长表单分区 | 分区标题、单双列、帮助与错误，固定操作区的滚动关系 | 当前长 Dialog 只验证局部样本；完整 BM-B 未通过 |
| 查询条与结果区 | 不同显式控件尺寸的同排关系、动作分组、换行后距离 | RN-06 已有本地查询 / 动作组样例及生产浏览器验证；完整 BM-A 未通过 |
| RN-06 公共 Layout | 父布局管理 gap / 对齐 / 分区，UI 保留内部几何 | Stack / Inline / Grid / Split 候选已实现；限定独立技术复核通过，Human Gate 保持待确认 |

RN-06 已将上述职责接入唯一的 `@rain-next/layouts` 包：Stack 管垂直间距，Inline 管横排与换行，Grid 管有限列数及显式最小列宽下的自适应，Split 管两个按 DOM 顺序的区域、受控收起与显式滚动。布局默认 gap 为 0，消费原有 Space；不增加表面、文字、控件尺寸或密度规则。具体入口与限制见[最小布局用法](2026-09-13-layouts-usage.md)。

本轮组合发现：同一 Grid 内的 FormItem 若帮助文字高度不同，宿主应设置 `className="items-start"`，使各字段按自己的内容高度排列，避免默认拉伸使短字段内部留白变大。Grid 原语保留默认 stretch，继续支持等高 Card 等用途；这一表单修正不转为全局 Grid 默认。

RN-06初版生产回归为[22项](../../evidence/runtime/layouts-v1/logs/production.log)。本轮三级间距调整后为[24项](../../evidence/runtime/spacing-hierarchy/logs/production.log)（Layout 9 + Dialog 9 + Card 6），详细几何与独立复核见[专项验证](../../evidence/runtime/spacing-hierarchy/verification.md)；这是所列局部样本的运行证据，不能替代完整 Benchmark或人工视觉接受。建设范围见[RN-06实施计划](../plans/2026-09-13-layouts-v1-implementation.md)。

有重复的实际需求后再考虑提炼共享 Recipe。三个独立场景仅构成按 [B2 合同](../../AGENTS.md#101-tailwind-b2组合速度与局部隔离)主动提示晋升的资格，仍需逐项评审；它不是自动创建新 Foundation、Variant 或公共组件的条件。

## 8. 证据与接受边界

本轮生产浏览器回归 **15 项通过（Dialog 9 + Card 6）**，覆盖短 / 长内容 × Light / Dark × default / compact，短弹窗有效距离与共线断言全部通过。1280×800 与 375×667 视口、独立正文滚动、内嵌 Select、焦点返回、校验及保存流程的详细范围见[本轮验证记录](../../evidence/runtime/dialog-visual-2026-09-13/verification.md)。本机 Chromium 的四组标题实际字体均为 PingFang SC Semibold。独立复核的补充样本单独归档，不扩写成全库覆盖。

后续复用时继续记录实际几何与截图，以及帮助 / 错误增高、窄屏换行和保存状态。字体证据区分 CSS 字体链与浏览器实际字体，颜色使用真实父表面合成。本轮 Footer 共享深色 Focus 在新表面上为 2.739:1，仍低于 3:1；正文表面保持 2.573:1。这些结果未被本轮精修关闭。

检查通过仅证明本轮记录的运行范围。人工视觉接受、必要文字与 Focus 对比度、真实辅助技术、完整 Benchmark、公共资产晋升、发布与业务迁移分别保持独立。本轮精修不自动关闭原有深色共享 Focus finding，也不替代用户对最终布局的视觉判断。
