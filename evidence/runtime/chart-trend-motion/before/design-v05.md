## 2. 配色与样式：先形成八种有来源的候选配方

下列 HEX 为本次从 Figma 数据图层读取的 RGB 转为8位色值。百分数若附在色值后表示不透明度；渐变“起／止”指色标，不保证恰好落在图形边缘。渐变还受方向、作用范围、图层及父层透明度影响。源稿值不等于已批准的公共 Token。

| 配方 | 源稿实测与样式规律 | 适用与允许变化 |
| --- | --- | --- |
| **P01 同色深浅渐变** | CH-007：紫 `#675FFF → #A77DFF`，青 `#01ADC3 → #22CADF`；两端均100%，视觉上由上至下变浅，柱宽10、方角。CH-003另有蓝 `#236EFF → #4DBFFF`、粉 `#FF6CC4 → #FF9CE3`、珊瑚 `#FF6960 → #FF8B84`、浅蓝 `#79CFFF → #A1DEFF`、浅紫 `#B58EFF → #D0B7FF`、橙 `#F57E58 → #FFA96B` | 堆叠、构成扇区等；类别由主色识别，深浅变化提供材质。允许选择配色家族、方向、强度；扇区原变换各不相同，不能笼统称为沿圆周渐变 |
| **P02 圆头渐隐分组柱** | CH-114六个数据基色：`#5074FF / #509CFF / #30B3FF / #DC7BFF / #B547FF / #895AFF`，每色100%→0%，向下淡出；柱宽约8，源顶部圆角6、底部0 | 多版本比较、系列较多的细柱；圆角需随柱宽合理限制。允许调整色组和淡出范围；柱顶与基线仍需可辨。渐隐与不透明堆叠分别保留 |
| **P03 清晰线＋轻面积** | CH-125：`#3D7BFF`线为70%／2px，同蓝面积20%→0，图形约96×40。CH-049：青色2px线，面积 `#29CBDF → #87EDFB` 的有效色标透明度约50%→0。CH-128：面积 `#6055FF → #6CA7FF` 约30%→0；1.5px线 `#6872FB → #8583FF`；柱为不透明 `#8A7CFC → #86B0FF` | 迷你趋势、周期对照、组合图；20／30／50是源稿样本，尚不是全库固定档位。允许实线／平滑、面积强弱、端点、轴开关；不能把整张图统一降透明度 |
| **P04 多类别实色＋柔和边缘** | CH-146矩形树：`#4661FE / #658CFF / #8848FF / #BFA5FF / #86DAEA / #37B5CE`，圆角8、无渐变。CH-133环段亦为纯色，另含 `#A171FF / #9BBEFF / #82E1C9 / #63D0AD`；源白描边40%，常规1px、高亮例3px，段角4／5 | 圆角色块、分段环、构成图。允许类别数量、分隔、图例布局、圆角；深浅不是等级。源稿白边只在当前浅色底成立，深色版本需另行设计 |
| **P05 蓝紫顺序色阶** | CH-090色条：0% `#F5F4FF`、15% `#DFE1FF`、30% `#C4C9FF`、50% `#A1A9FF`、70% `#7C7DFD`、85% `#5F55F7`、100% `#4A31D1`，均不透明；格子本身为实色。CH-091从中取五色表达1–5，气泡直径20／26／32／40／46，零为7px灰点 | 热力强度、相似度、气泡矩阵。允许连续或离散映射、明确的值域与分档；色条与图形应共用映射。气泡尺寸是源稿观察，实际方案需明确面积映射；缺测另设表达 |
| **P06 渐变仪表＋淡底轨** | CH-077弧线 `#9EB7FF → #4A6AF5`，线性渐变、14px；底轨 `#ECF1FF`、10px；端点白环＋`#5876F7`内点。主值为品牌蓝，标签浅底 | 评分／有界指标。允许弧长、轨道粗细、端点、读数布局；渐变本身不代表好坏。小仪表需缩配，不直接继承大图14px |
| **P07 焦点路径双色过渡** | CH-069：普通路径 `#103FB7`、9%；高亮路径 `#50D69A → #5FC6FF`、100%，示例线宽11 | 流向与两端关联。允许按两端类别色生成渐变、调整非焦点透明度；路径粗细若承担权重，必须与数据对应。外部选择时保持两端、路径、浮层的同一身份 |
| **P08 径向柔光节点＋语义线型** | CH-083：例如10%色标 `#B53FFF`／100% → 100%色标白色／80%；其他节点保留蓝紫青类别。实际为径向渐变，节点及祖先无模糊／阴影效果。边为紫 `#923FFF`实线、蓝 `#2554FE`与橙 `#F59A1A`虚线，1.5px、虚线4／4 | 稀疏关系网络、重点关系展示。允许节点色、中心范围、柔光强度、线型；密集网络优先清晰边界。白色边缘依赖背景，不能直接套深色主题 |

**关键区别：** 类别色回答“是谁”；顺序色回答“多少／多强”；等级色需要业务档位规则；正负变化色需要明确好坏方向。渐变也可以纯粹提供审美材质，不强求每一段颜色对应额外数据字段，但不能暗示不存在的数据关系。

配方最小记录应包含：名称、来源样本、适用图形、配色家族及稳定系列身份、色标与位置、透明度叠加、方向与作用范围、线／面／端部样式、选中与淡化、图例／提示配色、允许调整项。不先发明通用绘图语言，也不为每张图新建主题。

## 3. 统一什么，开放什么

| 层面 | 统一规则 | 可变化部分 |
| --- | --- | --- |
| 品牌与文字 | 现有 Rain 品牌锚点、UI／关键数值字体职责、文字层级与单位格式 | 标题／轴／说明的展示密度、关键数值大小，依容器与阅读任务选择 |
| 数据颜色 | 同一系列在图形、图例、浮层、关联明细中保持身份；筛选／排序后不换色 | 选择具名配色家族、系列数量与配对；首系列不固定等于品牌或成功 |
| 渐变与材质 | 每个配方明确线性／径向、色标、透明度、坐标范围和用途 | 实色、深浅渐变、透明淡出、路径双色、径向柔光均可保留 |
| 图形几何 | 面积／长度／角度随数据正确变化；零与缺测区分；相同量共用刻度 | 线宽、柱宽、圆角、点形、平滑方式、环宽和密度；变化不能制造额外量的误读 |
| 读图与状态 | 色标可追溯、单位和值可读，选中／悬停／焦点可辨；精确读数可达 | 图例位置、内嵌或外置列表、直接标签、浮层内容、重点高亮方式 |
| 组合与表面 | 使用 Rain 既有 UI／布局职责，图体可独立嵌入 | 无外框、报告模块、指标卡、图＋表、图＋解读；不把Card写死在图体里 |

当前 [AGENTS.md §9.9](../../AGENTS.md) 将蓝紫青渐变限定于智能语义；既有 [报告设计记录](2026-09-19-report-composition-design.md) 已记录用户指定的普通统计局部浅渐变。**本次用户进一步明确图表配色、渐变和样式的重要性，因此本补充提出清晰的图表范围：数据图形材质与 AI 身份标记分别定义，普通图表可以使用已选视觉配方，不能因此把普通按钮、导航和页面外壳都改为 AI 渐变。** 本轮记录这一范围建议，不改写共享规范或 Token。

现有颜色登记与图表角色分开核对。`#3D7BFF` 等已存在的值优先复用，但不把 Tag 的专用状态配方直接升为图表系列；也不因某个渐变色暂未登记，就静默替换成“最近的蓝”。精确映射和缺口留给 F08，不在讨论阶段新增全局色板。

## 4. 候选适配成本：以保留视觉配方为前提

以下保留选型前截至2026-10-07的官方能力核对与成本推断，**不是实际工时、实现结果或视觉验收**；最新方向见第7节。低＝主要用原生配置；中＝原生图型加自定义呈现／状态连接；高＝额外坐标、布局、绘制或交互逻辑。比较相同数据、容器和已选配方，不要求复制源稿的占位数字或偶然偏差。

CH-069若必须让连线严格对齐两侧等高列表的行中心、行距完全不随流量变化，四者均须按额外布局重新估算，可能升为高成本。原生Sankey不能直接证明这一能力。

CH-083的“径向”指节点内部的渐变材质，不是要求径向拓扑布局。自由力导布局与固定节点位置的成本不同；本轮没有将源稿的精确坐标设为强制要求。

影响成本判断的已核事实：

- **Ant Design Plots／G2：** Tiny、组合和Sankey有原生基础；样式提供数据驱动颜色、透明度、渐变及柱形圆角。主要工作是把原生入口整理为Rain配方；需要进一步使用G2自定义标记时应独立计入成本。[Tiny](https://ant-design-charts.antgroup.com/en/components/plots/tiny)、[G2样式](https://g2.antv.antgroup.com/en/manual/core/style)、[Sankey](https://ant-design-charts.antgroup.com/en/components/plots/sankey)
- **Nivo：** SVG的渐变定义／应用可分离；官方明确该机制不适用于Canvas，提示中的色块默认仍为实色。HeatMap支持圆形、可变大小、自定义cell。组合图的高成本是本次文档核对后的推断，不能理解为绝对无法实现。[渐变](https://nivo.rocks/guides/gradients/)、[HeatMap](https://nivo.rocks/heatmap/)、[Sankey类型](https://github.com/plouc/nivo/blob/master/packages/sankey/src/types.ts)
- **ECharts：** 系列样式、双轴、视觉映射已有入口；Rain定制集中在图例、提示、范围条与React状态连接。引擎和React包装层分别核对。[样式](https://echarts.apache.org/handbook/en/concepts/style/)、[轴](https://echarts.apache.org/handbook/en/concepts/axis/)、[视觉映射](https://echarts.apache.org/handbook/en/concepts/visual-map/)
- **Bklit：** Composed已支持柱／线／面积，Line／Area可使用左右轴，SeriesBar使用主轴；Brush已有入口。现有Heatmap的默认轴、数据和提示偏向日期贡献图，不能仅凭名称认定普通矩阵完成。[Composed](https://bklit.com/docs/components/composed-chart)、[Brush](https://bklit.com/docs/utility/brush)、[Heatmap](https://bklit.com/docs/components/heatmap-chart)、[Sankey](https://bklit.com/docs/components/sankey-chart)

网络图另有包与布局边界：G2本身提供[forceGraph](https://g2.antv.antgroup.com/en/manual/extra-topics/graph/force-graph/)，更丰富的[Ant Design Graphs](https://ant-design-charts.antgroup.com/en/components/graphs/overview)是独立包，不能把G6全部能力算作Plots自带。Nivo [Network](https://github.com/plouc/nivo/blob/master/packages/network/src/types.ts)提供自定义节点和边，但[默认布局](https://github.com/plouc/nivo/blob/master/packages/network/src/hooks.ts)会重算位置。ECharts [graph](https://github.com/apache/echarts-doc/blob/master/en/option/series/graph.md)提供显式位置、边弧度与箭头。Bklit[当前目录](https://bklit.com/docs/components)未见Network／Graph；这不是断言其底层生态无法实现。

差异主要在复杂组合、矩阵及精确关系布局，迷你图难以拉开差距。Ant Design Plots／G2与ECharts在这些样本中结构成本较均衡；Nivo的矩阵基础、Bklit的组合与视觉改造路径也提供了比较依据。用户随后确认 Plots／G2 主库方向与 Bklit 视觉参考；该选择不把官网默认外观当作 Rain 最终效果，也不表示适配成本已实测。

## 6. v0.2：建议起点与可调整范围

### 6.1 三组类别色与一组顺序色分别保留

- **蓝紫近邻（CH-114）：** 适合相关版本或同类对象的比较；系列多时须结合直接标签、位置或线型检查区分度，不能仅凭“六色”认定六个系列都易辨。
- **多色渐变（CH-003）：** 适合类别较多、需要更广色域的构成展示；同一类别使用一对稳定色标，变化强度提供材质。八色不自动构成八类信息的可访问性保证。
- **蓝紫青实色（CH-146）：** 适合矩形树、分段环和连续排列的色块；配色负责身份，面积与长度负责数量。可在需要更清楚色块边界时作为选择起点。
- **蓝紫顺序色（CH-090）：** 单独用于连续数量、强度或相似度，不与前三组类别色混用；离散业务等级另定阈值及名称。

这些名称是候选配色家族，不是三套完整主题。配色家族与材质可以组合，但已有跨图颜色身份优先；切换配方不应让同一类别无故换色。

### 6.2 按使用条件选择起点

| 场景 | 建议起点 | 保留的替代与限制 |
| --- | --- | --- |
| 指标卡、表格内迷你趋势 | P03，单一系列色、细线＋轻面积 | 信息密集时仅保留线；无轴时仍提供精确值或明细 |
| 多版本分组柱 | P02，蓝紫近邻＋圆头渐隐 | 大量系列或极短柱可用实色／缩短淡出段，避免基线和类别身份消失 |
| 堆叠与分段数量 | P01，不透明深浅渐变 | 紧密堆叠可用实色；保持分段边界与统一基线 |
| 构成环、矩形树 | P04，实色＋柔和边缘 | 构成环可选P01多色渐变；不同半径的玫瑰式形态需先明确额外编码含义 |
| 连续热力、数量气泡 | P05，顺序色＋精确数字 | 大小、颜色不必同时变化；实际映射与色条同源，缺测独立表达 |
| 评分与有界指标 | P06，渐变弧线＋淡轨道 | 紧凑场景减小线宽与端点；业务状态色不能由渐变色直接推导 |
| 流向与两端关联 | P07，弱背景＋焦点路径 | 需要全量同时比较时增加普通路径可读性；固定列表对齐单独验证 |
| 节点关系网络 | P08，径向柔光＋语义边 | 密集网络可减少柔光、改清晰节点边界；这是关系网络配方，不与Sankey混成一种换肤 |

“建议起点”用于减少重复选择，不强制绑定图型与唯一外观。是否采用仍取决于系列数量、容器、阅读任务与最终视觉讨论。

### 6.3 图形之外的样式关系

1. 图例沿用系列身份：可显示纯色代表点，也可显示渐变样本，必须预先定义代表色取法；不保留源稿中的偶然错色。
2. 趋势描边和面积分别定义，重点数据的清晰度优先；不能只设置一个总透明度控制全部图层。
3. 白边、白色柔光、浅底轨道作为浅色参考方案处理；深色场景后续独立校准，不直接反转颜色。
4. 装饰允许形成视觉气质。避免规定“所有图必须渐变”或“普通统计一律实色”；每种材质保留明确的适用条件与可调范围。
5. 用户已确认上述方向、第7节的具体映射，并授权本地验证。公共组件建设仍待后续明确范围与效果验收。

| 更新数据 | 曲线与面积连续过渡到新值，保留固定位置，不重播入场；真实零值、缺测断线和系列身份准确表达 |

视觉关系：采用清晰描边与轻渐变面积；提示框统一Rain字体、数值对齐与系列色标。边缘淡出先用于面积及辅助层，保留真实端点。局部亮线、弹簧随动、边缘淡出分别验证效果与适配成本。

状态处理建议，留给改造样本校准：固定位置绑定X数据身份，固定期间普通移动保持该位置，另点才切换；指针离开不隐藏仍由键盘焦点控制的反馈。该X缺测时保留位置并显示缺测，数据键被删除时解除固定。图例建议沿用组合样本至少保留一个可见系列。动画期间收到新操作以最新状态为准，中断旧过渡；Reduced Motion关闭长揭示、缩放及位置缓冲，保留最终读数与选择。

**改造顺序：** 先完成一个趋势／面积样本的读取位置与状态联动，再校准随动、入场与更新；局部亮线及遮罩单独对照。之后将合适规则扩展到柱与组合，矩阵和关系图另按信息任务设计反馈。组合图柱层仍保留第8节记录的静态修复。

**验收要点：** 鼠标连续移动顺滑；临时读取与固定选择清楚；点击、离开、图例操作、数据更新连续执行时状态保持一致。另检查快速来回移动、边缘位置、零与缺测、键盘、窄容器及Reduced Motion。它们属于后续验证要求，本轮未运行新检查。
