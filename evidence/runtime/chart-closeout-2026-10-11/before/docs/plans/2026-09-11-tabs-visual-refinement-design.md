## 1. 修订目标

三种外观共用稳定的排列边界。长名称、图标、数量、Hover 背景、选中背景和指示线都受到统一尺寸约束；用户可以辨认当前分区、键盘焦点和完整名称。

本轮需要解决的实际问题包括：纵向项目撑破列宽；选中指示线与焦点框被裁切；省略号落在可见区域之外；底板外围留白不一致；浅底选中态与二级按钮过于相似。线条两端圆角按用户最初的明确要求修正。

## 2. 已确认的排列规则

| 项目 | 确认规则 |
|---|---|
| 纵向宽度 | 同组全部项目服从统一列宽，名称不能将点击区域或背景撑宽。 |
| 纵向高度 | 场景明确选择单行或双行方案；同组始终同高，短名称在对应高度内垂直居中。 |
| 双行名称 | 最多两行，超出后省略，并保留可发现的全文入口。 |
| 纵向对齐 | 长短差异明显或使用双行时，左右两侧都左对齐；全是短名称且长度接近时，可整组居中。 |
| 图标列 | 左对齐的纵向组混用图标时，统一预留图标列；无图标项目保留空位。全组没有图标时不留该列。 |
| 数量 | 紧随名称区域，保持单行；没有数量时释放该空间，不统一预留末端数量列。 |
| 垂直关系 | 图标和数量相对整个名称块垂直居中。双行时，数量位于名称块右侧，不参与名称换行。 |
| 横向宽度 | 默认自然宽度；少量固定分区可以明确选择等分可用宽度。两种方式适用于三种外观。 |
| 横向内容 | 图标、名称、数量的组合在各自 Tab 内居中；名称保持单行，超长省略并提供全文入口。 |
| 方式选择 | 单行／双行、自然宽度／等分由场景明确选择；名称和数量变化不会自行切换这些排列方式。 |
| 窄屏 | 空间不足时，左右纵向导航切换为内容上方的横向导航；保留当前分区和已有内容状态。 |

数量仍使用轻量文字。0 与未知数量保持区分；已有数量格式和完整可访问描述继续适用。图标、名称、数量的既定顺序不因导航位于右侧而倒置。

## 3. 首轮尺寸候选

### 3.1 纵向宽度

- 统一列宽：192px。
- 内容左右留白：各 16px，从整个 Tab 的边界计算，包含背景内缩部分，不再额外累加。
- 三种外观、三档尺寸使用同一列宽；场景调整列宽时，整组一起调整。
- 图标与名称、名称区域与数量之间沿用现有 2px 间距。

以 38 档、16px 图标和约 27px 宽的 (128) 为例，名称宽度约为 192 − 32 − 16 − 4 − 27 = 113px，每行约可容纳 7 个 15px 汉字。这是尺寸预算估算；英文、混排、长数量和选中字重需在实际预览中核对。

### 3.2 单行与双行完整尺寸

| 对应尺寸档位 | 名称字号／行高 | 图标 | 单行整体高度 | 双行整体高度 | 名称行盒距整个 Tab 上下各留白 |
|---|---:|---:|---:|---:|---:|
| 28 档 | 13／18px | 14px | 28px | 46px | 5px |
| 32 档 | 14／20px | 14px | 32px | 52px | 6px |
| 38 档 | 15／22px | 16px | 38px | 60px | 8px |

双行整体高度 = 单行整体高度 + 一行行高。保留现有字号、行高及文字行盒到整个 Tab 边缘的上下留白。

28／32／38 在双行方案中表示对应的原尺寸档位，实际高度分别为 46／52／60px。不能将双行项目仍标注为实际高 28／32／38px。

数量保持现有 12px 字号、14px 行高及 400 字重；名称普通 400、选中 600。图标和数量不随双行高度放大。

依据：[完整尺寸配方](/Users/wenchengkai/CodexFile/雨课堂-shadcn组件库架构/rain-classroom-vibe-ui-spike/packages/foundations/src/tabs-token-contract.ts:6)。该源文件现已纳入本轮修订，修改前摘要保留在新证据目录的 `source-baseline.json`。

## 4. 三种外观

### 4.1 线条

- 指示线两端采用完整圆头，横向、纵向一致。
- 保留三档 2／2／3px 的线条厚度，以及现有长度选项与靠内容面板侧的位置关系。
- 统一列宽后，纵向指示线必须始终位于可见范围内；不能跟着名称向外撑开。
- 选中指示线与键盘焦点继续表达不同状态。

### 4.2 底板

已确认两项最终可见距离：外围净留白 3px，相邻背景净间距 8px。

| 测量位置 | 目标 |
|---|---:|
| 横向首项左侧、末项右侧、所有项上下 | 3px |
| 纵向首项顶部、末项底部、所有项左右 | 3px |
| 相邻两个项目的可见背景之间 | 8px |

本方案的尺寸关系为：每项背景向内缩 3px，点击区域之间保留 2px，因此相邻背景净间距为 3 + 2 + 3 = 8px。容器不得再重复叠加一层外围留白。Hover 与选中背景共用相同几何边界。

内缩包含在每项整体高度中，不额外增加高度。由此得到：

| 档位 | 单行背景高度 | 双行背景高度 | 背景内与名称行盒上下各余量 |
|---|---:|---:|---:|
| 28 → 46 | 22px | 40px | 2px |
| 32 → 52 | 26px | 46px | 3px |
| 38 → 60 | 32px | 54px | 5px |

最小档的 2px 是行盒几何余量，不是字形实际墨迹边距。能容纳文字不等于已经确认视觉舒适，需与较大档位一起预览。

### 4.3 浅底

- 取消选中态常驻的完整描边。
- 保留选中填充、品牌色名称／图标／数量和选中字重。
- 未选中、Hover、按下继续通过对应填充与内容颜色表达状态，使用现有 Rain 颜色体系。
- 键盘焦点框独立保留，可以与选中态叠加；几何边界不因状态变化而跳动。
- 手动模式下，当前项仍显示选中填充，另一个获得焦点的项目显示焦点框。

预览时必须与真实二级按钮并排比较，尤其检查“当前分区”与“保存备注”是否容易区分。取消描边是已确认的设计方向，辨识度仍需实际验证。

## 5. 窄屏与状态连续性

切换条件由页面的实际可用宽度及正文阅读空间共同确定。192px 列宽不是全局断点；不能仅根据设备名称或某一条标题长度作判断。

空间足够时保留侧边纵向导航；空间不足时切到内容上方的横向单行导航，继续使用已有“更多”机制。自然宽度与等分宽度仍按场景选择。

切换前后应保留当前分区、已输入内容及最新数量；已创建的内容面板不因排列切换而重新创建。键盘方向规则应与实际方向一致，焦点不能落到隐藏项目或消失的入口上。

## 6. 实施前后需要保护的行为

- 受控选择以业务实际接受的值为准；拒绝或延迟接受时，不提前切换内容、访问状态或焦点，也不因换布局额外发出选择请求。覆盖“请求后换向，再延迟接受”，确认旧请求不会抢回已移到外部的焦点。
- “更多”菜单继续使用完整名称、图标、数量和禁用说明。手动键盘移动焦点与真正切换分区保持分离。
- 菜单打开时换向需要专门检查：焦点分别位于菜单、Tab、内容面板和外部操作时，不能留下错误方向的菜单入口、隐藏焦点目标或意外失去焦点。
- 排列变化保持组件和条目的稳定身份，不通过重建整个 Tabs 来切换布局；三种既有内容挂载政策仍按原合同执行。
- 等分布局的宽度预算需要包含图标、数量、导航独立操作、菜单入口及必要间距，不能再次只计算文字。纵向预留图标列的规则不自动带到横向。
- 全文入口覆盖名称自身的一行／两行省略，并验证对祖先裁切的识别。祖先越界仍须修复，全文提示不能作为布局越界的补偿；禁用长名称保留已有可发现说明入口。
- 新增双行高度超过 44px 时，触屏点击区不能被原有最小尺寸补偿反向缩小。实际几何、焦点和点击范围要一起检查。

上述行为保护来自实施前对受控值接受、布局测量、焦点交接及内容保留的只读核对。当前实现见 [Tabs 源码](/Users/wenchengkai/CodexFile/雨课堂-shadcn组件库架构/rain-classroom-vibe-ui-spike/packages/ui/src/tabs/tabs.tsx)，修订后的实测结果另见[本轮验证记录](/Users/wenchengkai/CodexFile/雨课堂-shadcn组件库架构/rain-classroom-vibe-ui-spike/evidence/runtime/tabs-visual-refinement/verification.md)。

## 10. 追加确认：指示线限长成为默认（2026-09-11 确认，09-12 实施）

用户要求保留当前自适应逻辑，同时支持蓝线达到最大长度后不再增长，并明确选择随 28／32／38 尺寸设为 24／28／32px。此决定替代 09-10 计划中的默认 stretch 和 content 最大 104px；颜色、厚度与圆头规则继续沿用。

复用既有 indicatorSize 两种选项：stretch 保留既有几何（横向为项宽扣除两侧内边距，纵向为整项高度）；content 改为默认限长，横向取 min(内容组宽度, 尺寸上限)，纵向取 min(项高度, 尺寸上限)，居中并始终朝向面板。自然宽度下 stretch 随内容增长；等分宽度下 stretch 沿用原本随分配项宽伸展的行为。content 在等分排列中也只按内容组及最大长度计算。最大长度是上限，短于上限的内容组不被强行拉长。

继续采用现有 Rain Token、现有两个枚举和 CSS 约束，无需新的长度测量或依赖。默认变化同时作用于完整 Tabs 与 Compound API。预览页仅在线条外观展示两种方式的切换。
