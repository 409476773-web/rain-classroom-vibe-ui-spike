## 2. 两类入口

### TagSelect：切换一个当前值

- 面向“学习环节”“资源分类”等有限本地集合。触发器显示当前值与展开箭头；颜色由选项中已登记身份提供，组件不猜测名称，也没有选色入口。
- 继承 20/24/28 完整 Tag 尺寸，交互默认 24；Filled 默认，保留 Outlined / Solid。箭头使用正式图标，随当前档为 12/14/14；完整触发目标和触屏间距在实施时验证。
- 打开后标明已选项；键盘活动项与已选状态分别表达。选新值立即切换并关闭；重选当前值关闭但不发重复变更。Escape 回触发器；Tab 与外部点击按正常离开路径处理。
- 当前预览采用短列表、不显示搜索。旧库可选本地搜索保留为有明确较长列表需求时的能力；不由此加入远程搜索、加载或自由输入。

候选接口：`options: readonly { value: string | number; label: string; color: TagColor; disabled?: boolean }[]`；受控 `value` + `onValueChange` 或非受控 `defaultValue` 必须提供有效当前值；另有 `open/defaultOpen/onOpenChange`、`size`、`appearance`、`disabled`、可访问名称与局部布局入口。不加 `multiple`、`allowCreate`、`clearable` 或任意色值。无选项、重复值或失效当前值由使用方修正，组件不能静默切到第一项。

### 自定义标签：选择与管理组合

建议作为可复制的完整 Recipe；本轮不因单个流程建立空的 `@rain-next/patterns` 包。公开 Tag 保持展示 / 移除职责，组合拥有已选集合、选择面板、创建和编辑视图。

1. 已选标签区始终可见，× 只移除当前对象关联。添加入口打开搜索与复用已有标签的面板。
2. 默认建议勾选立即更新当前对象的标签值，面板保持打开以便连续选择；这表示前端值变更，真实业务保存由使用方处理。已询问用户是否改为“确认”统一应用；尚未回复时预览采用此默认，并提供设计对照。
3. 无完全同名标签时出现“创建 ‘名称’”。进入面板内的创建视图，保留搜索文字为名称，展示实时 Filled 效果与全部 20 色。
4. “创建并选中”成功后由业务返回稳定 ID，加入词表与当前对象，再回到选择视图。失败留在创建区域，保留名称和颜色，允许重试；提交中阻止重复操作。
5. “管理标签”进入同一面板的管理视图。每行提供独立“编辑”；选择行不嵌套编辑按钮。编辑包含名称、20 色与真实预览，并说明会更新当前范围内使用这个标签的引用。
6. “保存修改”按同一 ID 更新定义，所有引用同步显示新名称和颜色；移除关联不会删除定义。第一版不加入永久删除、合并、归档、拖拽排序或权限后台。

替代方案是选中先保留草稿，点击“确定”后统一应用：适合批量改动需取消的场景，多一次操作，并需区分关闭、取消与已创建定义。不会为了对照同时固化两套公共状态引擎；流程确认后选择一个默认 Recipe，业务确需另一种时再组合。

## 3. 数据、输入与失败

- 标签定义为稳定 `id`、`name`、已登记 `color`；对象保存 ID 数组。选项、定义、关联与搜索输入分别管理，不以名称充当 ID。
- 名称必须 trim 后非空。同名范围、大小写规则和长度限制由业务提供；预览仅使用“当前课程、trim 后不区分英文字母大小写”的演示规则，不将其写成跨业务不变量。
- 同名时优先复用已有标签；编辑时排除自身。创建回调仍需处理服务端重名结果，不能靠本地判断代替真实校验。
- 创建和修改分别使用 `onCreate({name,color})`、`onUpdate({id,name,color})` 的明确请求入口，返回正式定义；关联通过 `onValueChange(ids, details)` 交给上层。真实请求、权限、缓存与结果过期处理归使用方。
- 搜索与名称框使用已有 Input，中文组合输入期间 Enter 不选择、创建或保存。名称、颜色不因失败丢失；重新编辑或返回时清除过期错误。关闭或取消的结果处理在实际异步接入时验证。
- 预览仅含模拟资源和本地状态，不保存真实课程数据；不会声称后端已接入。

## 4. 组合与最小依赖

| 部件 | 复用 / 最小实施落点 |
| --- | --- |
| TagSelect | `packages/ui/src/tag/tag-select.tsx` 与最少配方扩展；直接组合选定 Base UI 的选择原语，保留独立 Rain 身份。 |
| 选择面板机械行为 | 采用同一 Base UI 底座；共享 Popover 若已落地直接消费。尚未落地时，先明确 UI 依赖声明和最小公开入口，不从 Playground 导入实验代码。 |
| 列表与管理内容 | 纯选项使用相应选择语义；包含搜索、创建、编辑等操作的开放面板使用普通表单、复选框和按钮。不得把创建表单塞进 ARIA menuitem 或 listbox option。 |
| 创建 / 编辑 | 复用 Input、Button、现有 Tag 配方；区域内错误与成功反馈。色板仅消费已有 profile，不新增颜色角色。 |
| 公开与本地边界 | TagSelect 进入独立 Manifest / 本地 Registry 候选；管理流程先作为 Tag 示例中的完整 Recipe 验证。后续是否沉淀共享 Pattern 单独判断。 |

对外实现前需要把 Base UI 1.8.0 的依赖声明从实验作用域扩展到确切消费包，登记新增文件与颜色、Typography 消费范围；这属于第三批单独实施清单，不从第二批验收记录借用权限。现有通用 Select、DropdownMenu、Dialog 及它们的 Human Gate 不在本稿内迁移。
