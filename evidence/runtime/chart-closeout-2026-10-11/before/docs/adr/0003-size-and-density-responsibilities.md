# ADR 0003：Size 与 Density 的职责及选择顺序

日期：2026-09-05。决策状态：用户已确认本次设计方向。对应讨论中的回复为“确定”；完整规则与现有组件对照见 [设计文档第 3.4 节](../plans/2026-09-05-typography-and-layout-token-design.md)。

同日来源纠正：用户随后指出“新版组件库大多数组件的尺寸都是不对的”，要求控件高度、公共高度和间距优先对照旧版 Vue 已建设完成组件。该指令更新数值候选的依据，保留下述 Size / Density 职责与选择顺序。

## 问题

组件尺寸和区域密度需要共同服务布局。若密度再次缩放已选尺寸，或只按同名 Size 判断高度，组合结果和局部修改范围就难以预测。

## 决策

- Size 选择组件的完整尺寸方案；Density 为区域选择默认方案及间距；布局配方管理组合与对齐。不采用密度对已选 Size 统一二次缩放的方式。
- 显式 Size 优先，未指定时使用 Density 默认。进一步调整沿用 Local Recipe / Local Fork，并检查必要关联项；不要求所有组件新增 Size。
- 同一区域保持同一 Density，各组件保留适合自身角色的尺寸。同类新控件的可比档位尽量统一含义；历史差异通过实际映射承接，不仅比较名称或强制覆盖高度。
- 固定单行控件、随内容增长的容器、图标盒子与点击区域分别管理。公共高度身份不随密度变值，正式高度表和全部组件映射后续确定。
- 以 Classic 已建设完成组件的设计确认、契约及具体 Part 的实际高度与间距为主要依据，并区分实现、局部确认、整体验收和发布状态。Next 当前尺寸只用于识别差异，不能作为新公共尺度的默认依据；先整理完整组件方案，再判断共享范围。

## 候选与实施边界

此前 Compact 32px / Default 36px 仅保留为历史讨论候选，须依据 Classic 重新论证，不作为优先默认。讨论中从 Next Button 推出的 28 / 32 / 36 / 40 / 48px 五档不再作为本轮推荐的公共高度表；替代表尚未确定。Next Input Compact 30px 仅作差异记录，不因现有实现获得保留或公共档位资格。TextButton、Badge 和内容型容器继续按各自角色检查。

本决定的实现为 `not-started`，运行验证为 `not-run`，视觉验收为 `not-evaluated`。候选需经过实际组件验证后才能形成已验收默认；本次不修改运行中的 Token、组件 API 或样式，不推进既有组件验收与发布状态。后续实施遵循 [阶段登记](../../status/current-phase.yaml)和 [B2 局部隔离合同](0002-tailwind-b2-local-fork.md)。
