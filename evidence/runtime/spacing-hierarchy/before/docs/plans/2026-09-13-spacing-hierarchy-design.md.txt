# 三级间距关系：确认记录与后续实施步骤

日期：2026-09-13。工作模式：System Mode 的设计记录。目标：为现有布局补充可自由选值的间距层级关系。

设计关系：已由用户确认。运行实现：本次未调整。新规则的运行验证：尚未执行。此确认不代表现有布局页面的人工视觉验收或资产晋升。

## 决定来源与范围

用户明确选择：“全库共享层级关系，页面、卡片、面板分别拥有适合自己的数值配方。”随后要求三个数值不固定，“只要保证更上级的间距一定大于等于下级间距就可以”，并对包含同容器、同方向比较与累计距离检查的整理回复“确定”。

确认结果：**边缘留白 ≥ 分区间距 ≥ 分区内信息间距**。任意两级或三级全部相等均合法；不规定固定差值、比例或唯一数值组合。规范正文放在[组合规则第2.1节](../audits/2026-09-13-composition-layout-rules.md#21-已确认自由选值的三级间距关系)，本文件保留决定来源与实施准备，不创建第二份数值事实源。

上一轮讨论中的页面32/24/16、卡片20/16/8–12、面板16/12/4–8仅为说明候选，没有被确认成固定配方。现有 Card default20/sm12、控件 Size/Density 和 Foundation 刻度继续按各自合同管理；关系确认本身不修改它们。

## 与现有架构的衔接

容器管理边缘留白；Stack、Inline、Grid、Split 在各自排列中管理相应分区或信息间距。内容角色决定层级，DOM包装数量不决定层级。配方可以调整默认值，但调整后须保持同方向上的顺序关系。

本次未选择新增 padding 参数、语义 gap 参数、自动层级上下文或运行时纠正机制。具体落地优先复用现有 Props 和局部组合；是否需要公共 API 增量由实际样例说明，不能把“确认关系”写成“已确认全部 API”。

## 当前待协调项

以下来自当前源码核对，尚未在新规则下重新做浏览器测量：

- 设置与资料 Card：内距20，正文分组间距24。
- 资料 Pane：内距16，内部列表项或内容组间距20。
- 资料列表：相邻内容之间累计20 gap + 1线厚 + 20顶部留白；空白合计40，几何距离41，不能只记录gap20。
- 窄屏：页面外留白减小后，需按横向、纵向各自关系重新核对；不直接比较左右留白与纵向模块间距。

样例来源：[布局消费者](../../apps/prototype/src/layout-recipes.tsx)、[局部样式](../../apps/prototype/src/layout-recipes.css)、[页面布局](../../apps/playground/src/docs/components/layouts-page.css)。原RN-06证据保留历史范围，不回写为新规则已通过。

## 后续实施步骤

1. 对当前页面、Card和Pane分别标明容器、直接分区、信息组及各方向的距离拥有者；区分内容盒、空白、分隔线厚度。
2. 从现有 Rain Space选择可调整组合，协调目前倒挂与重复累加。覆盖严格递减、部分相等、全部相等三种合法组合；不固定全库比例。
3. 将关系落实到可复用的局部配方与现有四类布局的使用指引，明确非法组合如何反馈；公共API若确有需要，再记录最小增量与精确范围。
4. 在窄容器、换行、多行帮助/错误、分隔线和Split堆叠后，测量实际距离与对齐，并保留当前草稿、焦点、滚动、Card/Dialog行为回归。
5. 依据真实修改同步阶段、相关Manifest/Registry与证据；新规则验证、独立复核、人工视觉接受分别记录。

本次只更新设计和文档入口，验证限于文本一致性、链接及差异检查；不以文档检查宣称运行布局已符合新关系。完整业务Benchmark、机器字体/辅助技术、颜色、发布和业务迁移仍按原边界分别记录。
