# Workspace adapter candidate

W4 adds `WorkspaceLayout`, `RecoverableRegion`, `RegionRestoreTrigger`, `PaneSplitter` and `useWorkspaceLayout` without changing existing `Split` or Sidebar defaults. This is a Registry candidate for G2 review, not a published or accessibility-complete layout standard.

The controller calls the pure functions in `workspace-state.ts`. `spec` identifies the workspace/subscene/instance, defines region geometry and restore ownership, and describes supported modes. Without `viewportWidth`, a ResizeObserver measures the actual container. Effective modes are derived from the width budget and never replace saved preferences. Inject optional `storage`; storage rejection leaves interaction usable. Optional controlled `preferences` remains authoritative and `onPreferencesChange` reports requests. A declined request is announced as waiting for synchronization.

Pass a stable `toolbar` containing external `RegionRestoreTrigger` controls. Regions follow caller DOM order, including nested flex rows; the adapter does not reorder content. Place `PaneSplitter` at the single boundary belonging to a region. Compact mode is only meaningful for identifiable global navigation. `RecoverableRegion` keeps one content body mounted across hidden, compact, expanded and temporary modes. Hidden bodies are `hidden` and `inert`. `children` and `header` can render `{region,effective,temporary,visible}`. Top ribbons pass their recipe's `topHeights` and `topTemporaryHeight`; their temporary body preserves the original owner height.

Temporary panels use inline absolute positioning to preserve the content instance and its original occupancy. Outside pointer events continue to their original target; Escape and explicit close restore focus to the stable recovery trigger. Portal events retain logical ownership through React capture. Existing Base UI popup/modal layers get Escape first; the adapter does not replace their focus or overlay management. Escape targets the most recently interacted workspace instance. Hover is off by default; opt-in uses 240 ms open / 360 ms close, bridges trigger-to-panel movement, respects editable focus and cancels timers on context change or unmount.

Splitter pointer drag clamps width without hiding. Physical left/right keys change width by 10 px or Shift 32 px; Home/End use the allowed budget; Enter hides explicitly and sends focus to the external recovery button. The separator owns the boundary and its full accessible value range. Width and region changes naturally trigger ConnectedSurface measurement through ResizeObserver.

Business selection, playback state and drafts belong to the mounted recipe caller; the adapter persists only versioned layout preferences. Re-keying business content by mode/width/theme is unnecessary. Callers that unmount business recipes must supply their own durable business owner.

Focused adapter verification covers all-hidden recovery, stable first-click targets, occupancy through peek/pin/unpin, portal ownership, Escape priority, draft/scroll/focus retention, controlled refusal, actual-width adaptation, hover/StrictMode cleanup, rejected storage, physical splitter keys, multiple instances and top ribbon recovery. Browser evidence and human review are separate status dimensions.
