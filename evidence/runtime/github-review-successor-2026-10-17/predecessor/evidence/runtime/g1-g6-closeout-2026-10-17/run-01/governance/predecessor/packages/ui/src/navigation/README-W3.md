# Navigation v0.4.2 · W3 UI candidates

Scope: System Mode, `registry-candidate`, unpublished. Approved reference `0.4.2-style.1`; W3–W5 runtime visual/composition through candidate13 was accepted on 2026-10-04. G3, complete accessibility/contrast and new E1–E6 compositions remain separate. Shared exports, manifests, registry and consumer evidence are registered by the master task.

The components use the final refined reference styles measured in `evidence/runtime/navigation-v042/w3/reference/2026-10-01T10-40-10-888Z/`. They preserve the Rain visual lineage and do not change old Tabs, RadioGroup or Sidebar defaults. V04/V05/D05/I01 apply to fixed title/metadata/status roles, stable content templates, bounded titles and the choice of native destination/setting/object semantics. This is componentization of the approved reference, with no new design direction.

| Component | Contract | Boundary |
| --- | --- | --- |
| NavigationList | `items`, `activeId`, named `aria-label`, optional `onNavigate(id,event)`, `appearance="inset\|icons"` | Native links. The host callback adapts routing and retains modified link activation. `href` is required even for unavailable destinations. Icon rails require an icon for every destination. |
| ObjectNavigator | `items`, controlled string/null `value`, `onValueChange`, named `aria-label`, `appearance="queue\|cards\|preview"`, `content="simple\|info\|identity\|summary\|preview"` | A group with a list of pressed choice buttons and sibling action controls. No listbox options with clickable descendants. Selection, business loading/error data and drafts belong to the host. |
| SegmentedControl | Existing RadioGroup controlled/uncontrolled props, `legend` required and visually hidden, augmented `options`, `appearance="segmented\|white-line\|white-soft"`, `tone="neutral\|inverse"`, optional `density="regular\|compact"`, `iconOnly` | Reuses native RadioGroup selection, keyboard, form and reset behavior. W1/W2 remain settings rather than empty content tabs. Density otherwise follows the existing parent context. |

Content parts: `root`, `track`, `item`, `entry`, `leading`, `content`, `label`, `description`, `metadata`, `count`, `status`, `preview`, `progress`, `trailing-action`. Main labels and descriptions are text; `icon`, `meta`, `status` and `preview` are passive React slots. Put interactive controls only in `actions`, which remain siblings of the selection button/link. Runtime validation rejects missing/duplicate IDs, labels, hrefs, iconless rails and progress outside 0–100. Duplicate visible labels remain valid because IDs own identity. Missing selected IDs are reported without silently choosing another object. Changing appearances/content retains the same keyed items and controlled selection.

The five structures use one named content contract for the whole collection. Simple exposes the title/icon; info adds count/status/metadata/progress; identity adds a second identity line; summary permits up to two title lines and concise metadata; preview adds a passive thumbnail and location metadata. Queue identity keeps the name before its student/object description, following the reference. Summary does not force a blank second line into the accepted compact C4 example.

Local candidate colors are defined only on `.rain-navigation-family`, under `--rain-local-navigation-family-*`, `--rain-local-navigation-segment-*` and `--rain-local-navigation-white-*`. Exact approved dimensions outside existing Foundations use local candidates for 3/5/9/13/22px spacing, 2/7px radii, 40px function rows, 76px queue rows, 52×60px icon entries, 180/300/360px card bounds, 102×65px preview media, 30/32px segmented slots and 24/26px segmented items, 34/44px white presets. The remaining spacing, radii, line thickness, brand marker and focus values reuse existing Rain tokens. `navigation-v042-segmented` is a feature recipe with `promotionStatus=not-proposed`; it modifies only Radio root/label presentation. Inverse replaces the whole segmented color set, including hover, current and track border treatment.

Accessible names remain full text while visible labels can truncate. Each main entry references description, metadata, count, business status and textual completion percentage via stable `useId`-scoped `aria-describedby` IDs; IDs remain distinct across instances and stable across reordering/content changes. Business status has its own slot and color ownership. Focus is explicit, keyboard visible, and supported in forced-colors mode. No animation was added. Arbitrary interactive content in passive slots is unsupported. Full contrast/VoiceOver/browser breadth and cross-device pixel parity remain separate checks.

Validation: `pnpm test packages/ui/src/navigation/navigation-families.test.tsx packages/ui/src/radio/radio.test.tsx packages/ui/src/navigation/navigation.test.tsx` passed 28 checks (10 new); `pnpm --filter @rain-next/ui typecheck` passed. The first new test run with empty component bodies failed all 8 expected behavioral checks before implementation; two subsequent description checks also failed before the semantic detail fix. Browser/reference parity evidence is owned by the master W3 batch, not inferred from these unit checks.
