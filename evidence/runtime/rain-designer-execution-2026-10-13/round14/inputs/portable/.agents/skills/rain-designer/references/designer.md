# Designer：高保真交互原型设计指南

版本：v0.5 · 2026-10-13  
状态：光学校准补充审阅稿；未覆盖已确认版本，设计效果尚未通过独立新任务验证。

本指南提供 UI、UX 与交互设计的判断方法，不提供固定页面模板、布局、列数、组件排列或视觉数值。根据当前设计问题选用相关内容，不要求逐条执行。

## 1. 职责与使用边界

### 1.1 设计职责

以专业 UI、UX 与交互设计师的视角，理解业务信息，组织界面结构，设计交互行为、视觉表达与内容呈现，并评议设计结果。

业务理解只深入到足以支持当前设计判断：明确使用情境、处理对象、信息关系、判断依据、可执行操作、状态与限制。不默认扩展到产品战略、经营分析或工程架构。

构图、字体、色彩、比例、节奏、质感与情绪表达属于设计工作，不只是功能完成后的装饰。

### 1.2 资料分工

| 资料 | 提供的依据 |
|---|---|
| 当前业务资料 | 对象、内容、流程、状态、统计口径和权限规则 |
| 当前品牌规范 | 已确认的字体、色彩、图形、组件等视觉表达要求 |
| 当前组件库 | 实际可用的交互、组合和实现能力，以及 API 与来源 |
| 本指南 | 信息组织、交互、视觉表达与设计评议的判断方法 |

形成初步设计理解后，核对现有组件能力，再根据实际约束调整方案。是否复用高层组合，取决于任务含义是否匹配及修改成本；不要为适配组件而改变业务任务，也不要猜测 API。

历史页面只作为方法研究材料。除非本次明确要求参考或还原，否则不以相似旧页面为默认起点，不继承其固定布局、比例、颜色或业务规则。

### 1.3 不可自行改变的内容

本指南不替代项目授权，也不允许覆盖已确认的业务含义、品牌要求或必要的操作安全与可访问性要求。遇到冲突，说明影响并按当前授权处理，不静默修改业务或公共资产。

资料缺失或矛盾时，区分已知事实、设计假设和待确认规则。不得自行创造统计口径、权限、提交方式等业务规则，也不得将设计假设写成事实。

## 2. 设计理念与判断基础

### 2.1 五项设计理念

| 理念 | 含义 |
|---|---|
| 关系真实、表达清楚 | 分组、层级与操作范围对应实际关系，不为形式整齐改变含义。 |
| 复杂有序 | 减少无关、重复和含糊表达，保留用户完成任务所需的信息。 |
| 主次明确 | 按当前任务分配空间和注意力，不平均强调所有内容。 |
| 统一而有变化 | 同类角色保持可辨认的规律，不同任务允许采用不同构图。 |
| 视觉与行为一致 | 视觉上的分组和选中，对应实际对象与操作范围；状态变化后重新核对。 |

### 2.2 信息作用先于表现形式

先判断信息用于识别、定位、比较、解释、决策还是状态反馈，再决定其可见程度、阅读完整性和视觉权重。这些角色用于分析，不需要直接变成页面栏目。

结合内容特征判断表达方式：是否需要同时比较或完整阅读，长度和数量如何变化，是否依赖图像识别，哪些信息相互依赖。不要仅因内容是数字就做成指标卡、是集合就采用卡片、是辅助信息就折叠。

### 2.3 区分三种层级

| 术语 | 判断对象 |
|---|---|
| 语义层级 | 对象的包含、归属，以及控制的作用范围。 |
| 注意力层级 | 当前任务和状态下，信息被优先注意的需要。 |
| 操作优先级 | 当前应优先支持的操作，结合任务阶段、使用频率与错误后果判断。 |

三者不必采用相同的大小和位置。高层上下文可以清楚但不突出；紧急反馈可以临时加强；高频操作可以易于获取而不占据最大面积。

### 2.4 明确视觉差异的含义

区分重要程度、类别、状态与品牌表达。它们可以使用相同的视觉手段，但不能相互冒充。例如，类别颜色不同，不自动代表重要程度不同。

颜色、大小或位置一旦暗示数量、程度或状态，就需要有对应的数据或状态依据；装饰性变化不能伪装成数据或状态编码。

## 3. 视觉与感知原则

每条原则按“目标—判断—取舍—检查”组织。目标说明希望形成的品质；判断指出需要观察的关系；取舍保留不同表达的选择；检查用于评议结果。它们不是四个必须依次完成的步骤。

### V1. 关系与分组

**目标：**让用户辨认内容归属、对象边界和操作范围。

**判断：**先确认语义关系，再检查位置、距离、相似性、对齐与共同区域是否准确表达对应关系。同一关系出现冲突线索时，先核对内容归属，不直接增加容器或间距。

**取舍：**根据关联强弱，选择文字、间距、对齐、分隔、背景、连接或容器。分隔过弱可能造成错误归组；分隔过强可能拆散连续任务。不预设有标题就需要卡片，也不预设去掉边框更好。

**检查：**内容换行、说明出现或区段展开后，标签、状态与操作是否仍属于正确对象。不要用容器数量或间距大小代替分组效果。

### V2. 主次与焦点

**目标：**突出当前任务需要的信息，同时保持其他必要内容可读。

**判断：**从整页到区域、再到元素确定相对权重。局部标题或数值不必成为整页焦点；不默认每个区域都需要强底色、大数字或主按钮，也不规定复杂页面只能有一个重要操作。

**取舍：**综合位置、尺度、字重、明暗、颜色、留白和表面关系。可以加强重点，也可以降低周围内容的强调程度；不要不断放大所有元素。弱化辅助信息时，保留项目要求的可读性与可访问性。

**检查：**关键内容是否容易识别；不同强调是否相互竞争；进入选中、错误或处理中状态后，注意力分配是否符合当前任务。

### V3. 秩序与稳定

**目标：**建立便于识别、比较和操作的重复规律。

**判断：**确定哪些对齐关系、阅读起点和角色位置需要稳定。允许长内容、数量变化或特殊状态引起尺寸与排列变化；几何整齐不能替代语义正确。

**取舍：**可使用网格、基线、缩进、重复的文字角色、图形或分隔。对称、非对称和局部错落都可采用，不要求等宽、等高或大量框线。为突出异常而打破重复时，保留对象身份和共同角色的识别线索。

**检查：**长内容、缺失值和局部展开后，用户是否仍能找到阅读起点、识别对象并定位关键操作。

#### V3.1 视觉对齐与光学校准

**目标：**使内容在实际显示条件下呈现预期的对齐关系。元素框对齐是结构依据，不是视觉校准已通过的证明。

**判断：**明确谁与谁对齐，参照是容器边缘、中心线、文字基线、首行还是主要可见图形。区分元素框、文字行框与可见轮廓；不要将文字基线当作所有字形的底边。检查问题属于位置、视觉大小、重量还是间隔，并核对字体、图标变体及资产已有的补偿。

**取舍：**先修正不合适的参照、配置或资产用法；仍有可辨认偏差时，再在授权范围内校准。选择与原因相符的调整，保留有意的主次、状态与类别差异。不为所有元素设置统一偏移，不以裁去内部留白、拉伸图形或逐字位移作为默认做法，也不重复补偿已校准资产。不改变数据编码或已确认的品牌图形比例，不破坏必要的布局规律、点击可达性与焦点表达。

**检查：**在目标尺寸下，将元素放回相关文字、组合和重复对象中比较；局部更顺眼不代表整组更协调。无需调整是有效结论；改善不明确时，不继续叠加偏移。具体检查见第6.4节；需要区分原因时，按需读取[光学校准诊断补充](optical-alignment.md)。

### V4. 空间与节奏

**目标：**用空间支持阅读、比较、操作和视觉节奏，不追求空白或密度的最大化。

**判断：**页面层面检查主辅比例与同时可见的需要；区域层面检查组内、组间关系；元素层面检查文字阅读与操作目标。区分内容数量、阅读排版和操作密度，内容多不意味着字号与点击区都要缩小。

**取舍：**空间不足时，先检查重复信息、错误分组和过度强调，再决定压缩、分步或按需呈现。隐藏内容时，同时比较发现、往返与记忆成本。允许区域密度不同，但差异需服务于任务或整体构图。具体数值来自项目规范，不从本指南推导固定比例。

**检查：**在约定窗口尺寸和真实内容条件下，用户是否能阅读必要内容、完成比较并触达操作；是否需要不必要的滚动。空间调整不只追求截图更空。

### V5. 统一与变化

**目标：**保持共同设计语言，同时保留不同内容所需的表达方式。

**判断：**区分由任务、内容、状态、识别需要或品牌表达引起的差异，与无明确依据的差异。同类角色和行为含义应可辨认，不要求所有模块使用相同结构。

**取舍：**统一损害信息表达时，允许变化；变化干扰识别与比较时，考虑收敛。字体、色彩、线条、图标、图像、表面与动效放在整页中协调。视觉兴趣、质感与符合产品气质的情绪表达可以是设计目标，不要求每处装饰对应业务字段，也不默认删除颜色、渐变或插图。

**检查：**同类角色是否一致，不同区域是否协调，视觉表现是否干扰阅读和操作。具体数值相同或局部精致，不代表整页协调；装饰数量和历史页面相似度也不是质量指标。

## 4. 交互与行为原则

### I1. 含义清楚

**目标：**让用户理解当前对象、入口和操作行为。

**判断：**区分定位、查看、选择、过滤、模式切换与执行动作。外观相近不代表行为相同；名称、图标、位置、可操作暗示和反馈需共同说明含义。

**取舍：**可以采用不同外形，但保持相近行为可辨认。使用用户能理解的语言，不默认其熟悉内部缩写；必要说明靠近相关内容，不依赖用户记住开场说明。

**检查：**按任务需要检查默认、悬停、焦点和选中状态，避免将装饰误认为控件，或因装饰弱化操作入口。

### I2. 结果可预期

**目标：**让用户在操作前理解影响范围和必要后果。

**判断：**明确作用对象、生效范围、前置条件与可逆性。业务未确认的默认值、提交方式或批量范围，不能由界面形式决定。

**取舍：**根据使用频率、错误代价与范围清晰度选择提示和确认。信息明确、风险较低时可直接操作；风险较高或范围含糊时，考虑增加说明与检查。不为所有动作使用相同确认，也不为减少点击删除必要保护。

**检查：**用户能否判断操作影响谁、何时生效及重要后果。未确定的行为标记为设计假设，并说明其影响。

### I3. 反馈可见

**目标：**让用户知道操作是否被接收、处理进展和结果。

**判断：**区分已接收、处理中、完成、部分失败与全部失败。反馈应关联原操作对象，不因当前视图切换而产生对象误解。

**取舍：**按影响范围和持续时间选择文字、图形或动效。局部事件不必打断整页；重要结果不应仅以容易错过的短暂提示呈现。模拟数据与模拟等待需注明，不当作真实性能，也不暗示尚未完成的工作已经完成。

**检查：**用户是否知道发生了什么、影响哪里、现在可以做什么。等待或切换视图后，反馈是否仍指向原操作对象。

### I4. 控制与恢复

**目标：**提供符合业务支持范围的退出、修正和继续路径。

**判断：**区分关闭视图、取消操作、放弃修改与撤销结果。根据实际业务设计恢复能力，不承诺不存在的撤销。

**取舍：**错误说明应包含问题、影响和可行的下一步。业务允许时保留输入与已完成内容，避免局部失败导致全部重做。输入容错不能在含义有歧义时静默改写用户意图。

**检查：**关闭、返回、失败或重新进入后，检查焦点、内容和操作位置。无法实际检查的行为标为未验证，不能以画出状态代替行为验证。

### I5. 连续与一致

**目标：**让用户在切换和重复操作后，仍能理解当前对象、已完成内容和下一步。

**判断：**检查对象切换、返回和异步结果到达后，哪些上下文与选择仍然有效。稳定不等于保留全部状态或固定全部位置。

**取舍：**保留有效状态；对失效状态，根据业务清除、解释或重新确认。保持熟悉行为可辨认，可按不同熟练程度提供操作路径；没有需求依据时，不为展示完整性增加快捷键、自定义或复杂模式。

**检查：**当前对象、选中态、显示内容与工具作用对象是否一致。状态变化后，视觉上的分组和选中是否仍反映实际作用范围。

## 5. 方法选择与设计取舍

### 5.1 从具体问题选用原则

先提出对问题的解释，再选择设计动作。“杂乱”可能来自分组错误、强调竞争或内容重复；“空洞”可能来自比例与节奏失衡；“难操作”可能来自对象或作用范围不清。

这些解释是待检查的设计假设，不因引用理论就成立。不要将所有问题都归结为间距，也不要求每次执行全部原则。

### 5.2 保留多种表达的可能

同一关联可以通过空间并置表达，也可以通过明确的进入与返回关系表达。比较共同阅读需要、操作频率、内容增长和空间条件，不预设某种布局更专业。

新建复杂页面时，可以比较少量实质不同的方向，差异应涉及信息关系、阅读方式、操作路径或构图，不只是颜色。是否展示多稿、何时等待选择，取决于用户要求和任务风险。

### 5.3 明确收益与代价

| 冲突 | 比较重点 |
|---|---|
| 分组与连续性 | 分隔是否帮助理解，是否拆散同一任务。 |
| 留白与信息完整性 | 哪些内容需同时查看，隐藏后增加什么成本。 |
| 强调与整体秩序 | 重点是否清楚，是否压过其他必要信息。 |
| 统一与内容差异 | 共同角色是否可识别，变化是否帮助表达。 |
| 快捷与安全 | 操作频率、错误后果、影响范围和可逆性。 |
| 品牌表现与可读性 | 风格是否协调，是否干扰判断、阅读或操作。 |

说明选择、依据、代价与待验证项，不用原则数量、符合项总分或固定权重代替判断。

### 5.4 让探索深度匹配修改范围

| 任务 | 处理边界 |
|---|---|
| 新建页面 | 在当前要求与授权内探索信息结构、交互和构图。 |
| 优化已有页面 | 保留已确认且不在本次修改范围内的内容，调整相关问题。 |
| 局部修改 | 不改变无关结构与行为，只检查必要联动。 |

需要改变已确认方向时，说明理由与影响后按授权处理。局部视觉调整不自动授权全页重设计或公共组件修改。

## 6. 设计评议

### 6.1 同时检查整体与局部

先检查整页任务组织、主辅关系和视觉气质，再检查区域与元素的排版；局部调整后回到整页，检查新增的强调竞争和不一致。

分别评价视觉完成度与交互正确性。美观不能抵消严重操作问题；可操作也不代表层级、节奏与视觉表达已经成熟。

### 6.2 用相关变化检查设计

按任务风险选择内容变长、对象增多、信息缺失、状态切换、错误出现、窗口变化或任务焦点变化等条件，检查信息与操作关系是否仍然清楚。

不机械补齐所有状态截图。局部修改覆盖必要联动，新建复杂页面采用更充分的检查。

### 6.3 区分证据与推断

| 证据 | 能够支持的判断 |
|---|---|
| 静态观察 | 已显示的信息组织与视觉关系。 |
| 可操作原型检查 | 实际执行过的交互行为。 |
| 真实参与者的测试与反馈 | 对应参与者、任务和条件下的使用情况。 |

记录检查内容、观察结果、修改和未验证项。AI 自查不等于用户测试，少数成功实例也不能证明所有任务都会受益。

### 6.4 检查视觉对齐与光学校准

检查顺序用于减少误判，不要求每次遍历所有元素或生成全部状态截图。

**确认条件。**先确认目标字体、图标和样式是否按预期呈现。原型页面使用实际渲染；Figma 或截图仅支持其已显示条件。截图被缩放、字体状态不明或资产未加载时，不据此确定精确补偿量。放大用于定位问题，判断是否改善要回到目标显示尺寸。

**确定参照并比较。**先明确对齐对象与目标关系，再比较可见轮廓。存在问题且有修改授权时，保留可比较的原状态；围绕已识别原因作可比较的局部调整，在相同内容、状态与显示条件下比较前后，再回到所在组合和整页复查。

**按风险复查。**根据实际改动选择多行或中英混排、数字与单位、目标尺寸、带标记变体、加载或选中等相关条件。不把单一条件下的补偿推广到所有尺寸和变体；检查裁切、溢出、点击区域、焦点表达与已有动效是否受影响。静态图不能证明这些行为已经通过。

**记录结论与停止。**按实际证据区分“已检查，无需调整”“已调整并复查”“存在疑点，待确认”“未检查，条件不足”。比较不能稳定支持改善时，撤回本次试调或保留疑点，不连续叠加补偿。少数条件通过不等于整个组件库通过，AI 自查也不等于用户验收。
