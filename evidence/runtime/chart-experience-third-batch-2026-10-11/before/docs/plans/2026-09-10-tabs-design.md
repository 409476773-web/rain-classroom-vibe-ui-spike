## 1. 目标与已确认决定

以 Rain Classic 的 Line Tabs 为视觉与功能来源，建设同一界面内关联内容分区的切换组件。默认提供可直接使用的完整方案，需要局部变化时通过公开内容位置与 Parts 组合。2026-09-10 经视觉比较，首版范围包含 Line、Contained、Soft，三种外观共同提供三档尺寸与四向；已确认语义保持一致。

| 事项 | 用户明确选择 | 适用边界 |
| --- | --- | --- |
| 首版用途 | 先做内容分区切换 | 用户主动新增、关闭的工作区另行建设；支持页面数据驱动的分区增减 |
| 横向溢出 | 默认“更多”收纳 | 保留横向滚动选项 |
| Line 尺寸基线 | 最初确认 Small 32px + Medium 38px，后续确认补充 28px | 最终三种外观共同提供 28 / 32 / 38px；保留原 32 / 38 完整几何 |
| 面板生命周期 | 首次进入时创建，之后保留 | 本次页面使用过程；不含刷新后恢复、自动保存与数据缓存 |
| 键盘激活 | 方向键定位，Enter / Space 切换 | 默认 manual，auto 可选；鼠标点击直接切换 |
| More 选择后的呈现 | 显示相邻的一段，随当前项移动 | 可见区为原始顺序中的连续区间；区间外项目按原序收入 More，不固定开头几项 |
| 内容组合与状态规则 | 文字保留，图标/数量可选；数量保持辅助层级；禁用整体弱化；长名称有全文入口；数量/尺寸变化不扰动内容与焦点 | 2026-09-10 对上一轮五条建议回复“确定。继续”；具体 Token、复合状态视觉与实现验证独立 |
| 纵向内容对齐 | 默认居中，保留左 / 右对齐 | 左右两侧的纵向导航均适用；每项内部对齐，长短差异大的名称可显式左对齐 |
| 外观探索方向 | A 基线认可；B 适合弹窗/卡片/局部小面板；C 保留并探索灰色未选态与主题色选中态 | 本轮水平几何与状态方案见第 3.6 节确认；Token、完整视觉验收独立 |
| 尺寸与外观独立 | A / B / C 共用 28 / 32 / 38px 三档 | 用户在实施计划编写时明确选择三档；场景只影响推荐档位，不改变可用集合 |
| 外观几何与复合状态 | 确认本轮 A/B/C 水平几何及状态方案；B 底板 6px / 内部 4px 圆角、内缩 2px；C 6px 圆角、预留 1px 描边；Focus 独立，已选禁用保留当前项标记 | 用户对状态对照与几何建议回复“确定”；设计确认不等于实施或运行验收 |
| C 的浅灰取舍 | 保留当前浅灰视觉，单独解决用色规则 | 不改成略深灰；保留实际 interactive / critical 语义，为 Tabs Soft 精确用途另行设计治理规则，不放宽全局 Weak Neutral |
| 方向与溢出范围 | A / B / C 都支持上、下、左、右四向 | 横向默认 More、Scroll 可选；纵向 Scroll；各方向具体几何与边界按实施计划核对 |

确认来源为当前对话中的逐项选择、成组确认及最新尺寸补充，原文与调研证据见 [来源审阅](../audits/2026-09-10-tabs-reference-review.md)。未在本表列出的建议不应标成用户已确认。

## 2. 使用场景与组成

| 场景示例 | 内容 | 关注点 |
| --- | --- | --- |
| 课程内容分区 | 概览、学生、课堂记录 | 计数、更多菜单、导航两端操作 |
| 局部面板 | 详情、讨论、操作记录 | 窄容器、状态保留、嵌套时的键盘归属 |
| 纵向设置 | 基础信息、教学设置、权限设置 | 标题对齐、长标题与纵向滚动 |

这些是设计与验证样本，不是三个新公共业务组件。

语义 Parts 为 Root、Nav、List、Tab、Icon、Label、Count、Indicator、ExtraStart / ExtraEnd、More、OverflowMenu、Panel。Parts 描述视觉和组合职责，不要求每个 Part 都导出一个空包装组件。

默认示例一次给出完整的标签列表、对应面板和切换行为。Label 为主体；图标辅助识别；Count 默认沿用轻量括号数字，保留 0；提醒标记通过现有能力组合。导出、新增学生等独立动作放在导航操作区。常规 Tab 内不嵌套另一独立按钮或链接。

已确认文字保留、图标与数量按需提供；以下四种组合使用同一份结构：

| 组合 | 使用依据 | 呈现规则 |
| --- | --- | --- |
| 文字 | 名称已能清楚区分分区 | 默认入口，名称必需 |
| 图标 + 文字 | 图标能帮助识别内容类型 | 前置图标仅辅助，不成为独立操作 |
| 文字 + 数量 | 数量有助于理解分区内容 | 如“学生 (56)”，数量保持辅助层级 |
| 图标 + 文字 + 数量 | 同时需要类型识别和数量信息 | 仍使用已确认的尺寸与内容间距 |

图标与数量缺省时不保留空位；不以纯图标替代常规内容分区名称。数量 0 明确显示为 `(0)`，未知或未提供数量不显示，不用 0 代替未知。默认显示完整数值，不自动压为 `99+`；特定业务需要缩写时由宿主明确提供呈现内容与完整可访问说明。普通数量不自动转成醒目徽标，未读或异常提醒单独使用语义明确的已有标记能力。

Panel 可承载表格、表单、图表和其他组件；不默认强加卡片、背景、固定高度或第二层滚动。页面内容的留白与滚动由组合场景决定。

关联内容面板可以同步 URL、支持深链接和前进后退；独立页面跳转通常使用链接导航；同一集合的筛选优先使用合适的选择组件。判断依据为内容关系，不仅是 URL 是否变化。

## 3. 尺寸与视觉

### 3.1 已确认 Line 基线完整尺寸配方

| 项目 | Small / compact | Medium / default |
| --- | ---: | ---: |
| Tab 高度 | 32px | 38px |
| Label 字号 / 行高 | 14 / 20px | 15 / 22px |
| 图标尺寸 | 14px | 16px |
| Count 字号 / 行高 | 12 / 14px | 12 / 14px |
| 标签间距 | 8px | 8px |
| Icon / Label / Count 内容间距 | 2px | 2px |
| 指示线厚度 | 2px | 3px |

Label 普通 400、选中 600，Count 保持 400；字体为 PingFang SC。显式 Size 优先，未提供时由区域 Density 选择完整默认配方；不再二次缩放。此映射仅属于 Tabs，不修改全局 Density 或其他组件。最新指令明确三种外观共用 28 / 32 / 38px；底板内缩等外观结构在同一尺寸定义内处理，不能把底板留白再叠加为另一种整体高度。共享尺寸见第 3.5 节。

### 3.2 Line 建议沿用的视觉规则

- 透明 Tab 背景，中性文字，品牌蓝指示线；Hover / Pressed 加深内容色，Selected 通过 Label 字重和指示线表达。
- 建议保留 Top / Bottom / Start / End 四向位置，默认 Top。水平默认按内容宽度排列，允许整组居中；纵向 left / center / right 与默认 center 已由用户确认。
- 指示线默认 stretch，允许 content。水平 stretch 覆盖扣除两侧内边距后的区域，纵向 stretch 覆盖整项高度；content 跟随图标、名称与数量，水平上限先沿用 104px。
- 水平 Tab 两侧各 8px；纵向内容两侧各 24px、导航宽度先沿用旧版 120px 作为基础候选，特殊宽度通过具名局部配方调整。长名称保留完整可访问名称与可发现的全文入口。
- 分隔线默认关闭，开启时整个导航区仅一条 1px 浅线，位于靠近 Panel 一侧；导航与 Panel 的默认间距先沿用 16px。
- 使用当前 Rain Next 全局双层 Focus，保持选中与键盘焦点可辨。颜色、字体、Focus 与几何映射到 Rain 公共 Token，不使用外部库默认外观或旧版变量树。

上述继承默认待整稿及后续真实样例检查；尺寸讨论示意不构成完整视觉验收。Dark 使用 Next 已有主题与颜色治理，旧 Vue Dark 数值只作来源参考。

### 3.3 已确认内容规则与状态表现候选

2026-09-10 用户对五条内容组合与状态建议回复“确定。继续”：文字保留且缺省图标/数量不留空位；显示 `(0)`、未知不显示、数量选中不加粗且不自动改徽标/`99+`；禁用时三类内容整体弱化且列表/More 规则一致；长名称优先省略 Label 并提供鼠标/键盘全文入口；数量变化或容器缩放不切换内容、不清空面板、不抢焦点。下表为落实这些规则的状态表现候选，具体 Token 和复合视觉仍需样例核对。

| 状态 | Label / Icon | Count | 选中标记与焦点 |
| --- | --- | --- | --- |
| 普通 | 中性内容色、Label 400 | 辅助中性色、400 | 无选中标记 |
| Hover / Pressed | 按相应状态加深 | 同步使用相应辅助内容状态、保持 400 | 不改变选中项 |
| Selected | Label 600，Icon 使用对应外观的选中内容色 | 选中辅助内容色、保持 400 | A 蓝线；B 底板内选中块；C 主题色文字/填充与浅边框 |
| Focused | 保持未选或已选的内容层级 | 不因聚焦冒充已选中 | 使用全局 Focus，选中标记仍跟随已选项 |
| Disabled | 使用禁用内容色 | 同步弱化、保持 400 | 不接受激活或 Hover / Pressed 反馈 |

列表与 More 菜单应一致表达内容的选中、禁用与辅助层级；菜单行的背景、Focus 与选中标记复用公共菜单合同，不额外复制一套标签指示线。三类内容分别映射对应 Rain Token，不强迫图标和数量使用完全相同色值。旧版禁用 Count 未同步弱化、More Count 状态遗漏不继承。

受控宿主明确保留 Selected + Disabled 时，选中含义仍须可识别；不把内容保留误作可再次激活，具体复合视觉在样例中核对。临时不可用可展示禁用项并在可发现位置解释原因；不通过禁用项泄露应由页面隐藏的权限内容。

长名称保持单行，优先省略 Label，图标与普通数量不被挤变形。截断时需有鼠标与键盘可发现的全文入口，More 菜单也提供完整名称；不改变 Tab 的主要切换动作。120px 纵向候选宽度及极长数量须在真实样例中核对，不能只剩图标和数量却看不清名称。数量更新只影响内容和溢出测量，不改变选中值、不重建 Panel，也不主动搬移焦点。

### 3.4 四向布局、对齐与导航操作区提案

本节中纵向默认居中及左/右可选已确认；编写实施计划时用户进一步确认三种外观均支持四向。其余具体布局默认仍为计划建议。默认 Top；Line 蓝色指示线及可选分隔线始终位于导航靠 Panel 的边缘：

| 导航位置 | 标签排列 | 指示线 / 分隔线所在边缘 | 常规使用 |
| --- | --- | --- | --- |
| 上方 Top | 横向 | 导航下沿 | 默认内容分区 |
| 下方 Bottom | 横向 | 导航上沿 | 内容结构明确需要下方切换时 |
| 左侧 Start（当前从左到右界面） | 纵向 | 导航右沿 | 设置、详情等侧边分区 |
| 右侧 End（当前从左到右界面） | 纵向 | 导航左沿 | 右侧工具区等明确场景 |

两类对齐分别定义，不能共用一个含糊的“居中”说明：

- 横向默认从左侧起按内容宽度排列，可选整组居中。居中基准是扣除前后操作区后的可用标签区域，包含 More；不承诺相对整页或整个导航区几何居中，也不将各项均分拉宽。
- 纵向每项内部 Icon / Label / Count 可左、中、右对齐；**用户已确认默认 center**，原文为“默认居中，保留左／右对齐（推荐）”。它不改变整条导航的位置，left / right 为物理方向，不因侧栏从左换到右自动镜像；长短差异明显的名称可显式 left。

分隔线建议默认关闭、需要明确区隔时再开启。开启后为一条跨越整个 Nav（含前后操作区）的 1px 浅线，蓝线叠在其上；导航与 Panel 间距建议沿用 16px，由一处组合规则提供，不叠加重复留白。两种指示线长度沿用第 3.2 节建议，不随分隔线开关改变点击区域或选中表现。

额外内容按导航方向排列：水平为“前置内容 → 标签与 More → 后置操作”，纵向为“上方内容 → 标签列表 → 下方操作”。Bottom / End 不反转前后位置；这些位置属于导航本身，不表示固定在视口边缘。默认两端为空且不占位，优先使用已有 Button / TextButton / IconButton 等组件。

组合建议：页面标题与面包屑放在 Tabs 外；稳定的相关操作可放导航末端；只属于当前面板的筛选、批量处理等默认放该 Panel 的工具区。基础 Tabs 提供内容位置，不增加“带导出”“带搜索”等业务开关。

较高按钮可以增加整行 Nav 的高度，但不能改写已确认的 Tab 尺寸。横向 Tab 靠 Panel 一侧与导航边缘对齐，避免蓝线与浅色分隔线错开；操作自身保持可用尺寸。纵向操作不能悄悄撑破侧栏宽度，需要更宽时由具名局部配方整体调整候选 120px 宽度。

窄容器先按已确认的 More 策略处理标签溢出。两端操作不混入“更多标签”菜单；当操作自身挤占标签的基本可用空间时，完整组合示例由页面布局把操作移至独立行或提供明确的精简操作，不缩字号、不缩点击区域、不自动丢弃操作。纵向切回 Top 由页面显式响应容器布局，基础 Tabs 不暗中改变方向。具体阈值由真实内容样例决定。

### 3.5 视觉变体探索

用户提出参考 shadcn/ui 增加其他 Tabs 外观，随后明确 A 没有问题、B 倾向局部小面板、C 可以保留并指定新状态方向。三种外观均纳入首版，水平几何与状态方案见第 3.6 节；实施计划编写时进一步确认三档尺寸、全四向及保留 C 浅灰。具体布局默认和颜色消费合同仍按计划落实。

本轮读取 [shadcn Base Tabs 官方页](https://ui.shadcn.com/docs/components/base/tabs) 与 [Radix 页](https://ui.shadcn.com/docs/components/radix/tabs)，并在浏览器查看 Base 默认及 Line 实际示例。官方 [Base 源码](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/ui/tabs.tsx) / [Radix 源码](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/radix/ui/tabs.tsx) 的 `TabsList` variant 为 `default`、`line`：前者为整组浅底板加选中背景块，后者为透明背景加指示线。方向、图标和 Panel 内 Card 属于另外的维度或组合，不是额外官方 variant；“底板式”是本草案的中文描述名。

| Rain 讨论方向 | 外观与场景假设 | 来源 / 当前建议 |
| --- | --- | --- |
| Line 下划线式 | 开放排列、中性文字与品牌蓝线，适合页面级内容分区 | 用户认可 A 基线，建议仍作默认 |
| Contained 底板式 | 浅冷色底板、独立选中块，适合弹窗、卡片或局部区域内少量关联面板 | 参考 shadcn default；这些场景可推荐偏小尺寸，但 B 必须具有完整尺寸集合 |
| Soft 主题色块式 | 无整体底板；未选中浅灰文字 + 很浅半透明中性填充、无可见描边；选中深主题文字 + 浅主题填充 + 浅主题描边 | 用户明确保留 C 并按此方向探索；这是 Rain 新增候选，非 shadcn 官方第三种 variant |

同一组名称、数量和选中状态已用于横向比较，真实页面组合按实施计划建设。三种外观共享已确认的内容语义、值、键盘激活与面板保留规则；新增外观不获得另一套默认行为。Line 的指示线长度与分隔线属于样式专用规则，底板式和浅色块式不叠加下划线。四向及溢出范围现已确认，具体组合仍须运行验证；示意不构成全矩阵支持或视觉验收。

外形像分段控件，不改变 Tabs 的内容面板语义；如果切换同一列表的筛选值或视图，仍应按语义选择 Segmented。卡片页签外观也不等同于新增/关闭工作区能力；本轮未引入这些工作区操作，后续若比较卡片外观，应单独说明其视觉目标。

#### 三种外观共享尺寸

2026-09-10 用户补充：“方案 A、B、C 它们的尺寸应该都是共通的”“如果提供尺寸，应该所有方案都会包含从小到大的完整尺寸”。这明确修正了助手先前单独为 B 分配较小尺寸的提案；未接受按外观拆分尺寸范围。尺寸与外观是独立选择，场景可推荐某档，但不改变可用集合。

完成共同尺寸对照后，用户在实施计划编写时明确选择 **28 / 32 / 38px 三档**，三种外观全部提供：

| 共同尺寸（整体高度） | Label 字号 / 行高 | A / B / C 覆盖 | B 底板内部单项高度（上下各内缩 2px） |
| --- | --- | --- | --- |
| 28px，新增紧凑档 | 13 / 18px | 全部提供 | 24px |
| 32px，沿用已确认 Small 基线 | 14 / 20px | 全部提供 | 28px |
| 38px，沿用已确认 Medium 基线 | 15 / 22px | 全部提供 | 34px |

建议 size 统一描述外部整体高度；同档三种外观使用同一 Label 字号/行高，Count 保持 12 / 14px、400。B 的底板内缩包含在总高度里，不能再额外加高。A 可在局部用小档，B 同样可使用大档；若后续增加尺寸，三种外观一起覆盖。场景推荐通过完整 Recipe 表达，appearance 不暗中二次缩放。触摸、键盘 Focus 与 200% 缩放作为所有外观/尺寸组合的验证内容，桌面紧凑示意不自动等于触摸验收。

#### C 的配色方向与当前候选边界

“主题色”本轮按 Rain Brand 蓝理解；未新增语义主题切换 API。C 由原先仅选中填充的方案改为两态均有填充、选中额外浅描边。描边出现不改变尺寸，仍保留 Label 选中 600、Count 400 与独立全局 Focus。

实施计划编写时，用户明确选择“保留当前浅灰视觉，单独解决用色规则”。因此不自动采用略深的 `/3` 对照；`/4` 的已知用途失败成为 Tabs Soft 精确治理任务。现行规则在实现修订与验证前仍按失败记录，不把设计选择写成既有校验已通过。

示意使用现有 Token 值作为颜色候选，底面明确为 `Background/Neutral/1`；只调整讨论图，不修改 Token 或公共消费合同：

| 未选中文字 | `Text/Neutral/4` | 用于本轮浅灰视觉探索，现行交互文字资格未通过，尚不能直接进入公共组件 |

### 3.6 已确认水平几何与复合状态方案

2026-09-10 用户在查看本轮状态对照与几何建议后回复“确定”，确认以下水平几何与状态方案。状态稿默认展示 32px，另可对照 28 / 38px。随后在实施计划编写时明确确认三档尺寸、全四向和保留 C 当前浅灰；设计确认不改变现有颜色用途资格结论，组件实现尚未启动。

| 已确认水平几何 | A 下划线 | B 底板 | C 主题色块 |
| --- | --- | --- | --- |
| 单项左右内边距 | 各 8px | 各 8px | 各 8px，另预留边框空间 |
| 项间距 | 8px | 底板内 2px | 8px |

圆角和内缩复用现有几何档位，不随 Hover、Selected 或 Focus 改变。此次只确认水平几何，不把各 8px 擅自覆盖到尚待核对的纵向布局；相同 size 保证共同高度、文字与图标配方，不要求三种外观总宽相等。B 的底板内缩不应缩小布局分配给该项的有效交互区域；紧凑尺寸的触摸适配仍需单独核对。

| 状态 | A 下划线 | B 底板 | C 主题色块 |
| --- | --- | --- | --- |
| 未选普通 | 中性文字、透明底 | 中性文字、底板透出 | 浅灰文字、很浅中性填充、无可见边 |

| 未选 Pressed | 文字进一步加深 | 中性反馈略增强 | 中性反馈略增强，仍不冒充选中 |

复合态按职责叠加：Selected 表达当前内容，Disabled 阻止交互反馈和新的激活，Focus 仅表示实际键盘位置。不要把整项统一降低透明度；分别处理 Label、Icon、Count，避免同时抹掉当前项标记。禁用项不因状态展示新增可聚焦行为，真实焦点在禁用变化时的交接仍需验证。

本轮状态示意使用 A/B 的 `Text/Neutral/3 → /2 → /1` 中性内容候选；C 未选仍保留 `/4` 浅灰探索，并提供 `/3` 合格对照。C 未选 Hover / Pressed 的填充候选为 `Fill/Neutral/Alpha/5 → /4`，选中 Hover / Pressed 的边框候选为 `Border/Brand/2 → /1`。这些新组合尚未完成完整颜色测量与消费资格验证；改变 Hover 不能补救普通态 `/4` 的资格问题，前节的未决结论继续有效。

全局 Focus 为现有 1px 品牌轮廓与 3px Alpha 外环；不计入组件高度，B 底板和 More / Scroll 裁切不得遮掉它。当前状态图是静态视觉比较，可切换共同尺寸及已选复合态；不运行 Panel、真实键盘或 More，也不充当无障碍或运行验收。

## 4. 内容与交互合同

### 4.1 已确认面板默认

首次激活 Panel 时创建，之后隐藏而不卸载。manual 模式仅移动 Tab 焦点不算访问；auto 模式 Tab 因聚焦而激活时算访问；浏览 More 菜单本身始终不算访问。隐藏内容不参与可访问树和键盘顺序。标识稳定、父级未重置时，不因普通标签切换主动清空面板内部输入和筛选状态。

建议允许按具体 Panel 选择“提前创建并保留”或“离开后卸载”，使用一个明确策略，避免多个布尔开关产生冲突；最终 API 拼写待技术适配时确定。

保留组件不等于保存业务数据：

- URL、缓存、请求刷新、权限和未保存提醒由页面拥有。
- 媒体、轮询与计时器由页面根据激活状态暂停或恢复。
- 内部滚动可随面板保留；整页滚动、虚拟列表与内容变化后的定位由实际场景验证。
- 页面刷新、离开页面、业务标识变化或父级重建不承诺自动恢复。同一业务 key 的条目对象因数据更新重新创建，不应清空面板状态。
- 分区真实删除会释放对应面板；More 收纳只改变展示，不等于删除，不应丢失已访问状态。

### 4.2 键盘与状态建议

点击或触摸可用 Tab 直接选择；键盘支持方向键、Home / End、禁用跳过及正常 Tab 离开。横向不拦截上下键，纵向使用上下键。多实例和嵌套只处理各自所属列表的事件。

保留自动与手动两种键盘激活。**已确认常规默认 manual：方向键移动焦点，Enter / Space 切换面板。**2026-09-10 用户明确选择“方向键定位，Enter／Space 切换（推荐）”。手动方式减少路过标签时的意外创建；明确能即时呈现的场景可用 auto。此次选择明确更新了旧版默认 auto 的行为，鼠标点击仍直接切换；设计确认不等于运行验证完成。

默认流程中，各外观的选中标记跟随已选项，Focus 跟随键盘位置；Line 的标记为蓝色指示线。方向键定位另一项时，原面板保持显示，未访问面板不创建；确认且选中值被接受后，选中标记和面板一起更新，首次激活才创建内容。返回已访问项继续使用原实例；More 中移动菜单焦点也不提前创建面板。

状态至少区分 Default、Hover、Pressed、Focused、Selected、Disabled，以及 Selected + Focused / Disabled 的组合。Disabled 不接受新的激活；受控 owner 可以保留明确的已选禁用状态，仍需给出清晰反馈。

### 4.3 值与动态分区

受控模式只有一个值来源，Tabs 发出用户选择意图，宿主决定接受；不擅自改写父级值。非受控缺省取首个可用项；选中项移除或变为不可用时建议回退首个可用项，全无可用项时为无选择。受控无效值需明确诊断及宿主处理约定，不能制造两套真值。

面板 key 在同一 Root 内稳定唯一；不同 Root 可使用相同业务 value，DOM 关联 ID 仍必须全局唯一。空列表、全禁用、数据切换、外部更新与动态移除焦点项进入验证；界面提示由页面或约定空内容位置提供。

## 5. 溢出与焦点

已确认水平默认 More、Scroll 可选；**More 选中新项后显示原始序列中包含它的连续一段**。2026-09-10 用户明确选择“显示相邻的一段，随当前项移动（推荐）”。例如原顺序为“概览、学生、课堂、作业、讨论、设置”，只能显示三项时，从 More 选中“讨论”，呈现“课堂、作业、讨论”；其余“概览、学生、设置”按原序留在 More。该例只表达连续区间规则，实际显示项数由内容宽度决定。

该选择明确采用连续可见区间，未采用“固定前几项、末尾换入当前项”的旧版分配方式；不修改业务数组顺序。它只确认呈现策略，精确宽度、焦点交接和下述细节仍需实现验证。

建议只有目标不在可见区或空间变化时才调整区间，并尽量少移动；目标已经可见时不因切换重新居中。以下为实现应验证的设计建议：

- 使用实际图标、Label、Count 与当前字重测量，完整计入最后 Tab 到 More 的间距及两端操作区。
- More 中选择获宿主接受后，更新连续可见区间、对应外观的选中标记与 Panel；取消选择不能提前替换内容或创建面板。
- 外部切换选中项时显露选中项，键盘移动时显露焦点项。手动模式不因为焦点改变而替换面板；不承诺任何窄度下两个不同项同时可见。方向键继续沿完整原序定位可用项，不只在当前可见子集循环。
- 容器缩放或数量变化不改变选中值、不主动抢焦点。焦点在 Tab 内时优先保住并显露该项，否则显露已选项；菜单打开时保持当前菜单焦点，不能因重测直接移除它。菜单关闭后再按选择和焦点归属协调显露。
- 超长单项先限制可见宽度并省略 Label，不因原始全文过长而永远藏入 More。容不下一个可辨识 Tab 和 More 时，建议降为滚动；保持字号和点击区域。纵向首版建议使用滚动，不承诺四方向 More。
- More 复用已建公共菜单的关闭、定位和焦点能力；Escape 回到 More，选择后交接给新 Tab，Tab 离开和外部点击保持合理的外部焦点。
- 收纳不应破坏 Tab 与 Panel 的关联，也不能制造重复 ID 或同时可聚焦的同值 Tab。菜单条目本身不能简单替代 tab 语义；More 与底层 Tab 注册关系、已访问隐藏 Panel 的引用及极窄模式切换必须先用小样验证。

## 6. 实现方向与开放组合

优先验证已安装的 Base UI 1.8.0 Tabs，复用现有 DropdownMenu。原 [ADR 0005](../adr/0005-headless-base.md) 没有覆盖 Tabs 选择；技术验证后再记录适用范围，不新增另一套焦点或弹层控制器。

候选公开结构为 Root / List / Tab / Panel，视觉 Indicator 和测量 Parts 由实现统一管理；是否需要额外公开 Parts 由实际组合决定。无论选择数据式还是 Compound 使用方式，More、可见 Tab 与 Panel 共用同一份值和条目身份；不让消费者维护两份列表或必填重复标签信息。

完整示例为默认入口；正常内容替换和组合通过公开 Parts 完成。开放组合继续共享同一份尺寸、More 与面板策略，不暗中回退为底层库的另一套默认行为；如果某项保证依赖必要结构，应在使用文档明确列出。局部视觉变化遵循 Existing Variant → 具名 Local Recipe → Local Fork。业务请求、保存、路由实现及工作区增删不进入基础 Tabs。

## 7. 验证与交付边界

实施后需建立所有确认尺寸 × 三种外观的完整矩阵，并明确各方向与交互状态的适用组合；用第 2 节三个场景及带未保存输入的 Panel 验证：

- 多 Root 同名值、嵌套、ARIA 关联、键盘与隐藏面板不误聚焦。
- 首次创建、访问后保留、可选销毁、业务标识变化、同 key 条目对象重建仍保留、受控取消和动态回退。
- 四种内容组合、0 / 未提供数量、长标题、计数变化、真实图标、普通列表与 More 的禁用/选中状态、字体加载、Resize、外部值更新、More 连续区间显露与极窄降级。
- 菜单在滚动区域与视口边缘的定位、外部关闭、Escape 和 Tab 交接。
- 四向的视觉与键盘阅读顺序；不对称前后操作下的居中；较高操作与两条线对齐；纵向宽度、长操作及窄容器独立行布局。
- 全局 Focus、Token 使用、200% 缩放、主题、Reduced Motion；真实辅助技术验收独立记录。
