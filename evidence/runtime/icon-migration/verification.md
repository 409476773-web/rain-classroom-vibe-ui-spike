## 验证中发现并处理的问题

1. Figma 撤销/重做源为空：保留准确错误、蒙版结构及原始透明 PNG；没有修改 Figma，也没有把其他图形补进去。
2. 少见 SVG 的 use/CSS/外联机制可能绕过单色判断：补充针对性失败测试；不能可靠分析的绘制机制需明确复核，未支持的活动/外联结构直接诊断。全量原始导出通过这些检查，无需改写源 SVG。
3. 目录对不可用资产的 nullable 引用处理：先观察缺少待修复筛选和搜索异常，再修复；不可用项不显示或复制空 import。
4. 完整图库进入主页面初始包：先验证总览仍请求图库，再改为仅在 #icons 路由加载。主 JS 约 265kB，图库独立块约 2.03MB；图库本身仍有构建体积提示，其他页面不提前加载它。
5. 生产构建会将小图片内联为 data URL：浏览器测试改为核对真实解码与原始 PNG 字节，不依赖开发服务器路径字符串。
6. 旧 Button 来源测试锁定 27px 紧裁切文件：更新为本次同源 72px 标准画布文件及真实 SHA-256，保留宿主可见尺寸补偿。
7. 强制配色下 Button loading 消失：新增像素用例先失败（可见墨迹比例为 0），最小样式修复后通过。
8. 原测试发现规则会扫描 workspace 依赖软链，造成重复计数：仅排除 **/node_modules/**，未删除真实源码测试。最终 426 项为唯一源码结果；不把此前 488/773 的混合计数与其作覆盖率比较。
9. 独立临时消费构建与治理扫描并行时触发一次严格路径拒绝：将临时构建移到已有忽略的依赖缓存并在 finally 清理，未放宽应用源码门禁；完整质量门随后通过。
