## Authorization and delivered behavior

The user instructed: “选中卡片描边，使用当前token中的主题色系border。所有icon都要使用现有icon库的icon。继续推进下一步”. The [SC-00 audit](../../../docs/audits/2026-09-09-selection-sc00-preflight.md) and [implementation plan](../../../docs/plans/2026-09-09-checkbox-sc01-implementation.md) bound this checkpoint to Checkbox / CheckboxGroup, descriptions and native forms.

- Native checkbox input and label, boolean selection, controlled/default APIs, separate description, DOM indeterminate and mixed ARIA state. Both check and minus use the existing library icons at 10px.
- Complete fieldset/legend group, stable unique string values, horizontal wrapping or vertical layout, disabled items, help and validation presentation. The model retains disabled and non-rendered selected values; native FormData includes only named, enabled, rendered checked inputs.
- Default reset follows the currently associated form, restores immediate native FormData and React state without a selection callback, and honors cancellation. Controlled owners restore their own state after an uncanceled reset; immediate synchronous FormData is not promised before the owner commits.
- Group required is a hint. The example host validates at least one selected value and focuses an enabled item. It does not mark every checkbox required.
- A working [preview](http://127.0.0.1:4173/#checkbox) shows labels, mixed/disabled states, reset, FormData, validation, long text and empty options.

Future selected cards retain the user's current-theme **Border/Brand/1** decision. This checkpoint adds no cards, Radio, preview action, conditional panel or check-all pattern. No new dependency, global Token value change, business migration, Figma write, publication or Git action was performed.
