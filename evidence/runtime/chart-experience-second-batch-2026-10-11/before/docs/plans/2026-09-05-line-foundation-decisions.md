# Rain Next 线条基础与公共能力：阶段性设计决定

## 状态与目标

- 日期：2026-09-05。
- 状态：下列原则及 [V1 建设设计](2026-09-05-line-foundation-v1-design.md)的 D1–D3 已通过当前对话确认，实现未启动。
- 目标：支持 AI 在 vibe coding / vibe design 中快速选择、复用和局部重组线条表达，同时保留 Rain 视觉与组件行为边界。
- 本记录只保存讨论决定，不新增运行中的 Token、Tailwind utility、组件、图形系统或发布能力，不改变现有阶段与验收状态。

## 已确认原则

### 1. 公共能力的范围大于公共 Token

公共性表示可复用范围；Token、组件、配方、绘制与计算工具分别承担不同职责。

箭头、端点符号、路径形态、线上标识、几何和数据映射都有成为公共能力的可能。是否建设，应依据真实消费者和稳定需求，不预先建设完整公共图形系统。

“图形相关能力”不是已经批准新增的固定架构层级；其中仍可包含基础规格、公共部件和业务专用实现。

### 2. 公共粗细与绘制方式分开

- 前期将 1–6px 作为公共粗细候选；现已在 V1 中确认 `Line/Thickness/1…6`，采用固定 CSS px，并明确 border/h/w 三类消费入口，详见第 7 节及 V1 建设文档。
- 合适的描边、横向填充条、竖向填充条可以共享粗细规格，由部件决定将其应用到边框厚度、条形高度、条形宽度等位置。
- 共享尺寸选择不要求不同部件共享默认档位或同步调整；改变 Tab 默认粗细，应调整 Tab 的选择，不扩大为所有同尺寸部件的变化。
- 路径几何和数据映射不受 1–6px 全局上限约束。是否使用公共档位取决于尺寸来源与用途，不按描边／填充、等宽／变宽一刀切。

### 3. 虚线先统一基础选择与同类默认

用户在了解成熟组件库处理方式后确认：“确定，按你建议的处理。”对应决定为：

1. 普通 UI 优先讨论实线、虚线的基础选择及其粗细、颜色；点线保留为候选，不自动纳入首批建设。
2. 同一种用途通过组件或配方复用默认表现，避免 AI 每次自行重新搭配。
3. 不给所有虚线绑定统一业务含义，不要求不同用途采用同一节奏。
4. 暂不新增全局虚线长度／间隔档位。
5. 当图表、拓扑或明确品牌表达需要精确节奏时，再按场景定义可复用的长度、间隔与端点规则。
6. 普通 UI 暂时接受原生虚线的渲染差异；如具体场景要求设计稿与网页每段严格对应，再选择可精确控制的实现。

基础样式选项可以公开，但每个选项不必都成为独立全局 Token。

### 4. 沿用 Rain 与 Tailwind 的职责

Rain Token 提供公共视觉规格；Tailwind 提供受约束的样式和布局组合入口；组件与配方决定部位、状态和默认搭配。路径生成、分叉布局及数据映射由对应能力负责。

颜色、间距、圆角等优先复用已有体系。公共颜色的设计方向依照最新颜色治理，不恢复“所有公共选色必须经过全局 Semantic”的旧前提；该颜色方向与当前运行实现仍须区分。

本记录不开放尚未登记的 Tailwind 写法，也不表示现有试点检查已经覆盖所有页面或线条表达。

### 5. 基础内容分隔线的端点与圆角边界

- 基础内容分隔线默认采用平直端点，首批不将端点样式作为独立可调参数；原生虚线仍遵循第 3 节的处理方式。
- 容器圆角由容器及既有 Radius 体系管理，不属于独立分隔线参数。
- 当前直线分隔场景不涉及路径转角；折线拐弯处的处理由对应路径组件或绘制能力管理。
- 此范围仅针对基础内容分隔线。标题强调条、Tab 指示条的圆头需求继续保留，在各自设计中明确端部表现。

本节原始确认仅覆盖端点与圆角职责。后续 V1 已确认一个内容分隔试点配方，仍不表示完整公共 Divider 的默认数值或公共接口已定稿。

### 6. 标题标记与 Tab 指示条的共享边界

- 圆头标题标记优先复用既有圆角能力；普通填充条可使用现有 `full` 圆角，不另建重复的线端点圆角数值。
- 长度与对齐作为配方规则，由配方给出默认关系、布局负责实现；具体长度、间距及调整范围尚待确定。
- 标题标记和 Tab 指示条分别拥有自己的默认行为，共享基础材料不要求统一定位、长度或状态规则。
- 是否抽出独立公共标记部件，待两类真实消费者的需求明确后再决定，不在本次确认中预设公共组件或接口。

### 7. V1 建设设计确认

2026-09-05 用户先要求“研究与原则讨论已足够，进入 V1 建设文档收敛”，在文档交付后回复“确定”，确认以下三项：

- D1：公共身份为 `Line/Thickness/1…6`，采用 1–6 CSS px，不随密度或字号改值。
- D2：border/h/w 三类静态 Tailwind 消费入口共 18 个，不并入 Spacing。
- D3：增量建设公共规格与桥接，用一个 1px 轻量内容分隔试点配方与基础对照验证，不自动迁移现有组件。

完整命名、配方、消费与验证合同见 [V1 建设文档](2026-09-05-line-foundation-v1-design.md)。本次确认形成实施设计依据，运行实现仍未启动。

## 延期事项

更多粗细、点线、精确虚线、单侧边框入口、标题标记与 Tab 完整配方、独立公共 Marker、图形能力、全库迁移及 Figma 接入，按 V1 文档 §10.2 的真实需求触发条件处理，不阻塞公共粗细的首版建设。
