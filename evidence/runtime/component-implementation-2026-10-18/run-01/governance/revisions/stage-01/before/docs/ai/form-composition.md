# 多分区表单：使用与改造

身份：BM-B 页面局部组合，local-experiment。已有接受仅覆盖 2026-09-15 的 BM-B 运行视觉；没有公共 Template、全组件对比度或新页面接受。指南提炼关系，不扩大原确认。

## 何时参考

编辑一个对象，字段按任务分组，最终统一保存，用户需要随时检查和退出。若主要是连续批改、浏览多个对象或比较趋势，应选择相应工作区；极短的两三个字段也不需要复制四个分区。

先看 [桌面参考](../../evidence/runtime/design-knowledge/form-desktop.png)和[窄屏参考](../../evidence/runtime/design-knowledge/form-narrow.png)，再读 [组合源码](../../apps/prototype/src/scenarios/bm-b/page.tsx)、[局部样式](../../apps/prototype/src/scenarios/bm-b/page.css)及[状态合同](../../apps/prototype/src/scenarios/bm-b/state-contract.md)。图片为 2026-09-16 对当前 BM-B 的参考取景，不是新增验收。布局切换是预览工具，底栏浅色提示有未关闭的对比度问题，均不应机械复制。

## 保持的关系与反例

| 条件 | 设计判断 | 实现与检查 |
| --- | --- | --- |
| 字段属于不同填写任务 | 以语义分区组织；一个分区可含多个字段 | section + 标题 + Stack，不给每个字段套 Card |
| 同组短字段能并列阅读 | 宽屏可用两列，按实际可用宽度回到一列 | 复用 Grid；标签、错误、长值出现后仍不挤压 |
| 持续阅读或输入长内容 | 给充分宽度，优先独占一行；相邻短说明才比较并列 | 不因统一两列把长叙述压窄；Textarea 复用完整方案 |
| 正文超过可用高度 | 保持标题上下文和主要操作可见，让正文滚动 | 复用 Dialog.Header/Body/Footer；极矮窗口沿用 Dialog 退化 |
| 明确提交或退出 | 一个主要保存动作、一个次要取消动作，关闭含义一致 | 底栏关联同一个 form；脏草稿退出进入放弃确认 |
| 保存、校验或附件失败 | 错误靠近问题，保留草稿，提供实际恢复路径 | FormItem 关联字段错误；保存失败可重试；不清空表单 |
| 容器变窄 | 重排头部、字段和操作，保持完整文案与点击区 | 先改布局，不缩小控件；滚动到底仍能保存/取消 |

尺寸参考：当前 BM-B 滚动底面外留白 12px、分区内留白 20px、分区间距 12px、圆角 8px，均属于该组合的 Local Recipe。Header/Footer 沿用 Dialog，布局控件另有局部间距。不要把这些值覆盖到所有 Dialog、Checkbox 或表单。

来源：[分区表面确认](../../evidence/runtime/bm-b-rn10/section-surfaces-2026-09-15.md)、[头部与提示确认及限制](../../evidence/runtime/bm-b-rn10/header-hint-2026-09-15.md)。静态提示的 3.71:1 保持待审查；新页面的帮助、状态和错误应按文字用途及背景选择可读颜色，不继承这项不足。

## 可以改什么

- 按任务增删分区、调整顺序；没有附件需求就删除附件区及状态，不复制模拟上传。
- 调整短字段组合、长内容宽度和容器档位；容器窄不等于全局 compact。
- 替换标签、必填项、数据与校验，保留可访问关联和第一处错误定位。
- 主操作文案描述实际结果。宽窄/单双列等演示开关归入预览工具，通常不进入业务流程。
- 仅查看信息且没有提交任务时，使用信息布局，不保留无意义的 Footer 或保存按钮。

## 改布局时保留状态

宿主持有已保存值和独立草稿。打开时复制已保存值；取消未修改内容可直接退出；脏草稿明确放弃才丢弃；失败保留内容；保存中防重复提交与意外退出；成功更新宿主并恢复焦点。迟到的异步结果不能覆盖更新数据或已关闭任务。

若宿主有页面内导航或历史记录，也要检查浏览器前进/后退。关闭 Dialog、刷新页面和同文档路由离开是不同出口；只监听 beforeunload 不能保护全部路径。离开确认继续使用宿主的同一份草稿与放弃判断。

使用 [FormItem](../../manifests/ui/form-item.yaml)、[Input](../../manifests/ui/input.yaml)、[Textarea](../../manifests/ui/textarea.yaml)、[Select](../../manifests/ui/select.yaml) 的既有语义；Dialog 处理浮层/焦点，页面处理业务。先读完整 API，不推测 FormItem 会替所有原生输入处理全部校验。

## 新页面的首稿检查

1. 解释每个分区为什么存在，删除示例残留字段和演示控制。
2. 查看宽屏及约 390px 窗口：长输入、错误、下拉与底栏无截断，无不必要整页横向滚动。
3. 操作一次有效保存、空必填校验、失败重试和未保存退出；Escape 逐层关闭并恢复焦点。有页面内导航时，另测浏览器前进/后退不会无提示丢稿。
4. 保留首次画面和修订，分别记录结构/语义、视觉自查、行为检查和用户接受，不以测试数量代替首稿评价。
