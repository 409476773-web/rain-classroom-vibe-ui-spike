# 作业质量复核与范围明确的批量处理

为教研员做一个作业质量复核页。有一组有限的本地作业记录，每条包括课程、类型、待处理问题数、复核状态和最后更新时间。可以按课程和状态筛选、切换列表与卡片视图，并在不同筛选下保留已选对象。批量“标为已复核”前必须看清将处理的对象数、其中被当前筛选隐藏的数量及只读不可处理项。模拟一次批量失败，选择和原记录保留，可重试。页头展示本批复核进度和问题分布，分母明确；无数据与有效 0 分开。用有限合成数据，不实现服务器全集选择。窄窗口可用，真实链接或查看详情的行为与批量勾选分开。

本例明确规则：本地完整集合固定为 data.json 的 12 条；课程/状态筛选不清空选中 ID，列表和卡片共用业务数据。批量执行前明确展示选中总数、当前筛选隐藏数、可处理数与不可处理数；只读和已复核项不重复处理。只读项可以禁止选择，也可以在审阅中选中后明确排除执行。第一次有效批量保存模拟失败，重试才更新符合资格的对象；失败不清选择。进度分母为全部有限记录数，问题分布按明确口径计算；problemCount 为 null 表示未统计，0 表示已统计且无问题，不能混同。详情操作不改变批量选择。

执行与留存要求：
- 只读取本次提供的冻结 Starter、此条需求及 data.json；设计与消费方法从 Starter 自带入口读取。不得读取原仓库、其他消费者、评估答案或实施工作包。
- 写任何业务代码前，先提交首次选型记录：assetId/真实 entry、使用意图、可替代方案及条件、各状态 owner、局部可改面、保留合同、实际已读文件。未找到可用能力可以明确 no-match，不猜 API。
- 首次代码写完、第一次编译前留存 T0；第一次类型检查和构建成功且路由挂载无阻断错误即留存 F0，不能等全部交互修好后补记。自查与修正另存，不覆盖首次记录。
- 只能改当前场景、本地组合和必要应用入口；不得改共享 packages、锁文件、指南、方法、source-lock 或另一场景。需要共享修复时报告具体失败和证据，交回系统任务。保留 StrictMode。
- 使用合成数据与本地模拟。记录实际运行命令、失败、读取文件和未测范围，不自行填写人工接受。
