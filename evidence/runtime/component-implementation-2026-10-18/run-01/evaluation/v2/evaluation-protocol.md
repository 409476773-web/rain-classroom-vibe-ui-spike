# A01 冻结评测协议 v2

此目录为评估侧材料，不能整体交给消费者。冻结规模为 12 个公开校准题、3 个独立端到端需求及 6 次结构改造。A01 只冻结协议与输入；尚未运行 CAL、A02 或 A03。无 A/B，本批只报告案例、实际分子/分母与限制，不证明通用成功率或提效百分比。

## 权威与门槛

用户当前指令与实际仓库合同优先。每题分别评六项：意图/范围、真实入口、替代条件、状态 owner、改造面、保留合同；证据读取另列。适用项全部正确且无硬失败才计“合理”，部分正确不计入合理分子。公开校准需至少 10/12 合理且硬失败为 0；不能观察结果后降低门槛或用删题自动过门。允许真实且语义正确的等价方案、合理 no-match 和本地组合，不以组件名唯一匹配。

硬失败：不存在公共 API、必需上下文缺失、重复状态 owner、对象混淆、草稿/选择错误丢失、关键操作不可达、越界修改共享包/锁。F0 的错误永久保留；R1/E2 的正确不能倒算首稿正确。三例最终须完成全部必需流程，六次改造须达成意图及非目标保持。记录齐全可称评估完成，硬合同仍错不能称开发目标通过。

## 只允许的输入与快照

A02 必须在 C01–C03 完成后重新生成、导出、检查最终 M1，并把 finalConsumerSnapshotId、source-lock、guide/Skill、完整允许输入文件清单和哈希写入独立的启动绑定记录。A01 当前不预填未来快照。M2 仍由 S01 独立验证，其额外 BM-C/D 不自动进入本轮三例的输入。G1、G3 与最终包分别标识；只有最终包的结果可支持最终交付。

每例独立代理使用 fork_turns none；初始只给最终 M1 Starter、对应 E0.md 和 data.json。不得给此协议全文、评分表、未来 E1/E2、原工作包、父聊天、CAL 答案或其他消费者。当前可见 BM-A/B 与组合例子的重叠已在 novelty-review 登记；最终导出若增减示例，启动前补绑定和新颖性复核，不静默改题。

新上下文不等于 OS 文件隔离或统计盲测；记录实际完整派发提示、初始材料、读取文件、工具/模型可见设置及未知项。仅未粘贴答案不构成无污染证明。污染保留并标 contaminated；重题调优后只能算回归，新能力复测需要新端到端题。

## 版本封存

- 首次写代码之前，由消费者给出 selection-first.json；整合者先封存哈希，再允许业务代码写入。
- T0 是第一次代码完成、首轮编译前的场景与入口快照；保留首次编译失败及每次修正记录。
- F0 是首次 typecheck/build 完成、路由可挂载且无阻断页面错误的版本，即使部分交互仍失败也立刻封存。
- S1 是一次自查批次；R1 是独立技术纠正形成的可用基线。没有修正也记录 no-change 和同源哈希，不能省略或覆盖 F0。
- E1 和 E2 按被冻结的顺序派发，首稿时不读取；每轮记录本轮改动与未改兄弟对象、状态/DOM/截图对照。

各版本目录创建前必须不存在；复制允许的场景文件与应用入口，保存路径排序的 SHA-256 清单、整树哈希、共享 packages/锁/指南/方法/source-lock 哈希、命令结果及截图绑定。封存目录不得复用；失败快照也不得删除。共享包在消费前后必须相同；消费代理若发现系统问题，交回对应系统任务重新冻结包，保留旧结果和新比较范围。

## 预算与修正归因

按 protocol.json 预登记：F0 最多 90 活跃分钟及 5 次编译修正；一次 S1 自查；最多两批 R1 外部技术纠正；每次结构改造最多 45 活跃分钟及两批技术纠正。安装、环境修复、用户等待单列。耗尽即保留失败与最后版本；继续完成用户授权修复时标 remediation，不能重启抹去失败。tokens/费用无真实计量填 null。

改选或修正触发者分为编译、自查、独立技术、用户视觉、需求变更、环境修正。先归因运行组件、合同/入口、生成者误用、题意或环境；有系统证据才回流修库。校准可用于改进指南，但对最终包有改动必须重导出并重新绑定；不得将旧包评测拼接为新包通过。

calibration/prompts.json 是公开题，evaluator-rubric.json 是评估侧答案。independent/EVAL-*/E0.md + data.json 是首稿输入；E1/E2 仅对应阶段派发。evaluator/* 不进入 Starter。record-template.json 和 evaluation-record.schema.json 只定义记录，无结果预填。frozen-manifest.json 固定全部冻结文件；verify-a01.mjs 会核对哈希、数量、数据覆盖和记录结构。

冻结内容改变时新增 v2 目录与新 seal，保留 v1 和已运行结果；不得重新计算旧 seal 来掩盖变化。A01 后续验证日志与任务结果不是冻结题目的一部分。
