# 跨题复评队列与连续评分

为教师做一个复评工作台。左侧按题目组织待复评队列，中间显示当前学生作答、原分与复评原因，评分区允许输入新分和说明。复评分 0 合法；每个作答有自己的草稿。可以切换题目和学生而不串草稿，保存失败保留新分与说明；保存成功后队列更新，但不能无理由跳到另一个对象。可以筛选“未处理/全部”，并显示每个范围的真实数量。另有一份可查看的评分参考；查看参考不应提交评分。处理长作答与窄窗口，不接真实服务。

本例明确规则：按 answerId 保存草稿，分数允许 0 至题目 maxScore（含 0.5 分步长），复评说明必填。每次显式保存只提交当前作答；第一次保存 answer-01 模拟失败，重试可成功。成功后当前对象继续可见并标明已处理；即使“未处理”筛选不再包含它，也不得无理由跳到另一作答。必须显式“下一份”或选择对象才继续。查看参考不提交评分；不同题目与作答的草稿互不覆盖，数量按实际筛选范围计算。

执行与留存要求：
- 只读取本次提供的冻结 Starter、此条需求及 data.json；设计与消费方法从 Starter 自带入口读取。不得读取原仓库、其他消费者、评估答案或实施工作包。
- 写任何业务代码前，先提交首次选型记录：assetId/真实 entry、使用意图、可替代方案及条件、各状态 owner、局部可改面、保留合同、实际已读文件。未找到可用能力可以明确 no-match，不猜 API。
- 首次代码写完、第一次编译前留存 T0；第一次类型检查和构建成功且路由挂载无阻断错误即留存 F0，不能等全部交互修好后补记。自查与修正另存，不覆盖首次记录。
- 只能改当前场景、本地组合和必要应用入口；不得改共享 packages、锁文件、指南、方法、source-lock 或另一场景。需要共享修复时报告具体失败和证据，交回系统任务。保留 StrictMode。
- 使用合成数据与本地模拟。记录实际运行命令、失败、读取文件和未测范围，不自行填写人工接受。
