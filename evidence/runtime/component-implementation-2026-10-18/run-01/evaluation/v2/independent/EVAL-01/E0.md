# 课程资源准备与发布前检查

为教师做一个课程资源准备页。课程有多个教学单元，每单元列资源标题、类型、当前版本、准备状态与必要说明。教师先选择一个单元，为其中的未就绪资源补说明或附件，再运行发布前检查；检查失败能定位具体资源，修复后才能把当前单元保存为可用状态。已保存快照和正在编辑的草稿分开；模拟一次保存失败，草稿保留并可重试。切换单元后能恢复各单元未保存内容。需要处理很长的中文标题，窄窗口仍能检查和保存。保留“预览资源”独立操作，不让预览自动选中或提交。用合成数据，至少含一个无问题单元、一个缺资料单元和一个长内容单元。

本例明确规则：所有单元、资源、附件使用给定稳定 ID。检查以当前单元当前草稿为准，缺必要说明或附件均能定位具体资源；只有检查通过才允许保存。已保存快照仅在保存成功时更新。首次对 unit-needs 的有效保存模拟失败，再次可成功；切换单元保留各自草稿，取消预览不产生提交。预览内容可以用给定摘要，不需要真实文件服务器。

执行与留存要求：
- 只读取本次提供的冻结 Starter、此条需求及 data.json；设计与消费方法从 Starter 自带入口读取。不得读取原仓库、其他消费者、评估答案或实施工作包。
- 写任何业务代码前，先提交首次选型记录：assetId/真实 entry、使用意图、可替代方案及条件、各状态 owner、局部可改面、保留合同、实际已读文件。未找到可用能力可以明确 no-match，不猜 API。
- 首次代码写完、第一次编译前留存 T0；第一次类型检查和构建成功且路由挂载无阻断错误即留存 F0，不能等全部交互修好后补记。自查与修正另存，不覆盖首次记录。
- 只能改当前场景、本地组合和必要应用入口；不得改共享 packages、锁文件、指南、方法、source-lock 或另一场景。需要共享修复时报告具体失败和证据，交回系统任务。保留 StrictMode。
- 使用合成数据与本地模拟。记录实际运行命令、失败、读取文件和未测范围，不自行填写人工接受。
