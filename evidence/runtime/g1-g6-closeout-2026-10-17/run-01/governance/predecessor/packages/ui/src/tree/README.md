# Tree (Rain Next)

`Tree` is the UI-layer tree. It owns the visible hierarchy, row focus, expansion, row selection, checkbox state, search projection, branch loading feedback, relation lines and move proposals. The caller owns `data` and applies loaded children or moves to that authoritative data. `ManageTree` is a separate Pattern.

```tsx
import { Tree } from "@rain-next/ui";

<Tree data={nodes} defaultExpandedKeys={["chapter"]} showLine />
```

- `data`: nested, immutable `TreeNodeRecord[]`. Keys are unique `string | number`; `1` and `"1"` are distinct. A branch with unknown children uses `canHaveChildren: true, childrenComplete: false`. A loaded empty branch uses `canHaveChildren: true, childrenComplete: true, children: []`. A true leaf has no expander and cannot receive an inside move.
- `variant="basic" | "rich"`, `density="compact" | "default"`, `richSpacing={8 | 10 | 12}`. Basic rows are 36/44px and truncate titles; Rich grows with content. Depth always adds 24px.
- `showLine` defaults to `false`; `lineStyle="solid" | "dotted"`. All horizontal arms are 12px. Every ancestor guide continues through its visible subtree, including last-child chains, and ends at that subtree's final visible first-line anchor. Separate roots are not linked. Endpoints follow the full visible projection across collapse, filtering, moves and virtual-window boundaries. The geometry is independent of selection, drag and check state.
- `selectionAppearance="full" | "inset"` defaults to full-row selection. Deep trees keep their 24px indentation and scroll horizontally inside the tree; Basic titles expose their full text through the native title attribute.
- `expandedKeys` / `defaultExpandedKeys`, `selectedKeys` / `defaultSelectedKeys`, `checkState` / `defaultCheckState`, and `focusedKey` / `defaultFocusedKey` each have one state owner. A controlled value requires its change callback. `selectionMode` is `none | single | multiple`; the default is single.
- `checkable` defaults to false. `checkMode` is `cascade` or `independent`; `nodeCheckable` is `all | leaf | branch | predicate`. `checkable: false` hides a node checkbox while retaining the checkbox column; `checkDisabled: true` displays its disabled checkbox. Restrictions on a parent do not automatically restrict descendants. `CheckState` keeps direct keys and include/exclude intents so unloaded descendants can inherit a subtree choice. `checkedStrategy` only affects callback result serialization; independent mode requires `exact`.
- `search={{ query, mode: "filter" | "locate", matcher?, matches? }}`. Filter is the default. Filtered rows include matching ancestors and pause dragging; locate leaves the full tree visible. Search changes can expand matching paths; clearing keeps the current expansion state. `matches` accepts known keys for externally computed results, not remote loading.
- `loadChildren` and `onChildrenLoaded` must be supplied together. `loadChildren` returns `{ children, complete: true }`; the callback must merge it into `data` and mark the branch complete. Initially expanded incomplete branches load automatically. Separate branches can load concurrently; each branch waits for the host writeback before allowing another request. `dataRevision` identifies a full data session; stale results are ignored. A failed branch exposes a retry button.
- The `TreeHandle` ref exposes `refresh(key)` and `reveal(key)`. Refresh cancels that branch's pending request and reloads it, including a previously complete branch. Reveal expands known ancestors and focuses the row, returning `not-found`, `not-loaded`, `filtered-out` or `denied` when unsuccessful. It does not fetch an unknown remote path.
- `getScrollAnchor()` returns the first row intersecting the tree's own viewport as `{ key, offset, scrollLeft }`; `restoreScrollAnchor(anchor)` restores that relative position and returns false for an unavailable row or invalid coordinates. `onScrollAnchorChange` reports scrolling. These methods handle the tree viewport, not document-level page scrolling.
- `dragAndDrop={{ onMove, canDrop?, maxDepth?, autoExpand?, autoScroll? }}` enables mouse and keyboard move proposals. Both automatic behaviors default on. Tree never mutates `data` on a drop. `validateTreeMove` and `applyTreeMove` are public pure helpers for a host that wants to apply proposals. An incomplete source subtree or destination sibling list is rejected until loaded; an empty complete branch can receive children. Filtering or disabling drag cancels pending movement and timers. Successful inside moves expand the destination.
- Structural moves preserve the checked membership of existing nodes and the moved branch's previous subtree intent. Aggregated parent checks do not become future-child inclusion. A controlled host receives reconciled checks through `onCheckStateChange` and must accept that snapshot just as it accepts a user check action. A newly disabled node keeps only its own prior value; eligible descendants retain their own rules.
- `virtual={{ height, overscan? }}` requires a positive viewport height and complete, fixed-height Basic rows (default overscan 4). Rich, asynchronous loading, descriptions, metadata, custom renderers, and arbitrary leading/action content are rejected because their heights are unknown. The window keeps an offscreen focused row mounted without pulling manual scrolling back; collapse and filtering clamp obsolete scroll positions.
- `accessors` maps business data while retaining each original object as `node.source`. `renderTitle`, `renderDescription`, `renderLeading`, `renderMeta` and `renderActions` receive `(node, context)`; existing one-argument callbacks remain valid. The shared `TreeRenderContext` provides zero-based depth, expanded/selected/checked/indeterminate/focused flags, per-operation `disabledReasons`, and `actions.toggleExpanded/select/toggleChecked/focus`. Treat node/source and context as read-only snapshots. Retained actions recheck current visibility and permissions; controlled actions emit callbacks and require the host to echo values. Use the actions slot for interactive controls; these are supported in ordinary rendering, not fixed-height virtualization. `onEditRequest` delegates F2 to the host. `aria-label` names the tree, and `className` adds a root class.

`renderEmpty({ reason, query })` replaces the default empty message. `reason` is `empty` when data is empty, or `no-results` when a non-empty tree has no matching rows. Compose existing `Empty` and `Button`; their controls retain normal Tab access. Omit this prop to keep the existing default messages. It also works in virtual mode because it does not change node heights.

Arrow buttons only expand. Row activation only selects. Checkboxes only check. On the focused row, arrows/Home/End navigate; Right enters the first visible child of an already expanded branch. Enter selects, Space checks when available, F6 reaches row controls, Escape returns to the row, and F2 can delegate through `onEditRequest`. Disabled or hidden checkboxes do not make Space select the row instead. There is one row Tab entry; F6 opens that row's controls to Tab navigation. The handle enters keyboard movement with Space/Enter; arrows choose target and placement, Enter confirms, Escape cancels. A deleted focused row falls back to its next sibling, previous sibling, surviving ancestor or first row, without stealing focus from an external search input.

On 2026-09-29 the user accepted the current Tree visual and confirmed foundational completion for Web high-fidelity interactive prototypes, including the companion ManageTree pattern. The component is ready for prototype page use and on-demand maintenance. Idle colors remain pale; the hovered, focused or valid drop-target row receives the reviewed readability enhancement. Actual screen-reader speech, known idle contrast findings and wider-workspace validation remain separate follow-ups; publication and production readiness are not granted.
