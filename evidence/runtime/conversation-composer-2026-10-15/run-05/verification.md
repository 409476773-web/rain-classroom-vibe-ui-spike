# Conversation Composer 第二轮结构与状态优化

2026-10-15 · card-v2 · 用户授权：“按顺序开始优化”。模式为 System Mode 未发布候选增量。

## 本轮实施

1. **结构**：紧凑与展开均使用全宽正文和下方工具行；左侧添加/范围、右侧语音/布局/主动作。展开只增加书写空间；保留同一 textarea、光标、草稿和既有自然增高逻辑。
2. **资料与范围**：课程引用和上传附件共用 Attachment Parts，显示来源、名称、状态和移除；只有已有附件能力提供预览。需处理项按真实 DOM 顺序优先；额外就绪项可收纳，资料区最多 min(192px,30dvh) 并可键盘滚动，正文与主动作在区域外。范围保留原语义和可见标签，降低视觉权重。
3. **选择器与视觉**：整行选中反馈，空初始选择禁止确认，已有引用可以清空后确认。统一资料字重、间距和工具基线，保留 Rain 两种表面、语义色、现有图标和焦点。
4. **语音与动效**：录音/转写沿稳定工具行切换，停止录音与发送共用位置，正文保持可见。显示实际录音时长，不计权限及转写等待；失败/重试保留，丢弃/新录音/切会话清零。180ms 弹层淡入、220ms 资料出现、140ms 局部反馈；减少动效时关闭，正文逐字高度不动画。
5. **完整会话**：保留附件/引用/回复的失败恢复、同身份发送重试、确认后清稿、会话隔离、IME 与 Enter 换行、AI 生成与下一稿分离、原历史阅读与返回最新行为。

第二轮结构修订见设计方案第 15 节；此前紧凑行内工具排列明确被本轮用户授权替代。没有新增公开 API、npm 依赖、Foundation Token 或修改基础行为引擎。

## 本轮发现并修复

初次弹层缩放让搜索框在动画中测得不足 36px，移除了缩放。进一步检查发现确认资料改变锚点时，关闭动画继续保留弹层会产生 ResizeObserver 循环通知。分别检查后改为打开淡入、关闭立即完成；motion-close-check 为 2/2，最终全量 28/28，browser-verified.log 中 ResizeObserver loop 与 Unhandled error 均为 0。早期 browser 和 browser-final 记录保留为调试过程，不是最终验证证据。
