## 已复现并修复的问题

| 对象 | 原问题及原因 | 修正与回归 |
| --- | --- | --- |
| 附件排版 | 标题嵌在绝对定位的 AttachmentTrigger 中，退出正常流，与文件图标重叠 | 标题回到 AttachmentContent，空 Trigger 为同级预览入口，局部 nowrap 保持操作可见。桌面/窄屏旧标题坐标分别 251/47，均小于图标右界要求 283/79；attachment-red 两项失败，attachment-green 两项通过。最终包含长文件名、完整预览、移除与焦点检查 |
| 附件移除 | onRemove 返回 false 时无反馈，看起来没有响应 | 保留附件并显示“移除未完成，请重试。”，下次仍可操作；红/绿单测 |
| 附件预览 | 保存打开时的对象快照，随后权限或 availability 变化不更新 | 按当前附件 ID 与会话 epoch 派生最新对象；权限撤回立即隐藏内容/下载，项移除后关闭。红/绿单测 |
| 附件替换 | 通用组件只查原附件 done，未拦截未解决的 replacement | 组件与宿主共同阻止发送旧资料。当前页面没有替换入口，此项为共享能力边界回归，未新增替换 UI |
| 引用恢复 | 确认失败时的 reviewed 旧记录覆盖新搜索的可用资料 | 新结果替换对应 ID 的旧复核状态，恢复可用后可重新选择；先红后绿 |
| 引用名称 | resolve 的不可用占位名覆盖用户原选项名称 | 不可用时保留原名称快照，并保留服务给出的原因；先红后绿 |
| 引用范围 | 页面拦截空“本次引用资料”，但宿主直接提交入口没有再次检查 | 宿主统一阻止空范围并保稿，不扩大到全课程；红测观察旧实现调用 submit 1 次，修正后拒绝调用 |
| 语音回填 | 文字插入后的下一帧光标恢复没有会话与新文字防护 | 检查挂载状态、会话版本、编辑节点与插入后的文本；切会话/继续编辑后不抢焦点。跨会话及新文字两项红测后转绿，卸载回归原先已通过 |
| 失败发送焦点 | pending 将发送按钮设为原生 disabled，浏览器清掉焦点，失败后难以连续键盘重试 | pending 保持同一按钮，loading/aria-disabled 与表单校验阻止重复激活；外部 disabled/readOnly 仍原生禁用。focus-red 复现 inactive，focus-green 通过 |

## 页面实测与视觉复核

在已打开的 5481 预览实际操作发送失败、取消回复、加号文件选择、上传失败与重试、引用搜索与 Escape。取消回复保留原正文并清旧发送错误；引用搜索不丢临时选择，Escape 放弃临时选择并返回添加按钮。发送失败焦点丢失在实测及独立浏览器均复现后修复。

按 Rain Designer 的局部交互检查，对照“文件图标→名称→移除”“原稿→录音/转写反馈→恢复操作”“临时选择→确认/取消→原稿”的关系。截图初评发现附件重叠后已单独补红测。修正后的桌面/窄屏 send-recovery 和最终 long-attachment 同条件复看：图标在左、名称占独立文字区、关闭在右，无重叠；完整名称可由预览读取。录音保留状态在窄屏正常换行，重试与丢弃仍可操作。该复核是本地自查，不是用户视觉或对比度验收。
