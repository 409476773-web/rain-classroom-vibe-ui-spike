更新日期：2026-10-01。持续记录组件、局部模块和完整页面中的设计经验，供人和 AI 在后续任务中查找、应用、检验与补充。保留现有文件路径，方便已有入口继续找到本文。

**记录重点：怎么配色与搭配样式，怎么改造组件，怎么组织版式与层级，怎么结合功能与装饰，以及怎么为不同信息选择清楚、有辨识度且有设计感的表达。**

经验以“条件 → 做法 → 原因 → 可变部分 → 检查 → 案例依据”组织。方法可以继续修订、组合或产生新分支；不要求未来设计都沿用报告页的外观。报告页是首批案例之一，后续组件和页面同样可以贡献经验。

## AI 使用入口

1. **设计前读取：** 先读方法索引，按任务、信息类型和视觉问题选择相关条目，再核对当前项目组件、Token 与用户要求。无需把整本文档和全部案例都加载进上下文。
2. **设计时应用：** 在任务的设计记录中写明“方法编号 / 为什么适合 / 如何搭配 / 本次改变什么 / 怎样检查”。这些记录不放进业务界面。没有合适条目时可以提出新方案，并标为待验证经验。
3. **完成后检查：** 依据所选方法查看真实组件或整页，以及长内容、窄容器和必要交互状态。记录实际观察和用户反馈，不用“读过文档”代替效果验证。
4. **形成新经验后回写：** 将有具体做法或适用边界的发现合并到对应条目；新的方法新增编号。无新发现时不为更新而追加。来源、确认范围和反例一并保留。

当前任务的明确要求优先。本文提供设计方法；当前组件合同决定可用能力；当前项目的颜色与排版体系决定可用视觉值。证据不足时如实标明，不把参考观察或局部确认写成普遍有效结论。

## 一、视觉表现方法

**统一感来自稳定的关系与风格：共享排版层级、对齐、间距、圆角、图标风格、色彩明度与强调方式；丰富度来自有理由的构图、形态、配色和材质变化。**

### V01 · 用配色家族建立层级与主题辨识

**适用：** 多个主题、对象或信息层需要区分，且需要保持同一品牌气质。关键词：颜色搭配、邻近色、明度、类别色。

| 职责 | 用法 | 检查 |
| --- | --- | --- |
| 建立层级 | 页面画布、章节表面、主题重点区、辅助解读分别采用合适的明度与染色 | 主结果是否比背景、网格和备注更容易被看见 |
| 区分身份 | 同一对象或类型在图形、图例、表格、读数中使用稳定颜色 | 筛选或排序后是否发生身份换色；图例是否需要反复猜测 |
| 表达状态 | 成功、警告、错误、禁用等沿用系统语义 | 装饰颜色是否被误读成业务状态 |

主题色可以与邻近色、协调的辅助色组成家族。不同主题的指标卡、不同对象系列可以使用不同颜色；结合接近的明度、饱和度和材质保持整体协调。类别较多时优先检查实际区分度，再辅以文字、形状或线型，不靠颜色单独传达含义。

颜色的稳定性以“当前关系”界定。一个页面同时存在章节主题色和数据系列色时，图例与标签需说清各自含义，避免同一色标承担相互冲突的解释。

具体搭配时，先分配各类颜色的职责，再从现有色系中选值：

1. 用较安静的画布与阅读表面承接大面积内容；重点主题获得局部染色。
2. 一个主题的背景、图标底板、强调图形可以使用同色相的不同深浅，形成连续关系；文字按用途选择可辨识的色阶。
3. 并列主题可使用邻近色或协调的辅助色，保持相近的材质与视觉重量。例如蓝色与紫色主题卡共享结构，再用图标和浅底区分含义。
4. 较强颜色集中在需要辨认的标记、主操作或重点数据，小面积强调与浅色大面积形成配合。实际比例由内容决定，不硬套固定配色百分比。
5. 检查颜色是否一色多义、是否随筛选换色、是否所有区域都在抢焦点。需要类别区分时，深浅相近的邻近色还应搭配文字、形状或线型。

**可变：** 色相组合、染色面积、明度与饱和度、渐变位置；使用当前项目已有颜色体系。**检查：** 同级主题是否协调、重点是否清楚、类别是否可分、业务状态是否准确。**依据：** S1、S2；具体蓝紫方案只在当前报告获得视觉确认。

### V02 · 组合样式时，保持共同结构并选择差异点

**适用：** 多个卡片、标签、模块既要属于一个系列，又需要各自的辨识度。关键词：样式搭配、家族感、同级同构、丰富度。

- **做法：** 先确定共同的标题位置、圆角、内边距、图标比例和信息顺序，再按主题改变配色、语义图形或局部材质。不同信息角色还可以改变形态，例如数值区用主题卡，说明用内嵌面，精确记录用表格。
- **搭配逻辑：** 重复的结构帮助快速学习，受控的变化帮助区分内容；同角色可以有主题差异，不要求每张卡完全相同。
- **可变：** 同级模块保持共同结构；不同角色可以更换构图。少量重点信息可以丰富，连续高密度区域可以简洁。
- **检查：** 去掉文案后是否仍能认出同一家族；放回文案后是否能看出各自角色；是否只靠随机换色制造差异。
- **依据：** S1 的变化型指标与分组概览、S2 的两类重点指标。跨场景组合属于归纳方法。

### V03 · 用语义图形和轻材质增加表现力

**适用：** 重点内容需要记忆点、章节需要识别标记，或页面缺少精致感。关键词：图标、插图、渐变、透明、亮边、阴影。

- 优先选择与内容相关的图标：对象、任务、关系或内容类别均可成为选型依据。相同层级沿用一致的尺寸、绘制风格和放置方式。
- 重点指标少、需要建立记忆点时，可以使用更具表现力的插图；高密度工作区采用紧凑图标和稳定排列。
- 图标底板、浅染色、细亮边、局部渐变、透明层次、切面标记、小型背景图形都可以增加材质与辨识度。
- 装饰本身有审美价值，不要求每个装饰都对应一个额外数据字段。它应与内容气质、层级和整体材质协调，不改变数据含义。
- 装饰的位置需要节奏：章节标记用于章节，主题图标用于重点主题，状态标记用于状态。这样丰富的局部形式仍能帮助定位层级。
- 阴影按浮起和层次需求选择。固定内容区可用表面和边界区分；浮层可使用适当阴影。参考稿中的光感可以保留，具体投影强度由画面判断。

**可变：** 图形复杂度、图标底板、透明程度、局部光感与投影强度。**检查：** 图形是否与主题相关、材质是否协调、文字和数据是否清楚，装饰是否占据了本该留给主要内容的空间。**依据：** S1、S2；具体图标与去外投影选择保留为案例。

### V04 · 通过多种视觉变量建立文字层级

**适用：** 主值、正文、单位、状态、提示混在一起，或所有内容同样抢眼。关键词：字号、字重、排版、强调、弱化。

主次由字号、字重、颜色、位置、留白共同建立。主值可以使用系统中的数据字体，标签、单位和常规表格沿用适合连续阅读的 UI 字体；同级内容稳定，较长名称与中文单位保持清楚。

需要精读的结果、状态、错误和操作信息保留足够辨识度。次要范围摘要、来源和计算备注可明显淡化，或收进就近帮助；当前生效筛选及影响判断的必要口径仍应清楚可辨。用户已允许当前报告的非重要提示使用很浅的低对比度颜色，这是明确的局部视觉偏好；将其用于新页面时，应重新识别哪些文字确实不影响任务，不能自动套到所有“小字”上。

**做法：** 先给文字标记标题、主内容、关键结果、单位、说明等角色，再从现有排版方案中分配层级；同一段落只突出帮助判断的部分。例如主值与单位同排但重量不同，表格保留规整数值，标题通过字重和间距获得层级。**可变：** 字号、字重、颜色、行长及强调位置。**检查：** 快速扫读是否先看到应该看到的内容，连续阅读是否舒服，长标签或中文单位是否挤压。**依据：** S1—S4。

### V05 · 改造组件时，同时考虑内容、外观与行为

**适用：** 已有组件能力基本合适，但当前内容、布局或视觉表达需要变化。关键词：组件改造、组合、变体、样式调整。

- **做法：** 先识别组件承担的任务。按需要调整内容层级、图标与文本组合、子区域布局、表面材质及密度；能用现有变体就直接用，多个组件形成新关系时先做局部组合，确需改结构时保留明确的局部改造来源。
- **搭配逻辑：** 改造应解决具体问题。例如把一段“类别、状态、日期、数量”拆成名称区、属性标签、状态和辅助元信息；表格中的数值加微型条帮助比较，仍保留精确数字。
- **保持：** 选择范围、查看入口、操作含义、焦点、键盘、禁用、加载与错误反馈。可点击外观必须对应真实操作；改变装饰不能悄悄改变业务含义。
- **可变：** 位置、比例、对齐、语义图标、表面和局部组合；尺寸调整需要连同文字、图标和点击区一起检查。单个页面的处理可以保留为局部方案。
- **检查：** 真实长内容及必要状态是否仍然成立；改造后能否更快识别对象、状态和动作；在相邻组件中是否协调。
- **依据：** S2、S3、S4；复用路径仍为 Existing Variant → Local Recipe → Local Fork。新公共默认按对应组件流程单独处理。


**已确认案例 · Breadcrumb（2026-09-24）：** 当设计稿将文字与箭头表达为一个下拉入口时，拆成文字链接与独立图标按钮会造成视觉与操作含义不一致。本轮采用整项按钮，统一Hover、按下、焦点与展开反馈，将返回该层放入菜单；普通上级链接继续直接导航。检查文字和箭头点击、重复点击收起、键盘关闭恢复及长名称提示互斥。此规则限于用户确认的整项下拉型面包屑，不否定其他明确采用双入口的设计。来源与验收范围见 [Breadcrumb验证记录](../../evidence/runtime/breadcrumb/verification.md)。

**已确认案例 · R2 导航品牌过渡（2026-10-01）：** 展开/收起时，品牌文字的条件挂载与布局切换容易产生视觉跳跃。当前R2保留同一节点与位置锚点，组合区域宽度、Logo位移和文字渐显；快速反向与减少动效一起检查。现有220ms只是本配方参数，不定义共享Sidebar或全库Motion默认值。用户确认范围为当前A1/A4/R2视觉，逐帧记录与头像复用见[导航使用指南](navigation-v042.md#g1-人工视觉验收--2026-10-01)及其review-08证据。

## 二、设计思路与设计手法

### D01 · 从用户要做的判断，确定整页的顺序

**适用：** 新页面、流程重组，或模块齐全但主线不清楚。**做法与判断：**

开工前先回答：用户是谁？此刻最想知道或完成什么？哪些信息会改变他的判断？需要哪些证据？下一步操作是什么？

先把内容写成问题，再决定模块名称。例如“哪些周的缺口最多”比“放一个柱状图”更能指导设计。“首屏、第二屏、第三屏”是阅读阶段，模块随内容自然延伸，不绑定固定视口高度。

| 页面任务 | 优先阅读与操作顺序 | 重点布局关系 |
| --- | --- | --- |
| 了解表现、定位差异 | 确定范围 → 关键结果 → 趋势 / 对比 / 分解 → 明细核查 | 首部形成焦点，解释与证据就近，精确记录在后 |
| 连续处理多个对象 | 定位对象 → 阅读当前内容 → 判断 / 编辑 → 保存并继续 | 目录、阅读区、处理区分工；主要操作持续可达 |
| 查找与管理资料 | 搜索 / 筛选 → 扫描对象与属性 → 选择 / 查看 → 执行 | 筛选对应同一结果集；身份、状态、选择、动作分开 |
| 理解一个复杂对象 | 身份与关键状态 → 核心内容 → 属性 / 关系 / 历史 → 对应操作 | 主内容获得足够宽度，辅助属性集中归组 |
| 编辑一个对象 | 识别填写任务 → 分区完成 → 就近校验 → 统一提交 | 长内容与短字段分配不同空间，错误紧邻问题 |

首部吸引力来自“最值得先看的内容”与“足够有辨识度的表现”共同成立。根据主任务选择突出结果、对象、待办或主要内容，不给每种页面都增加一排统计卡。

**可变：** 顺序、首部焦点、章节数量随主任务选择。**检查：** 每个区域能否回答一个明确问题，并自然接到下一个判断或动作。**依据：** S1—S4；不同任务的路径为归纳方法。

### D02 · 用关系组织空间，减少阅读阻塞

**适用：** 信息碎片化、卡片过多、主次不明或阅读来回跳转。**做法与判断：**

#### 分组与承载面

先判断哪些内容属于同一主题、同一对象或同一连续任务，再使用章节、卡片、分隔线和留白。

- 大章节负责明确阅读阶段；章内通过标题和间距组织子问题。多个紧密相关的图或属性可以共享一个表面。
- 独立对象或独立任务适合独立卡片。重点指标也可按主题形成一组染色面，组内再分主值、变化与补充数据。
- 解释区可以使用浅色内嵌面，与对应证据构成一体。长度很短的建议适合融入证据区；独立且完整的建议任务可以单独成章。
- 选择、查看、业务状态和操作要能分别识别。例如复选框控制整张对象卡，名称负责查看，状态标签说明属性。

#### 位置、比例与留白

- 图例靠近图形，说明靠近被解释内容，错误靠近字段，动作靠近作用对象，减少用户来回寻找。
- 同级内容可以等宽；主证据与辅助解读按内容分配空间。图宽、文字行长、字段数量共同决定比例，不固定套用一组数字。
- 组内间距帮助连续阅读，组间间距帮助分区，章节间距帮助切换问题。用间距梯度表达关系，避免所有间距相同。
- 呼吸感由自然留白、合理行长和清楚分组共同形成。内容少的比较区保持紧凑，信息多的图表获得充足空间。
- 对齐线贯穿标题、图表、列表和操作区。表格按字段选择文本左对齐、数值右对齐或短值居中，表头与对应内容保持一致。
- 长文字通过短标题、段落、关键短语高亮与按需展开变得可扫描；纯文字同样可以形成精致的模块。

检查一次阅读过程：用户是否反复找图例？需要记住前面数值才能比较？重要结果被解释文字挡住？上下模块重复回答同一问题？没有容器归属的小段信息是否打断阅读？这些都是优先修正的结构问题。

**可变：** 对齐方式、主从比例、章节密度与留白。**依据：** S1—S4；报告的具体间距与表格居中列只是案例。

**已确认案例 · Tree 关系线（2026-09-25）：** 连接线接近交互控件时，以完整按钮背景矩形测量避让，不能只看图标轮廓，也不能用背景遮盖相交的线。本次 Tree 在统一 12px 横线与 4px 留白下采用 24px 层级缩进、叶子取消展开占位；这是用户选择的 Tree A 排列，不是所有树都必须采用的通用尺寸。检查横向间距、按钮下方竖线、最后兄弟、富内容首行及窄栏换行；代表视觉已通过，正式组件与对比度验证另行记录。依据：[Tree实施规则与审核记录](../plans/2026-09-25-tree-implementation-rules.md)。

**已确认案例 · A4/R2 内容锚点与跨层级对齐（2026-10-01）：** 页签的Hover与选中只改变表面关系，保持文字、图标和点击区的锚点，避免反馈状态推动内容；树中名称按层级缩进，右侧元信息按独立列对齐。分支和叶子的操作数不同，应给操作区保留同等宽度，再检查元信息右边缘；只统一同级缩进不能解决跨层级偏移。当前8px页签留白、108/88px元信息列与108px操作区均为已确认A1/A4/R2样本的局部参数，其他内容应重新测量。来源：[导航review-04与review-07及验收范围](navigation-v042.md#g1-人工视觉验收--2026-10-01)。

### D03 · 按任务选择组合，再调整构图

**适用：** 已识别信息关系，需要找到可开始设计的组合方式。**做法：**

| 使用条件 | 组合 | 可变化部分 |
| --- | --- | --- |
| 少量重点结果，需要快速建立认识 | 语义图标 / 小插图 → 标签 → 主值 → 变化或参照 | 左对齐适合连续扫读；居中适合少量概览对象；按主题可分组染色 |
| 有清楚主证据和短解读 | 图形 / 主内容＋就近解释区 | 左右主从或上下递进；比例按图宽与文字行长决定 |
| 两个相同口径需要比较 | 同构两栏＋共享范围＋稳定系列身份＋差异摘要 | 可用于方案比较、版本变化、属性对照；内容长时改纵向对应 |
| 同一对象有多种关系 | 关系全貌 → 强弱 / 覆盖分布 → 精确记录 | 选需要的视角，不要求每页都有网络、热力和气泡图 |
| 管理多个同类对象 | 名称 / 封面＋类别标签＋关键属性＋状态＋独立动作 | 图像与对象辨识重要时用卡片；跨对象精确比较重要时用表格 |
| 连续阅读并处理 | 对象导航＋主要阅读区＋判断 / 编辑区＋稳定操作区 | 依据当前任务调整宽度；辅助工具不挤占主内容 |
| 分区填写一个对象 | 主题标题＋短字段组＋宽长内容＋就近帮助 / 错误＋统一提交 | 以字段关系决定单双列，不给每个字段单独套卡 |
| 需要综合结论 | 简短标题＋分段结论＋对应证据 / 后续动作 | 允许纯文字收束；结论不重复逐项读数，也不超出证据 |

每次选用时写下“适合原因、保持的关系、必要变化”。复用完整思路，同时允许内容改变构图。

**检查：** 组合是否服务当前内容；主次关系是否保留；是否为了套用组合增加无用区域。**依据：** S1—S4；组合关系可以迁移，实际构图需查看真实内容。

### D04 · 让功能性设计与装饰性设计协作

**适用：** 页面需要更有设计感，或需要判断一项视觉处理是否值得保留。关键词：功能、装饰、识别、焦点、氛围。

- **做法：** 先明确功能骨架：什么内容、什么关系、什么状态、什么操作。再选择与内容气质相符的表现方式：主题色、图标底板、插图、细亮边、轻渐变或背景图形。
- **搭配逻辑：** 功能设计让信息和操作可理解，装饰设计带来精致感、气质和记忆点；一种手法可以同时承担两者。例如章节切面标记既定位章节，也形成页面的视觉节奏。
- **可变：** 装饰位置、尺度、材质与密度。少量重点内容可以有更强表现力，连续操作区以稳定识别为先；装饰不必全部对应数据字段。
- **检查：** 装饰是否遮挡或挤压内容、是否像一个并不存在的按钮、是否误导为状态或 AI 生成身份；移除或保留后，整体气质和焦点各发生什么变化。
- **依据：** S1 的完整参考、S2 的用户反馈；“去掉两枚图标外投影”只适用于当前案例，不推出所有图标都不能有阴影。

### D05 · 根据真实内容和容器调整表达

**适用：** 长名称、密集数据、窄窗口、错误或空状态使原构图失效。关键词：响应式、密度、内容适应。

- **做法：** 先换行、重排、改主从比例或将低频内容按需展开；保留相互比较所需的关系。精确表格可以局部横滚，长正文获得合理行长。
- **搭配逻辑：** 容器变化首先影响空间关系，信息角色和操作含义保持稳定。一个窄组件也可能需要这种调整，不只整页适用。
- **可变：** 双栏转纵向、标签位置、图例排列、局部滚动；密度变化连同字号、控件和点击区一起评估。
- **检查：** 不依赖缩小所有文字维持构图；长内容、错误、加载、空值、触摸与键盘使用仍可理解。没有数据与数值为零分别表达。
- **依据：** S2—S4；新断点由实际容器和内容决定，不复制案例窗口尺寸。

## 三、信息展示思路与方法

### I01 · 先分清信息角色，再选择样式与组件形态

**适用：** 一段文字含多种信息，或不同信息都使用相同样式而难以分辨。**做法：**

相同角色使用稳定表达；不同角色通过形态、位置、颜色或字重形成区分。选样式前，先确定内容的角色及重要程度。

| 信息类型 | 用户需要识别什么 | 合适的表达 | 视觉处理要点 |
| --- | --- | --- | --- |
| 对象身份 | 这是什么、属于哪里 | 名称、头像 / 封面、语义图标、少量属性标签 | 名称稳定突出，附属属性靠近对象；图标与信息有联系 |
| 关键结果 | 当前最重要的事实 | 主值＋标签＋单位＋必要参照 | 数值优先，单位退后；重点区可用浅染色、主题图标与轻材质 |
| 变化 | 从哪里到哪里、变了多少 | 当前值＋差值＋明确比较范围，必要时配小趋势 | 方向与幅度同时明确；上涨并不自动代表好转 |
| 横向差异 | 谁更高、相差多少 | 并列条形、点图、对照列、差值摘要 | 同指标共刻度、同对象顺序稳定；数值与图形对应 |
| 时间变化 | 何时变化、走势如何 | 折线、面积或按时段柱形 | 线是主角，网格与刻度轻；直接标签和按需读数按密度取舍 |
| 构成与分布 | 由什么组成、集中在哪里 | 分组 / 堆叠条形、分布图、矩阵 | 构成与大小比较分别选型；图例、单位、零值与缺测明确 |
| 关系与覆盖 | 谁与谁有关、方向与强弱如何 | 网络、关系矩阵、气泡矩阵、关系标签 | 位置、连接、面积、线型分别承担清楚含义 |
| 类型与状态 | 属于哪类、当前处于什么状态 | 标签、徽标、状态点＋文字 | 类别色保持身份，状态色保留状态含义；状态不伪装成操作 |
| 解释与建议 | 这些信息意味着什么、可做什么 | 就近短解读、段落、对照总结、侧栏 | 标题或小标记说明角色；事实、解释和建议分开表达 |
| 精确记录 | 某一项到底是多少 | 表格、属性列表、原文摘录 | 对齐和行关系优先；微型条帮助扫读，文字保留精度 |
| 范围与口径 | 数据来自哪里、边界是什么 | 就近范围提示、标题旁帮助、来源说明 | 影响判断的范围可找到；低优先级解释减少常驻占位 |
| 动作 | 我能做什么、会改变什么 | 按钮、链接、图标按钮、局部工具栏 | 视觉重量对应动作优先级，位置对应作用范围 |

同一内容可以有两种互补表达：图形用于扫读，数字用于核查；概览用于判断，明细用于追溯。两处呈现应服务不同任务，避免相邻区域原样重复。

**搭配逻辑：** 先区分角色，再区分同角色中的主题或对象。例如名称、状态和操作需要不同形态；两个同级指标可以共用结构，再用主题色和图标区分。**检查：** 不读完整句子时，能否认出对象、结果、解释与动作各在哪里。**依据：** S1—S4。

### I02 · 按信息关系选择图形，并保留精确读数

**适用：** 趋势、比较、构成、分布或关系需要可视化，或表格扫描成本较高。**做法与边界：**

两份参考的成熟之处包括完整的读图组合：标题、单位、图形、图例、精确读数、解释相互配合。选型先看关系，风格再决定材质。

| 问题 | 可借鉴的图形与组合 | 使用边界 |
| --- | --- | --- |
| 总体随时间如何变化 | 细折线＋轻面积＋重点端点；下方或旁边短解读 | 基线与量纲明确，避免视觉夸大；缺测与零值区分 |
| 不同对象谁更多 | 水平条形＋直接数值；同指标并排比较 | 共用刻度和排序逻辑，允许只选一个对象时回到表现展示 |
| 总量变化来自哪一部分 | 总体趋势在前，类别分解在后 | 两图回答不同问题；类别 / 版本颜色贯穿图例与浮层 |
| 多个维度的轮廓如何不同 | 雷达图＋原文或维度依据 | 维度口径可比、对象数量可读；需要精确排名时另用条形或表格 |
| 两项不同量纲如何变化 | 分组小图；必要时线柱组合及清楚的双轴 | 不借图形接近暗示数值相等或因果；复杂时拆开读 |
| 哪些对象相互连接 | 关系网络＋分组图例 | 节点类别、连接类型、方向分别编码；密集时聚焦或筛选 |
| 相似度 / 时序位置如何分布 | 行列矩阵＋连续色阶＋数字 | 颜色反映强弱或顺序，不能随意改成好坏；长标签可借编号定位 |
| 覆盖关系集中在哪里 | 气泡矩阵＋面积 / 深浅＋精确数字 | 明确面积映射；零、无关系和缺测不混淆 |
| 一条记录的全部属性是什么 | 表格＋微型条＋类别 / 关系标签＋独立操作 | 同字段表达稳定；数值保留，微型图形辅助扫读 |
| 差异依据来自哪些文本 | 并列摘录＋同异高亮＋短归纳 | 高亮对准比较问题；避免整段着色削弱焦点 |

图例可以单独成板、合并成轻横条，或贴近系列直接标注，取决于读图距离和系列数量。图例的图形应与实际标记、线型和颜色一致。

常驻标签适合少量关键读数；密集或次要读数可以在指向 / 聚焦后出现，图面保留形态。采用按需显示时，提供键盘或触摸可达的等价读数，也可由明细补充核查。当前报告“柱顶值按需出现”是其中一种具体选择，趋势端点仍可常驻。

图表组件尚未建设时，保留问题、口径、构图、系列编码与交互目标；在相应阶段建设。数据不足时明确缺少什么，不能用新增图形暗示已经掌握不存在的信息。

**可变：** 图形、排列、图例位置、直接标签或按需显示、材质；保持统计口径与映射真实。**检查：** 图形是否回答当前问题，读者是否能找到单位、范围和精确值。**依据：** S1、S2；图表选型是条件性建议。

### I03 · 将范围、结果、证据与解释组织成信息链

**适用：** 信息很多但逻辑散乱，结论缺少依据，或同一事实被反复重复。关键词：逻辑梳理、解读、建议、渐进展示。

- **做法：** 为内容标记“作用范围、主结果、支持证据、解释、可执行动作”，再按当前任务排列。比较需共用口径，原因推断需明确依据，解释靠近被解释的内容。
- **搭配逻辑：** 用户先形成认识，再按需要核查细节；图形概括、原文依据、短解读和明细各自承担不同阅读层次。
- **可变：** 解释与主图左右并置、图下内嵌、对照两栏或章节后纯文字收束；信息很少时直接合并成紧凑区域。
- **检查：** 当前筛选是否影响全部预期区域；局部切换是否改变了用户未预期的范围；结论是否只是重复读数；是否把相关性或示例数据写成因果结论。
- **依据：** S1 的图文组合、S2 的全页筛选与章节迭代、S3 的局部工具归属。

## 四、应用、补充与持续维护

### 在一个组件或页面中应用

1. **写任务。** 一句话描述用户要完成的判断或动作。
2. **列信息。** 标记主结果、证据、身份、状态、说明、操作，以及它们的作用范围。
3. **排问题。** 决定先看什么、再解释什么、最后核查或执行什么；移除没有新增作用的重复模块。
4. **选表达。** 为每组信息选择最合适的图表、表格、文字、标签或对象卡，并说明为什么适合。
5. **定视觉家族。** 明确章节、子标题、主值、图例、辅助说明的共同规则，以及哪些主题需要颜色、图标、材质差异。
6. **排空间。** 先完成主要对齐、分组、比例和留白，再精修字号、线条、渐变和交互反馈。需要探索方向时，用相同业务内容比较两种实质不同的组织方式。
7. **看真实内容。** 在完整长页和窄屏中检查长名称、密集数据、少量数据、空值和错误；窄屏先重排关系，表格必要时局部横滚。
8. **完成反馈闭环。** 先看整页任务与焦点，再看区域关系，最后看组件细节和状态。记录本次选择的条件，便于后续迁移。

评审时逐项询问：主要结果是否容易发现？不同信息角色能否快速分辨？相同对象是否始终对应同一标记？解释是否挡住内容？是否出现无效大块空白或过度挤压？装饰是否形成协调的材质与节奏？每个图是否回答独立问题？需要精确核查时是否有可达入口？

设计记录只需一小段，例如：

> 采用 V01、V02、I01：这组对象属于同级主题，共用卡片结构，用协调的主题色与语义图标区分；名称、状态和操作分开。此次将概览主值改为对象名称，收起低频属性。检查长名称、单对象、窄容器及状态变化；记录实际反馈后再决定是否形成新经验。

这个例子说明如何引用方法，不代表已经完成新页面验证。没有合适方法时，在记录中说明缺口并探索，不为引用编号强套现有方案。

### 何时沉淀

**当前约定：每次组件或页面设计完成、确认后沉淀。** 由用户于 2026-09-20 明确选择。设计结束或收到用户确认后，检查是否出现值得保留的做法、反例或适用边界；中间反馈可以先作为候选经验留在任务设计记录中，收尾时一并归纳。

设计完成但尚未获得用户确认的方法可以记录为待验证，后续收到证据再更新。归纳时合并已有新证据、清理重复与过时结论；没有新发现时不为更新而追加。

仅当用户授权的任务进入实施或总结范围时回写；纯讨论、只读评审或明确要求不改文件时，先在回复中给出候选经验。这是随设计任务进行的收尾步骤，本文本身不触发后台任务。

### 一条经验怎么写

优先补充已有方法，避免同义条目越积越多。新方法使用对应分类的下一个编号；编号保留，标题可以改进。

```markdown
### V06 / D06 / I04 · 方法名称（按分类选择下一个编号）

- 检索词与适用场景：遇到什么内容、视觉或操作问题；适用于组件、模块还是整页。
- 具体做法：怎样配色、搭配样式、组织信息或改造组件，写到可以执行。
- 搭配与判断逻辑：为什么这样做；功能价值、装饰价值分别是什么。
- 保持与可变：哪些关系要保留，哪些参数随内容和容器改变。
- 检查与反例：怎样判断有效，什么情况不适用或需要换一种方法。
- 案例与反馈：日期、页面或组件、原问题 → 调整 → 实际观察；有截图或源码时给出路径。
- 证据状态：参考观察 / 待验证尝试 / 局部用户确认；写清确认范围。多次使用分别记案例。
```

“更美观、更高级、信息更清晰”需要补上导致效果的具体动作，才能成为可应用的方法。尚未测量的效率收益不写成事实。单次确认不升级为所有场景的固定规则。

### 如何保持方法库有用

- 同一方法的新案例放在原条目下；不同条件导致不同做法时补充分支与选择依据。
- 遇到矛盾，保留来源并明确条件或替代关系；过时条目注明被哪个编号替代，不静默丢失历史理由。
- 更新正文时同步方法索引、日期与相关入口。局部参数留在案例；组件 API、正式默认值仍由现有组件合同维护。
- 设计记录应能看出实际使用了什么、怎样改变和结果如何。文档可达证明 AI 有机会读取；新场景实际应用的证据才支持质量判断。
- 独立 Starter 中可以应用并追加本地经验；导出快照不会自动同步回原工作区。后续整合时核对来源与确认范围，再合并方法。
